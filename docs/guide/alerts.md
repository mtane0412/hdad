# アラート（素材の種類「アラート」）

Twitchのイベントに合わせて、画像・動画・音声と文言を配信画面に表示する素材です。1件ずつ順番に再生し、再生中に届いたものは待たせます。利用には[デプロイ](./deploy.md)の Twitchログインの設定が必要です。

配信画面に出すには、[合成オーバーレイ](./overlay.md)の画面（`/overlay/`）でオーバーレイに素材「アラート」を足します。パラメータはありません（何を出すかは下記のトリガーで決めます）。**素材の枠の中央**に出るので、枠は足したときのオーバーレイいっぱいのままにするのが基本です。見栄えと配置は `/overlay/` のプレビューで確かめられます（サンプルのアラートが順に流れます）。

## トリガー（どんなときに何をするか）

どんなときに何をするか（トリガー）は、配信者がトリガーの管理画面（`/triggers/`）で決めます。設定の手順は下の「[アラートの設定と素材](#アラートの設定と素材)」にあります。トリガーは「きっかけ」と「動作」からなります。

きっかけは**最初から一覧に並んでいます**。イベント種別と条件を自分で組み合わせる形ではありません（このツールは汎用のノーコード自動化を目指していないためです）。配信者がすることは、効果を付けたい出来事を開いて何をするかを決めることだけです。

一覧は「チャット」（発言がきっかけのもの）と「イベント」（それ以外）の2つの区分に分かれていて、項目によっては絞り込みを1つだけ選べます（報酬・ユーザー名・言葉・日数・自動で入った広告か）。**効果をひとつも付けていない出来事では何も起きません**（並んでいるだけなので、有効・無効の切り替えはありません）。

| 区分 | 項目 | 絞り込み |
|---|---|---|
| チャット | 初めて来た人の発言 | なし |
| チャット | 久しぶりの人の発言 | 前の発言から空いた日数（1〜365日） |
| チャット | その配信で最初の発言 | なし |
| チャット | すべての発言 | なし |
| チャット | 決まった言葉を含む発言 | 含まれる言葉（部分一致） |
| チャット | 決まった人の発言 | Twitchのユーザー名 |
| イベント | チャンネルポイントが交換された | 報酬（既定はすべての報酬） |
| イベント | フォローされた / サブスクされた（新規） / サブスクの継続メッセージが届いた / レイドされた | なし |
| イベント | 広告（始まったとき・終わったときで別々の効果を付けられる） | 自動で入った広告だけ・手動で打った広告だけ・どちらでも |

> **チャットの上3つは「挨拶」で、1通の発言に動くのは当てはまるうち一番上のものだけです。** 初めて来た人の発言は「その配信で最初の発言」でもあるので、すべて動かすと同じ1通に挨拶が二重・三重に飛んでしまいます。「すべての発言」は挨拶と**同時に**動くので、読み上げや効果音に向いています。

> **既定メニューにする前の設定は読み込めません。** イベント種別と条件を持つ古い形が保存されていると、管理画面もエラーになります（黙って読み替えないためです）。KVの `alert-config` を消してから、メニューで設定し直してください。

### 効果（動作）の種類

**報酬・言葉・ユーザーの3つは、1つの出来事の中に設定を複数持てます**（「乾杯」の報酬と「おみくじ」の報酬に別々の効果を付けられます）。ほかの出来事は1つずつです。

効果には次の5種類があります。

- **アラートを出す** — アラートの素材が画像・動画・音声と文言を再生します
- **チャットに送る** — Workerがbotとしてチャットへ1通送ります
- **AIに文面を作らせて送る** — Workerがその人の記録を材料にLLMへ文面を作らせ、botとして送ります（下の「[AIに文面を作らせて送る](#aiに文面を作らせて送る)」を参照）
- **アナウンスを送る** — Workerがbotとして、モデレーター権限で色の付いた帯を送ります
- **シャウトアウトを送る** — Workerがbotとして、レイドしてきた配信者をTwitchのシャウトアウトで紹介します（**レイドされたときだけ**選べます）

### 当てはまった行はすべて実行します

Twitchからの通知はすべてWorkerがWebhookで受け取り、当てはまったアラートだけを合成ページへWebSocket（`GET /api/overlay/socket`）で押し出します。**当てはまった行はすべて実行します**（1件だけを選ぶことはしません）。たとえば「すべての発言」と「初めて来た人の発言」の両方に効果を付けていれば、初見さんの1通目では両方が動きます。

アラートが重なったときは、届いた順に並べて1つずつ再生します。素材はTwitchへ直接つながず、届いたものを再生するだけです。判定を通知のたびに行うので、設定を変えてもOBSの再読み込みは不要です。

どのトリガーに当てはまるかをWorkerが決めるのは、きっかけに「その配信で初めての発言か」「このチャンネルで初めての発言か」のようにデータベースの記録からしか決められないものがあるためです。アラートを出す動作を持つトリガーが1件もなければ何も表示しません。**アラートの素材を置いたオーバーレイを開いていない間に届いたアラートは、貯めずに捨てます**（開いたときに過去の分がまとめて流れないようにするためです）。

### botの接続が要る効果

チャットに送る動作・AIに文面を作らせて送る動作・アナウンスを送る動作は合成ページには渡らず、TwitchからWorkerへ直接届くWebhookで実行します。そのため**OBSを開いていなくてもチャットのお礼は送られます**（送るには「[チャットボット](./bot.md)」のページでbotアカウントを接続しておきます）。アナウンスとシャウトアウトはさらに、botがそのチャンネルのモデレーターにされている必要があります。

アラートを出す動作はbotの接続と関係なく動きますが、**チャットに送る・AIに文面を作らせて送る・アナウンスを送る・シャウトアウトを送る動作はbotを接続しているときだけ動きます**（送り主のアカウントが要るため）。未接続のときは `/triggers/` の画面で知らせます。

## チャットの項目の当てはまり方

「チャット」の区分はすべて発言がきっかけなので、「決まった人が発言したら音を鳴らす」「合言葉が出たらアラートを出す」といった設定ができます（ユーザー名も言葉も、大文字小文字は区別しません）。挨拶の3項目は、次の発言に当てはまります。

| 項目 | 当てはまる発言 |
|---|---|
| その配信で最初の発言 | その配信で最初にチャットした人の1通目。同じ人の2回目以降の発言では動かず、配信が変わればまた動きます。**配信していないあいだの発言は初回と判定しません**（テスト配信や配信前の雑談のたびに動いてしまうため） |
| 初めて来た人の発言 | 視聴者の記録（`viewers`。[視聴者の記録](./viewers.md)を参照）が1行もない人の1通目。Twitchの「初見」の印（IRCの `first-msg`）ではなく自前の記録で判定します。トリガーの判定に使うEventSubの通知にはこの印が無いためです。常連は当てはまらないので、「初めて来てくれた人にだけ挨拶する」ができます。**この記録を始める前から来ている常連も「初めて」と扱われます**（記録がないためです。運用を始めた直後は動作を控えめにしておくことをおすすめします） |
| 久しぶりの人の発言 | 最後の発言から指定した日数（1〜365日）以上空けて発言した人の1通目。「お久しぶりです」と声をかけるのに使います。このチャンネルで初めての人には当てはまりません（空いた日数が決まらないためです） |

「初めて来た人の発言」と「久しぶりの人の発言」は視聴者の記録から判定するので、**人ごとに記録を削除すると、その人はまた「初めて」に戻ります**。

## 広告の項目

「イベント」の区分の**広告**では、「広告が入ることをチャットで知らせる」「広告が終わったら声をかける」ができます。始まったときと終わったときで別々の効果を付けられ、文言には広告の長さを差し込む `{duration}`（秒）が使えます。絞り込みで、自動広告だけ・手動で打った広告だけに絞れます（手で打った広告は配信者が自分で告知できるので、ふだん告知したいのは自動広告のほうです）。

> **Twitchには広告の終了に相当する通知がありません。** 届くのは開始（`channel.ad_break.begin`）だけで、そこに広告の長さ（`duration_seconds`）が入っています。そこでWorkerは開始を受けた時点で「終わる時刻」を Durable Object（`AD_BREAKS`。`worker/ad-break-timer.ts`）に預け、その時刻にアラームで起きて、擬似イベント `channel.ad_break.end` として同じ照合に回します。cron（5分おき）では30〜180秒の広告に間に合わず、Workerは接続もタイマーも持てないためです。終了のトリガーが1件もなければ預けません。
>
> **すでに動かしている場合は、配信者のログインし直しが必要です。** 広告の通知を購読するために、配信者のスコープに `channel:read:ads` が増えたためです。

## 失敗の出方

キーの指定漏れのように起動できない失敗は素材の枠にエラーを表示し、切断などの一時的な失敗は枠の左下にお知らせを出してつなぎ直します。つながらないまま閉じた場合（キーの誤りなど）も、ブラウザからは理由を読めないため、左下に手がかりを出したうえでつなぎ直し続けます。

## OBSでの設定

ブラウザソースの置き方は[合成オーバーレイ](./overlay.md)の「OBSでの設定」を見てください。動画・音声の素材を使う場合は、そのブラウザソースのプロパティで「OBSで音声を制御する」を有効にすると、音量をOBSのミキサーで調整できます。

## アラートの設定と素材

トリガーの管理画面（`https://<公開先のドメイン>/triggers/`）とアップロードの画面（`/media/`）で、配信者としてログインして行います。

| 欄 | できること |
|---|---|
| 配信画面への出し方（`/triggers/`） | `/overlay/` への案内と、オーバーレイ用キーの再発行。**キーはすべてのオーバーレイと裏方で共通なので**、再発行すると今のURLはそのすべてで使えなくなり、OBSのURLを貼り替えることになる |
| 素材（`/media/`） | 画像・動画・音声のアップロード（1ファイル50MBまで）、試し見・試し聴き、削除。トリガーに使われている素材は削除できない |
| トリガー（`/triggers/`） | 一覧に並ぶ出来事を開き、絞り込み（上の表のとおり項目ごとに1つ）と、そのとき行う効果を並べて保存する。一覧では要約だけが見出しに出て折りたたまれ、見出しを押すと入力欄が開く。効果は上の5種類で、1つだけでも複数でもよい（ただし「チャットに送る」と「AIに文面を作らせて送る」は同じ発言に2通返ってしまうので同時に選べない）。効果をひとつも付けていない出来事は保存されない |

管理用API（`/api/admin/*`）は配信者のセッションが必要で、書き換えを伴うメソッドは管理画面と同じサイトからのリクエスト（`Origin` ヘッダーが一致するもの）だけを受け付けます。ローカルでは `npm run dev`（`http://localhost:5173/triggers/`）で確かめます。`@cloudflare/vite-plugin` が開発サーバーの中でWorkerを動かします。

### 効果ごとの入力の決まり

- **アラートを出す** — 表示時間（`durationSeconds`）は1〜60秒、音量（`volume`）は0〜1、文言（`message`）は200文字以内です（差し込み語が置き換わり、空文字なら文言を出しません）
- **チャットに送る** — 文言（`message`）は1〜500文字（Twitchのチャット1通の上限）で、空文字は許しません。`{message}` を差し込んだ結果が500文字を超える場合は、末尾を `…` にして収めます（超えたままではTwitchが1通まるごと拒むため）
- **AIに文面を作らせて送る** — AIへの指示（`instruction`）は1〜1000文字で、文面そのものではなく「どう書くか」を書きます（差し込み語は使いません）
- 同じ種類の動作は1つのトリガーに1件までで、`chat` と `aiChat` は同じトリガーに並べられません（同じ発言に2通返ってしまうため）
- 差し込み語はイベント種別ごとに違い、`{user}`（交換した人・フォローした人・レイド元の配信者・発言した人）のほか、`{reward}`・`{tier}`・`{months}`・`{viewers}`・`{message}`（発言の本文）・`{duration}`（広告の長さ。秒）が使えます
- 設定に問題があれば、保存せずに問題点の一覧（`error.problems`）を返します

### AIに文面を作らせて送る

「AIに文面を作らせて送る」動作（`aiChat`）は、次のものを材料にLLMへ文面を作らせて送ります。

- 配信者が書いた指示（`instruction`）
- 相手の名前と発言の本文
- その人の記録（`viewers` のメモ・AIが作った人物像・初回と最後の発言日時・おおよその発言数・最後に見たバッジ・最後に観測したその人自身のチャンネルの内容）
- 「このチャンネルで初めての発言か」「前の発言から何日空いたか」

文面を作らせる先（提供元とモデル）は管理画面（`/llm/`）で選びます。既定は Cloudflare の Workers AI で、箇所ごとに変えられます（[文面を作らせるLLM](./llm.md)を参照）。

視聴者の記録を材料に渡せるのはチャットの発言のトリガーだけで、ほかのイベントでは指示とイベントの中身だけから作らせます。「初めて」「お久しぶり」の判定は、トリガーの絞り込みに使っていなくてもこの動作があれば行います（行わないと来訪の別を知らないまま文面を作らせることになるためです。そのぶん、発言のたびに視聴者の記録を読みます）。

Webhookの応答を待たせるとTwitchが同じ通知を再送するため、**Twitchへ2xxを返してから**文面を作って送ります（`ExecutionContext.waitUntil`）。AIが作った文面が500文字（Twitchのチャット1通の上限）を超えたとき、AIが失敗したとき（無料枠切れを含みます。無料枠の見方は[文面を作らせるLLM](./llm.md)を参照）は、**切り詰めたり固定文言に落としたりせず送るのをやめて** `collection_failures` に `alert-aichat-failed` として記録します。
