# 配信中の文字起こし

配信者が喋った内容を Worker に取り込みます。取り込み自体は映すものを持たず（Web Speech API の方法なら、素材「[字幕](./caption.md)」で配信画面に出せます）、[これまでのあらすじ](./bot.md#これまでのあらすじ)と[サイドスーパー](./side-super.md)の材料になります（どちらも、置いていなければ視聴者の発言とカテゴリ・タイトルだけを材料に作られます）。

取り込み方は2つあります。

- **HDAD のアプリのページで認識する（Web Speech API）**: Chrome で HDAD を開いておくだけで、PCに常駐させるものが要りません
- **ゆかコネNEO から中継する（`transcript/relay/`）**: これまでの方法です。Web Speech API の方法を実配信で確かめ終えるまで残します（issue #192）

いまは両方を並べて動かし、取りこぼしと精度を比べている段階です（issue #189）。両方を動かすと、同じ発話が2件ずつ記録されます。

## アプリのページで認識する（Web Speech API）

アプリの「コネクター」のページ（`/connectors/`）の **Web Speech API** の区画で「文字起こしする」をオンにします。Chrome の音声認識（ゆかコネNEO の「ブラウザ音声認識」と同じもの）が配信者の声を文字にし、確定した発話を Worker へ送ります。

- **認識するのは HDAD を開いている Chrome のタブです**。ほかのページに移っても認識は続き、サイドバーの末尾に「文字起こし: 聞いています」などの状態が出ます。タブを閉じると止まるので、**配信中は HDAD を別のウィンドウで開いたままにしてください**。OBS のブラウザソースでは Chrome の音声認識が使えないため、OBS には置けません
- オン・オフは**このブラウザに覚えます**。オンのまま開き直せば、開いただけで始め直します（別の端末で HDAD を開いても、そこでは始めません）
- HDAD を2つ以上のタブで開いていても、**認識するのは1つのタブだけです**（同じ発話を二重に記録しないため）。ほかのタブには「別のタブで認識中」と出て、認識しているタブを閉じると代わりに始めます
- Chrome は黙っているときなどに認識を勝手に終えるので、**終わったらすぐつなぎ直します**。マイクも開いたままにします（Chrome が裏に回ったタブを止めないようにするためです）。つなぎ直しが5秒を超えて戻らないときは「途切れています」と黄色で出します
- マイクが許可されていない・外れた、つなぎ直しが1分に30回を超えたなど、続けられないときは**止めて理由を赤で出します**。コネクターのページの「もう一度始める」で始め直します（マイクの許可を求め直すには、ボタンを押すことが要る場合があります）
- コネクターのページには、話している途中の文・つなぎ直した回数と途切れた時間の合計・直近50件の発話と記録できたかどうか（`記録`・`配信外`・`送れませんでした`）が出ます。通信の失敗なら、同じ発話を少し待って3回まで送り直します
- 裏に回したタブが止められないよう、Chrome の設定の「パフォーマンス」で、HDAD のサイトを「常にアクティブにするサイト」に追加してください
- 配信していないあいだの発話を Worker が捨てること、1件は1000文字までであること、配信が終わって1日で消えることは、ゆかコネNEO からの中継と同じです
- 話している途中の文と確定した文は、オーバーレイの素材「[字幕](./caption.md)」にも送ります（配信していないあいだも送ります）。字幕の中継先とつながらないときは、この区画に理由が赤で出ます

## ゆかコネNEO から中継する（`transcript/relay/`）

音声認識そのものは、配信に使うPCで動かした [ゆかコネNEO](https://nmori.github.io/yncneo-Docs/)が行います。ゆかコネNEO には認識の結果を外部へ送る仕組みが無いので、**PCと Worker の橋渡しをOBSのブラウザソースに置く中継ページ（`transcript/relay/`）が受け持ちます**。OBSに貼るURLは、アプリの「コネクター」のページ（`/connectors/`）で **ゆかコネNEO** に印を付けてコピーする[裏方](./backstage.md)のURLです（中継は裏方の1枚の中で動きます）。利用には[デプロイ](./deploy.md)の Twitchログインの設定が必要です。

```text
https://hdad.<サブドメイン>.workers.dev/transcript/relay/?key=<オーバーレイ用キー>
```

| パラメータ | 内容 |
| --- | --- |
| `key` | オーバーレイ用キー（必須）。キーを含む裏方のURLはコネクターのページでコピーできる（アラート・サイドスーパー・注目コメントと同じキーです） |
| `host` | ゆかコネNEO が動いているホスト。`localhost`（既定）か `127.0.0.1` のみ |
| `port` | ゆかコネNEO の WebSocket のポート番号（既定 `11901`）。1〜65535の整数 |

- **OBSと同じPCで開く必要があります**。中継ページがつなぐ先は同じPCのループバック（`ws://localhost:11901/`）だからです。`host` に `localhost` と `127.0.0.1` しか受け取らないのも同じ理由です（ブラウザが `ws://` への接続を許すのはループバックだけです）
- ポート番号はコネクターのページで入れてからURLをコピーします。**読めない値を入れたときはURLを出さずに理由を出します**（既定に黙って戻すと、入れたポートと違う先へつなぐURLを、そうと分からないまま渡してしまうためです）
- 送るのは**確定した母国語の発話だけ**です。認識中の暫定の文（何度も書き換わるもの）は送らず、翻訳（ゆかコネNEO の `Text2`〜`Text6`）も捨てます（あらすじに要らないためです）
- **同じ発話を二度は送りません**（ゆかコネNEO は確定した1件も、字幕の残り時間を減らしながら繰り返し押し出してくるので、送ったIDを覚えています）。送信に失敗した1件は覚えているものから外すので、次に押し出されたときにひとりでに送り直されます
- **編集者による取り消しは取り消しとして扱いません**。ゆかコネNEO の「消えた」という知らせは、字幕の表示時間が尽きたときにも同じ形で届き、編集者の取り消しと区別できないためです（取り消しとして扱っていたころは、確定した発話が数秒後にすべて消えて材料が残りませんでした）
- **配信していないあいだの発話は Worker が捨てます**（中継ページの画面に「配信外」と出ます）。配信の前後に開いたままにして構いません。1件は1000文字までです
- 中継ページは、**接続の状態と直近50件の発話**（`✓` 記録した・`配信外` 捨てられた・`送信失敗`）を画面に出します。OBSのブラウザソースではコンソールを読めないので、文字起こしが Worker へ届いていないことに配信が終わるまで気づかないのを避けるためです
- つながらないときは、考えられる原因（ゆかコネNEO が起動していない・ポート番号が違う・ブラウザが `ws://` を拒んでいる）を画面に出し、1秒から倍に延ばしながら（最大30秒間隔で）つなぎ直し続けます。1件が読めなかった・送れなかったときも中継は止まりません
- キーの指定漏れや誤りのように起動できない失敗は、画面全体にエラーを表示します
- 取り込んだ発話はD1（`transcripts`）に貯まりますが、**配信が終わって1日で cron が消します**（あらすじの材料にするための一時的な記録で、配信後に残す意味がないためです。配信の直後に読み返せるよう1日だけ残します）
- [裏方](./backstage.md)（`overlay/backstage/`）を使えば、[チャットの読み上げ](./speech.md)と1つのブラウザソースにまとめられます

### OBSでの設定

1. ソースの追加 > ブラウザ
2. URLに、コネクターのページでコピーした裏方のURLを貼る。映すものが無いので大きさは任意（画面の状態を読めるよう 600×600 px を勧めます）。見えない位置に置いて構いません。アプリは中継だけのURL（`transcript/relay/`）を出さなくなりました（すでに貼ってあるものはそのまま動きます）
3. **ソースのプロパティの「非アクティブ時にソースをシャットダウン」は有効にしないでください**。ソースを非表示にした時点で中継ページが閉じられ、取り込みが止まります
4. 配信に使うPCでゆかコネNEO を起動し、WebSocket のポート（既定 `11901`）で待ち受けさせておく
