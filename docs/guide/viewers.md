# 視聴者の記録（`/viewers/`）

チャットで発言した人を、Worker が1人1行でD1（`viewers`）に貯めます。**発言そのものは貯めません**（チャットは件数の桁が違い、配信の記録と書き込みの枠を食い合うため）。貯めるのは人なので、数千人でも数MBに収まり、消さずに持ち続けられます。「この人は前にも来てくれた」「前はこういう話をした」を配信者が振り返るためのものです。

視聴者の画面（`https://<公開先のドメイン>/viewers/`）では、最後に発言した順に並ぶ一覧を見て、ログイン名の前方一致で絞り込み、人ごとにメモを書けます。一覧は50人ずつ読み、続きは「もっと読み込む」で足します。

その人がどんな人かの要約（人物像）は、AIが作って記録に足します。材料はその人がその配信で話した内容なので、**配信中のあいだだけはチャットの本文も貯めます**（`stream_chat_messages`）。これは「発言そのものは貯めない」という上の方針の、意識して設けた例外です（発言数やバッジだけでは人物像を作れないためです）。貯めた本文は、配信が終わったあとに cron（5分おき）が1回5人ずつ人物像にまとめ、**使い終えたその場で消します**。人物像を作るときは前回までの人物像も材料に渡すので、配信を重ねるほど積み上がります。作った人物像は、次にその人が発言したときの「AIに文面を作らせて送る」動作（`aiChat`）の材料にもなります。AIが失敗したとき（無料枠切れを含む）は人物像を作らず、`collection_failures` に `viewer-summary-failed` として記録し、材料は次の収集でやり直せるよう残します（残ったまま7日を過ぎた材料は cron が消します）。記録を削除すると、まだ人物像にしていない本文も、配信中のぶんまで含めて一緒に消えます。

| 記録する値 | 内容 |
|---|---|
| ログイン名・表示名 | 最後に見た名前。本人がいつでも変えられるので、**照合にはTwitchのユーザーIDだけを使います**（名前で照合すると、改名した人が別人として増えます） |
| 初回・最後の発言日時 | このチャンネルで初めて発言した日時と、最後に発言した日時 |
| 通算の発言数 | 後述のとおり10分に1回までしか数えないので、実際の発言数より少なくなります |
| 最後に見たバッジ | 発言の通知に含まれるバッジ（配信者・モデレーター・VIP・サブスク）。**サブスクやVIPの状態は自前で管理しません**。Twitchを真実の持ち主として、最後に観測した値を控えるだけにします（自前で持つと、Twitch側での変更と必ず食い違います） |
| メモ | 配信者が手で書くもの（2000文字まで） |
| 人物像 | 配信が終わったあとにAIが作るもの（200文字まで）。**メモとは別の列に持ち、画面でも別々に出します**（機械の推測と人が書いたものを混ぜないためです）。画面からは書き換えられません |
| その人自身のチャンネルの内容 | 最後に観測したカテゴリとタイトルと、観測した日時。視聴者が自分でも配信している人なら、そのチャンネルからさらに詳しいことが分かるので、AIの材料と画面に使います。**「配信者かどうか」という真偽値では持ちません**（次の箇条書きを参照） |

- 同じ人の記録を更新するのは、**前回から10分が経ったときだけ**です。それより短い間隔で届いた発言では1行も書き込みません（条件に合わない行はD1の書き込みとして数えられないため、常連が連投しても枠を食いません）
- **bot自身の発言は記録しません**。自動モデレーションで処分した発言は記録します（荒らしの履歴も配信者には有用なためです）
- 同じ通知がTwitchから再送されても、発言数は二重に増えません（最後に記録した発言のIDを控えています）。ただし控えているのは直前の1件だけなので、10分の間引きで記録しなかった発言がそれより後に再送された場合は、1回数えられます。発言数はもともと数え落とすことを承知のうえでの概数です
- 記録は人ごとに削除できます（本人から求められたときに応じるためのものです）。削除した人がまた発言すれば、初めての人として記録し直します
- その人自身のチャンネルは、**人物像を作る5人のぶんだけ**、人物像づくりと同じ cron が観測します（`GET /helix/channels`。スコープは要らないので、ログインし直しは不要です）。発言を受け取るたびには調べません（Twitchへ速く応答を返す必要がある道に、問い合わせを足さないためです）。観測できなかった人は前の値のまま残り、`collection_failures` に `viewer-channel-failed` として記録されます（同じ回に複数人ぶん失敗したときは、1行にまとめて残します）
- チャンネルの内容を「配信者かどうか」という真偽値にしないのは、Twitchがその真偽を返さないためです。`broadcaster_type`（partner / affiliate / 空文字）は収益化の区分で、アフィリエイト未満の配信者は空文字になります。観測できるのは「最後に配信した内容があるか」だけなので、値は観測したまま持ち、「配信者らしい」という判断は使う側（AIへ渡す材料と画面）が行います。**調べたが配信した記録が無い人**と**まだ調べていない人**も画面で見分けられます（真偽値1列では同じ「false」に潰れてしまいます）
- この記録は、トリガーの「このチャンネルで初めての発言」「前の発言から空いた日数」の条件の判定にも使います。判定は発言を記録したあとに行い、**同じ通知が再送されても答えが変わりません**（記録を作った発言のIDと、更新する前の最後の発言日時を控えているためです）
