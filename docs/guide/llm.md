# 文面を作らせるLLM（`/llm/`）

このツールがLLMに文面を作らせる箇所は4つあります。**箇所ごとに**提供元とモデルを、管理画面（`https://<公開先のドメイン>/llm/`）で選べます。

| 使う箇所 | 何を作るか | 呼ばれる頻度 |
|---|---|---|
| チャットの文面 | トリガーの動作「AIチャット」が視聴者へ送る文面 | 当てはまった発言・イベントごと |
| サイドスーパー | 配信画面の隅に出す2行のテロップ | cron（5分おき） |
| 視聴者の人物像 | 配信が終わったあと、その人の発言からまとめた文 | cron（1回に5人ぶんまで） |
| 配信のあらすじ | 配信者の発話と視聴者の発言をまとめた文（`{summary}`）と、ダッシュボードに残す配信の章（[配信の記録](./stats.md)） | cron（5分おき） |

選べる提供元は2つです。

| 提供元 | 用意するもの | 備考 |
|---|---|---|
| Workers AI（Cloudflare） | なし（Workerに付いています） | 既定。無料枠（1日10,000 Neurons）の中で動きます |
| OpenRouter | シークレット `OPENROUTER_API_KEY` | ほかの会社のモデルも選べます。料金はOpenRouterのアカウントに請求されます |

「あらすじだけ OpenRouter の賢いモデルに任せ、発言ごとに呼ばれるチャットの文面は無料枠の Workers AI に留める」といった使い分けができます。既定は4か所すべて Workers AI で、あらすじだけ大きいモデル（`llama-3.3-70b`）、ほかの3か所は軽いモデル（`llama-3.1-8b`）です。あらすじに大きいモデルを充てるのは、小さいモデルでは視聴者の書き込みを配信者がしたことのように書く・同じ言い回しを繰り返して長さの上限を超える、といった壊れ方が起きたためです。

OpenRouter を使うときは、先に鍵を設定してください。

```bash
# https://openrouter.ai/keys で発行した鍵を設定する
npx wrangler secret put OPENROUTER_API_KEY
# ローカル（npm run dev）では .dev.vars に OPENROUTER_API_KEY=... と書く
```

- モデルは**一覧から選びます**（手で入力しません）。打ち間違いに気づくのが「配信中に文面が作られなかったとき」になってしまうためです。候補は Workers AI がこのリポジトリの一覧（`worker/llm-models.ts`。文面づくりに向く汎用のモデルだけを載せています。増えたらここに追加します）、OpenRouter が openrouter.ai の公開API（鍵は要りません。Workerが1時間ぶん貯めます）です
- 選んだモデルは**提供元ごとに別に覚えます**（`@cf/meta/llama-3.1-8b-instruct-fp8` と `meta-llama/llama-3.1-8b-instruct` のように書き方が違うため）。切り替えて戻しても選び直す必要はありません
- 候補を読み込めなかったときは、空の選択欄にせず理由を出します。いま保存されているモデルは選択欄に残るので、そのまま保存できます
- OpenRouter を選んだ箇所は、鍵が無ければ**その箇所の文面を作るときに失敗します**（黙って Workers AI へは切り替わりません）。管理画面は、鍵が無いのに OpenRouter を選んでいる箇所の名前を挙げて知らせます
- 失敗（鍵が無い・残高が足りない・無料枠を使い切った）は、箇所ごとの失敗として記録に残ります（`/api/admin/stats/failures` の `alert-aichat-failed`・`side-super-failed`・`viewer-summary-failed`・`stream-summary-failed`）。固定の文言に黙って落とすことはしません

## 使用状況

同じ画面で、**どれだけLLMを呼んだか**を見られます。全体の合計（今日・直近7日・実費・残高）と直近30日の日ごとの呼び出し回数のグラフを上に、箇所ごとの数を「AIを使う箇所」の表の各行に出します。箇所の説明は、名前の横の ？ を押すと出ます。数えているのは Worker 自身で、LLMを呼ぶ唯一の入口（`worker/llm.ts`）が呼び出しのたびに回数・トークン数・実費をD1（`llm_usage`）へ足し込みます。

| 出るもの | 内容 |
|---|---|
| 今日・直近7日の回数 | 文面を受け取れた回数と、失敗した回数（無料枠切れ・残高不足・推論モデルで本文が空だったものを含みます） |
| トークン数 | 提供元が応答に入れてきた値の合計。返してこないモデルでは 0 のままです（回数だけが増えます） |
| 実費 | OpenRouter が1回ごとに返す額の合計（米ドル）。Workers AI は返さないので 0 です |
| OpenRouter の残高 | 付与額・使用額・残り。鍵を設定しているときだけ、画面を開いたときに openrouter.ai へ問い合わせます |

- **日の区切りはUTC**です。Workers AI の無料枠がUTCの日で切り替わるので、それに合わせています（JSTの日付とはずれます）
- **Workers AI の「残り Neurons」は出せません**。読むにはアカウント単位のAPIトークンが必要で、このWorkerはそれを持たない方針です（モデルの一覧を手で持っているのと同じ理由です）。無料枠の使い具合は、呼び出した回数から見当をつけてください
- 記録は1回ごとに1行ではなく、**「日 × 箇所 × 提供元 × モデル」の1行へ足し込みます**（チャットの文面は発言ごとに呼ばれるため）。90日より前の行は消えます
- **判定用のモデル Jev（TypeSafe）の呼び出しも同じ画面に出ます**（「AIを使う箇所」の表の「BGMの選択（Jev）」の行。いまは[BGM](./bgm.md)の「配信の話題に合う曲へ自動で切り替える」の1か所です）。Jev は文面を作らず判定だけを返すモデルで、OpenRouter から呼ぶので同じ `OPENROUTER_API_KEY` と残高を使います。モデルは版を固定しているので選べません。料金は入力 100万トークンあたり $0.042（出力は無料）で、1回はおよそ $0.00004 です
- 使用状況を記録できなかったときでも、**作れた文面はそのまま使います**（モニターのための記録のために配信中の文面が失われないようにするためです）。記録できなかったことは `collection_failures` に `llm-usage-record-failed` として残ります
