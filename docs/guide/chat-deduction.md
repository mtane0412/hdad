# チャットで推理

視聴者がチャンネルポイントで「質問」を送って答え（人物・場所・出来事・もの）を絞り込み、「解答」で当てるゲームです。ページは `/chat-deduction/` です。

質問への答えと解答の正誤は、[合成オーバーレイ](./overlay.md)の素材「チャットで推理」で配信画面にカードとして映します（[配信画面に映す](#配信画面に映す)）。チャットには書き込みません。

## はじめに: 報酬を作る

`/chat-deduction/` の「報酬を作る」を押すと、HDAD が次の2つのチャンネルポイント報酬を作ります。どちらも交換するときにメッセージの入力を求め、ゲームのあいだだけ交換できます。

| 報酬 | 必要ポイント（作ったとき） | 視聴者が書くもの |
| --- | --- | --- |
| チャットで推理: 質問 | 100 | 「はい」か「いいえ」で答えられる質問（例: 生き物ですか？） |
| チャットで推理: 解答 | 300 | 答えだと思うもの（例: 富士山） |

必要ポイントや説明は[チャンネルポイント報酬](./rewards.md)のページで変えられます。この2つの報酬はゲームの開始と終了で使うので、`/rewards/` からは削除できません。

Twitch のダッシュボードで作った報酬は使えません（Twitch は、HDAD が作った報酬でないと交換できるかどうかを切り替えさせないためです）。

## ゲームを始める・終える

1. 「問題集」の欄で問題集を選びます（例: 古代史の人物（24問））
2. 「ゲームを始める」を押すと、HDAD が問題集の中から1問を選び、2つの報酬が交換できるようになります。直前のゲームと同じ問題は選びません（問題集に1問しかないときを除く）
3. 開催中のページには、問題集の名前と区分だけを出します（例: 【人物】古代史の人物）。正解はこのページにも出さないので、配信者も視聴者と一緒に推理できます
4. 終えるときは「終える」を押して確かめます。2つの報酬は交換できなくなります。ゲームを終えたあと（視聴者が正解して終わったときも）は、ページに「前回の正解」を出します

報酬の切り替えに失敗したときは、ゲームを始めません（終えるときは、ゲームを開催中のまま残します）。表示された理由を確かめて、もう一度押してください。

### トリガーで始める

[トリガー](./alerts.md)の行に「チャットで推理を始める」を付けると、その出来事でゲームを始められます（どの行でも選べます）。たとえば「チャットで推理を始める」というチャンネルポイント報酬を作り、その報酬の行に付ければ、視聴者がポイントでゲームを始められます。

- 「問題集」で問題集を選び、「出す問題」で1問を指定するか、「ランダム（直前の問題は除く）」のままにします。問題を指定すると、直前のゲームと同じ問題でもその問題を出します
- チャンネルポイントで始めたときは、ゲームが終わるまで（「終える」を押したときも、視聴者が正解したときも）その報酬を交換できないようにし、終わったら交換できるように戻します。切り替えられるのは HDAD の[チャンネルポイント報酬](./rewards.md)のページで作った報酬だけです。Twitch のダッシュボードで作った報酬で始めると切り替えられないので、ゲームは始まりません
- ほかのゲームが開催中のとき・報酬をまだ作っていないとき・報酬を切り替えられなかったときは、ゲームを始めず、[配信の記録](./stats.md)の失敗の一覧に `chat-deduction-start-failed` を残します。交換されたポイントは返しません

## 質問への答え

ゲームのあいだに「質問」の報酬が交換されると、AI が問題の事実メモだけを材料にして「はい」「いいえ」「分からない」のどれかと、理由の1文（60文字まで）で答えます。事実メモから当然に分かること（日本の地名の出身なら日本の人物、など）には答え、事実メモから分からないことには「分からない」と答えます。理由の1文で出す手がかりは、質問が重なるにつれて増えます。答えた質問が9件までは聞かれたことの言い直しだけで手がかりを足さず、10件からは大まかな手がかり（時代・分野・地方くらい）を1つ、20件からは候補を絞り込める手がかりを1つ添えられるようになります（必ず添えるわけではありません。手がかりは事実メモから選びます。境目は質問の上限30件の3分の1ずつです）。答えは D1 の `chat_deduction_questions` に残ります。

同じ人が続けて質問しても、間を空けずに受け付けます。受け付けないのは次の表の場合だけで、**交換を取り消して視聴者にポイントを返します**。AI は呼びません。

| 理由 | 内容 |
| --- | --- |
| ゲームをしていない | ゲームを始める前・終えたあとに届いた交換 |
| 質問の数の上限 | 1問あたり30件まで。受け付けなかった質問・答えられなかった質問は数えません |

AI が答えられなかったとき（無料枠切れ・返事の形が違う・返事に正解の名前が入っていた）も、交換を取り消してポイントを返し、[配信の記録](./stats.md)の収集の失敗に `chat-deduction-answer-failed` を残します。答えた質問の交換は完了にします。交換を完了・取り消しにできなかったときは `chat-deduction-redemption-failed` を残し、交換は Twitch の待ち行列に未処理のまま残ります（Twitch の画面で処理してください）。

答えを作る AI のモデルは [LLM の設定](./llm.md)の「チャットで推理の質問への答え」で選べます。

## 解答の判定

ゲームのあいだに「解答」の報酬が交換されると、問題の `aliases`（別名の一覧）と照らして正誤を決めます。AI は使いません。照らす前に、解答と別名の両方の表記を次のように揃えます。

- 前後と途中の空白、中黒（・）や句読点・感嘆符などの記号を除く
- 全角の英数字を半角に、半角のカタカナを全角にする。英字は小文字にする
- カタカナをひらがなに直す（長音符「ー」は残す）

揃えたあとで別名のどれかと完全に一致したときだけ正解にします。別名を含むだけの解答（例: 「富士山の頂上」）は不正解です。

- **最初の正解者が出たら、ゲームを終えて2つの報酬を交換できなくします**。正解者の交換は完了にします
- 不正解の解答も D1 の `chat_deduction_guesses` に残し、交換は完了にします（ポイントは返しません）
- ゲームを始める前・終えたあと（正解者が出たあとを含む）に届いた解答は、**交換を取り消してポイントを返します**

正解者が出てゲームを終えても、`/chat-deduction/` は開いたままでは変わりません。再読み込みすると終えたゲームとして表示されます。報酬を交換できなくできなかったときは、[配信の記録](./stats.md)の収集の失敗に `chat-deduction-rewards-failed` を残します（ゲームは終えたままです。`/rewards/` で2つの報酬を確かめてください）。

## 配信画面に映す

`/overlay/` で素材「チャットで推理」をオーバーレイに置きます（追加したときの大きさはオーバーレイいっぱいで、カードを3列に並べて画面全体に出します。背景は透明で上下左右に余白を取るので、画面の縁・カードの隙間・まだカードの無いところからは配信画面が見えます。以前に置いた素材は大きさが変わらないので、表示領域でオーバーレイいっぱいに広げてください）。映すのは最後に始めたゲームです。ゲームを終えると正解を1分間映し、そのあと板ごと消えます（プレビューのサンプルでは消えません）。一度もゲームを始めていなければ何も映しません。

- 見出しの行に区分（例: お題: 場所）と参加のしかたを出します。問題集が時代などの括りを持つときは、区分の前に括りを添えます（例: お題: 古代史の人物）。正解はゲームのあいだは配信画面に出ません（合成ページにも届きません）
- 答えた質問と、正誤を決めた解答を、左上から右へ届いた順に12枚まで並べます（それより古いものは画面から外れます）
  - 質問のカードは「はい」（緑）・「いいえ」（赤）・「分からない」（灰）の色と印、何問目か（Q1・Q2…。画面から外れた質問も数えます）、AI の1文・送った人の名前を出します。質問と1文は、長いときは2行ずつで切ります
  - 解答のカードは「正解」（黄色）・「不正解」（取り消し線）の印と、送った人の名前を出します
  - ポイントを返した質問と解答（ゲームの外・上限・AI が答えられなかった）は映しません
- 終えたら見出しの代わりに「正解は○○でした」の帯を出します（正解者が出て終えたときは緑の帯に「○○さんが正解！」も添え、打ち切ったときは赤の帯にします）
- 終えてから5秒たつと、カードの代わりに正解の解説（問題集の `explanation`）を白い板で出します。記事の画像があれば解説の左に、作者とライセンスを添えて出します（読み込めなければ画像を外し、素材の箱に失敗を出します）。正解の帯は残ります。板が消えるのは、ほかと同じく終えてから1分後です（プレビューのサンプルでは最初から解説を出します）

カードはゲームを始めた・終えた・質問に答えた・解答の正誤を決めたたびに配信画面へ届きます。開始・終了のときに届けられなかったときは、ゲームを始めた・終えたことはそのままにして、ページに理由を出します。質問と解答のときに届けられなかったときは、交換の処理は続け、[配信の記録](./stats.md)の収集の失敗に `chat-deduction-push-failed` を残します。どちらの場合も、合成ページはつなぎ直したときと5分おきに読み直して追いつきます。

## 音を鳴らす

`/chat-deduction/` の「音」のカードで、場面ごとに合成ページで鳴らす音を選べます。音声は先に[アップロードのページ](./alerts.md)で追加しておきます（リポジトリには音声を入れていないので、何も選ばなければ鳴りません）。

| 枠 | 鳴るとき |
|---|---|
| BGM | ゲームを始めてから、正解の解答が出るか打ち切るまでループで流す |
| 開始 | ゲームを始めたとき |
| 回答 | 質問に答えたとき（はい・いいえ・分からないのどれでも） |
| 不正解 | 解答が外れたとき |
| 正解 | 正解の解答が出たとき |
| 打ち切り | 「終える」でゲームを終えたとき |

- 音量は BGM と効果音（BGM 以外のすべて）の2つです
- BGM を流しているあいだは、[BGM](./bgm.md)の配信の曲を下げます。ゲームが終わると戻します。合成ページを閉じても、2分たてば戻ります
- ゲームのあいだに合成ページを開き直したときは、BGM だけを流しはじめます（効果音はそのとき以降に届いた場面でだけ鳴ります）
- 保存した音は、次にゲームが動いたとき（質問に答えた・解答の正誤を決めた など）から鳴ります。プレビューでは鳴りません
- 音に選んでいる音声は、アップロードのページから削除できません。先にこのカードで外してください

## 問題を足す

問題は `src/chat-deduction/problems.json` に問題集ごとに書きます。いまある問題集は「古代史の人物」「古代史の出来事」「いろいろ」です。問題集は次の項目を持ちます。

| 項目 | 内容 |
| --- | --- |
| `id` | 英小文字・数字・ハイフンだけの識別子（例: `ancient-people`） |
| `name` | 問題集を選ぶ欄に出す名前（例: 古代史の人物） |
| `topic` | 省略できます。時代などの括り（例: 古代史）。名前に含まれる語にします。書くと合成ページのお題が「古代史の人物」のようになります。時代の混ざる問題集（いろいろ）には書きません |
| `problems` | 問題の一覧（1問以上） |

1問は次の項目を持ちます。

| 項目 | 内容 |
| --- | --- |
| `id` | 英小文字・数字・ハイフンだけの識別子（例: `mount-fuji`） |
| `category` | 区分。`person`（人物）・`place`（場所）・`event`（出来事）・`thing`（もの） |
| `answer` | 画面に出す正解の表記 |
| `aliases` | 正解として受け付ける表記の一覧。表記を揃えたうえで完全に一致した解答だけを正解にします（[解答の判定](#解答の判定)）。カタカナとひらがな・全角と半角・中黒の有無は揃えるので書き分けなくてよく、別の読みや略称（例: 漱石）を書いておきます |
| `facts` | 質問に答える AI の材料。ここから分からないことは「分からない」と答えさせます。よく聞かれること（性別・日本のものか・いまも残っているか など）は書いておくと答えられます |
| `wikipedia` | 解説に添える画像を引く、日本語版 Wikipedia の記事名（例: 藤原鎌足）。画像は下の手順で作り直します |
| `image` | 省略できます。記事の代表画像が無い・合わないときに、代わりに出す Commons の画像（例: `{ "file": "Map_of_the_Battle_of_Baekgang.png" }`）。[解説に添える画像](#解説に添える画像)を見てください |
| `explanation` | ゲームを終えたあとに配信画面へ出す解説（150文字まで）。AI には作らせず、ここに書いた文をそのまま出すので、確かめた事柄だけを書きます。2〜3文で、正解が何で、何をしたか・何が起きたかと、覚えておきたい点（諸説あることなど）を書くと伝わりやすくなります |

問題の `id` は、問題集をまたいでも重ねないでください。形の誤り（区分の打ち間違い・別名や事実メモや解説や記事名が空・解説が長すぎる・同じ `id`・問題の無い問題集）は `npm test` で見つかります。

### 解説に添える画像

解説の横には、`wikipedia` の記事の代表画像を出します。画像は配信中に取りに行かず、`npm run build:chat-deduction-images` で `src/chat-deduction/images.json` に書き出したものだけを使います（手で直さないでください）。問題を足したとき・記事名を変えたときに作り直し、どの画像になったかを確かめてからコミットします。作り直していないと `npm test` が知らせます。

出すのは、クリエイティブ・コモンズかパブリック・ドメインの画像だけです（市町村紹介と同じ判定）。記事に代表画像が無い・地図や紋章・ライセンスが合わない問題は、画像を出さずに解説だけを出します。

記事の代表画像の代わりに出したい画像があれば、問題に `image` を書いて指名します。`file` には Commons のファイル名を「File:」を付けずに書きます。指名した画像は地図でも出しますが、ライセンスが合わなければ作り直しのときにエラーで止まります。Commons のファイルページの「作者」の欄が空で、本文に作者が書かれている画像（例: 「投稿者 味っ子 が作成」）は、`artist` に作者を書きます（例: `{ "file": "藤原広嗣の乱.png", "artist": "味っ子" }`）。作者の欄がある画像に `artist` を書くと、どちらを出すか決められないのでエラーになります。画像の下には作者とライセンスと「Wikimedia Commons」を添えます。

## 導入

この機能を入れたあとは、マイグレーション `0039_chat_deduction_games.sql`・`0040_chat_deduction_questions.sql`・`0041_chat_deduction_guesses.sql`・`0044_chat_deduction_start_reward.sql` を適用してください（適用方法は[配信の記録](./stats.md)を参照）。`0039` を適用していないと、ゲームを始められず、`/chat-deduction/` の読み込みも失敗します。`0040` を適用していないと質問を、`0041` を適用していないと解答を受け付けられず、Twitch が同じ交換を送り直し続けます。`0044` を適用していないと、ゲームを始められません。

報酬を作るにも、質問の交換を完了・取り消しにするにも、配信者のトークンに `channel:manage:redemptions` が要ります。足りないと言われたら、ログインし直してください。
