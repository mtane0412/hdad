# 開発方針

## このツールが目指すもの

HDAD は、作者（配信者）が**自分の配信に集中するため**のツールです。たくさんの配信者がそれぞれ自分に最適な形へカスタマイズできる汎用性（Firebot やたぬえさが備えているもの）は目指していません。**汎用性よりも属人性**を採り、作者ひとりの配信に最適化された判断をそのままコードに埋め込みます。

目指すのは、**自分の配信のための設定方法を調べて頑張って設定する**状態ではなく、**自分の配信のためにすでに使いやすくなっている**状態です。そのため設定項目は、増やせることではなく減らせることを価値とします。

手を動かすのは基本的にAIエージェントです。配信者が設定画面を探して回るより、望みを言葉で伝えてコードを直させるほうが早い、という前提に立っています。そのため設定UIを増やす代わりに、エージェントが迷わず直せるように約束（`.claude/CLAUDE.md`・`.claude/rules/`）と経緯（`docs/decisions/`）と使い方（`docs/guide/`）を分けて整えます。

作者に最適化されたツールは、そのままでは他の配信者に合いません。それでもソースコードは MIT License で公開しています。他の人の要望を取り込んで汎用化する代わりに、**フォークして自分に特化させてもらう**ためです。改造のハードルはAIエージェントによって下がっており、`.claude/` と `docs/decisions/` はフォークした人のエージェントのためにもあります。フォークからデプロイまでは `README.md` の Deploy to Cloudflare ボタン1つで始められます（手順は [デプロイ](./guide/deploy.md)）。

## これまでの判断から見えている方針

以下は新しく決めた規則ではなく、[`docs/decisions/`](./decisions/) に書かれた判断を読み直して、**繰り返し現れているもの**を言葉にしたものです。迷ったときは、まず自分の判断がこの並びのどれかと衝突していないかを見ます。

判定と検証の置き場・テストの分け方といった実装の作法は、方針ではなく守る約束なので `.claude/rules/implementation.md` に置いてあります。

### 1. 配信者に決めさせず、既定を決め切る

自由に組み立てられる形は、意味を持たない組み合わせを作れてしまいます。選択肢を増やすより、作者の配信に合う既定を決めます。

- **配信者はトリガーを作りません。** 起きうる出来事が区分（チャット・イベント）ごとに最初から固定で並んでおり、画面にイベント種別の選択欄も条件の追加ボタンもありません（[トリガーの管理画面](./decisions/triggers-page.md)）。イベント種別と条件を自由に組み合わせる形を採らなかったのは、「初見さんに反応したい」だけで2段の手順が要るためです（[トリガーの既定メニューと照合](./decisions/alerts-triggers.md)）
- **シャウトアウトはレイドのトリガーにしか置けません。** ほかのイベントの相手は配信者とは限らず、すべての項目に出すと意味のない組み合わせを作れてしまうためです（[トリガーの動作](./decisions/alerts-actions.md)）
- **自動モデレーションのURL判定に、設定として正規表現を持ち込みません**（検証と ReDoS の対策が要るため。[チャットボット](./decisions/bot.md)）

### 2. 打ち間違いは、打たせないことで防ぐ

打ち間違いに気づくのが「配信中に動かなかったとき」になる入力は、手で打たせません。

- **LLMのモデルは入力させず選ばせます**（[LLMの呼び先](./decisions/llm.md)）
- **差し込み語（`{summary}` など）は、文言の欄ごとに押して入れるボタンで並べます**（[トリガーの管理画面](./decisions/triggers-page.md)）
- **素材を置くオーバーレイは選択欄から選ばせ、手で打つのは「オーバーレイを追加する」ときだけです**（名前はOBSに貼るURLに載るため。[構成を編集する管理画面](./decisions/overlay-editor.md)）

### 3. 配信中に変える設定は、URLに入れない

OBSのブラウザソースのURLを配信中に貼り替えさせないためです。逆に「このブラウザソースが何をするか」という構造の指定はURLに残します。

- **読み上げの設定（話者・速度・音量など）をURLから Worker へ移しました**（音量ひとつ変えるのにURLの貼り替えが要ったため。issue #86。[チャットの読み上げ](./decisions/speech.md)）
- **注目コメントで取り上げる発言をURLに入れません**（配信中に選び直すたびに貼り替えることになるため。[注目コメント](./decisions/focus.md)）
- **オーバーレイのURLは `?key=` と `?overlay=` だけで、名前を変えないかぎり貼り替え不要です**（[素材を重ねる合成ページ](./decisions/overlay-stage.md)）。一方で「どの裏方を動かすか」（`?speech=false`）は構造の指定なのでURLに残します（[裏方をまとめたページ](./decisions/backstage.md)）

### 4. 黙って辻褄を合わせず、エラーにする（Fail-Fast）

黙って既定値や別の道へ落とすと、配信者は壊れていることに気づけません。

- **不正なURLパラメータは既定値へ戻さずエラーにします**（`src/core/params.ts:6`）
- **LLMの失敗を、黙って別の提供元へ落としません**（OpenRouter を選んでいるのに鍵が無い・残高が足りない、はすべて投げます。黙って Workers AI に落ちると、課金したモデルが使われていないことに気づけないため。[LLMの呼び先](./decisions/llm.md)）
- **サイドスーパーは2行でなければ、補わず切り詰めず投げます**（片方が届かなくなっていることに配信中は気付けないため。[サイドスーパー](./decisions/side-super.md)）
- **保存済みの設定が古い形なら、読み替えずエラーにして直し方を文面に出します**（[トリガーの既定メニューと照合](./decisions/alerts-triggers.md)・[LLMの呼び先](./decisions/llm.md)）

### 5. Fail-Fast の例外は、数えられるだけに留める

「止める」ことが配信の被害を大きくする場所だけ、意識して例外にします。例外はそれと分かるように書き残します。

- **1つの素材の失敗で、同じオーバーレイのほかの素材は動かし続けます**（被害を配信画面の全損から1素材の欠落に留めるため。失敗はその素材の箱の中だけに出す。[素材を重ねる合成ページ](./decisions/overlay-stage.md)）
- **1つの裏方の失敗で、もう一方は動かし続けます**（1枚にまとめたせいで巻き込まないため。[裏方をまとめたページ](./decisions/backstage.md)）
- **LLMの使用状況の記録に失敗しても、作れた文面はそのまま返します**（モニターのための記録のために配信中の文面が出なくなるのは本末転倒であるため。[LLMの呼び先](./decisions/llm.md)）
- **読み上げは、鳴らしている途中の1件の失敗ではその1件だけを飛ばします**（1件のために以降ずっと無音になるとOBSの再読み込みが要るため。[チャットの読み上げ](./decisions/speech.md)）

### 6. 分からないことは、分かったふりをせずそのまま持つ

- **記録が無い値は `null` のまま持ち、表示のときだけ「—」にします**（0 として出すと「誰も見ていなかった」と「記録できていなかった」が同じ見た目になるため。[ダッシュボード](./decisions/dashboard.md)）
- **視聴者が「配信者かどうか」を真偽値で持ちません。** 観測した値（最後に配信したカテゴリ・タイトルと観測日時）として持ち、「調べたが記録が無い」と「まだ調べていない」を区別します（[視聴者の記録](./decisions/viewers.md)）
- **モデルの一覧を取れなかったときは、空の一覧を返さず投げます**（空の選択欄では「選べるモデルが無い」のか「一覧を取れていない」のか見分けられないため。[LLMの呼び先](./decisions/llm.md)）
- **サブスク・VIPの状態を自前で管理せず、最後に観測した値として控えるだけにします**（自前で持つとTwitch側での変更と必ず食い違うため。同上）

### 7. 外部（Twitch・OBS・ゆかコネNEO）の現実に、形のほうを合わせる

同じ通知が再送される・欲しい通知が無い・APIが真偽を返さない、といった現実に合わせて作りを決めます。

- **同じ通知の再送で二重に実行しないよう、鍵を確保してから送ります**（鍵には動作の種類と当てはまった順の位置まで混ぜる。[トリガーの動作](./decisions/alerts-actions.md)）。**送信に失敗してもTwitchへは2xxを返して記録します**（2xx以外だと再送で二重投稿になるため）
- **Twitchには広告の終了の通知が無いので、Worker が擬似イベントを作ります**（開始に入っている長さから終わる時刻を Durable Object のアラームへ預ける。[広告の開始と終了](./decisions/ad-break.md)）
- **ゆかコネNEO の `isDeleted` を取り消しとして扱いません**（字幕の表示時間が尽きたときにも届き、編集者の取り消しと区別できない。取り消しとして扱っていたため確定した発話が数秒後に消えていた。[配信中の文字起こし](./decisions/transcript.md)）
- **初見の判定にTwitchのAPIは使えないので、自前の記録を使います**（EventSub の `channel.chat.message` には IRC のタグにある `first-msg` が無いため。[トリガーの既定メニューと照合](./decisions/alerts-triggers.md)）

### 8. 無料枠とデータベースの枠が、設計を決める

個人が無料枠の範囲で動かし続けられることを前提に作ります。

- **あらすじは毎回ゼロから作り直さず、前回のあらすじに積み上げます**（長い配信でも1回あたりの入力が一定に保たれ、Workers AI の無料枠を食い潰さないため。[これまでのあらすじ](./decisions/stream-summary.md)）
- **新しい材料が1件も無ければLLMを呼びません**（同上・[サイドスーパー](./decisions/side-super.md)）。**コマンドやトリガーのたびにもLLMを呼びません**（無料枠が視聴者の発言数しだいにならないため。同上）
- **発言ではなく人を貯めます**（1人1行なら数千人でも数MBに収まる。[視聴者の記録](./decisions/viewers.md)）。**LLMの使用状況も1呼び出し1行ではなく「日 × 箇所 × 提供元 × モデル」の1行へ足し込みます**（[LLMの呼び先](./decisions/llm.md)）
- **OBSのブラウザソースは、素材の数ではなく「Webでないソースを挟んで何枚に分かれるか」の数だけにします**（ブラウザソースはその数だけ Chromium のレンダラを立ち上げるため。[素材を重ねる合成ページ](./decisions/overlay-stage.md)）

### 9. 画面では、説明せずに見せる

- **「オーバーレイを追加する」欄では、名前がURLに載ることを文章で説明せず、打っている名前の入ったURLをその場に出します**（打てばURLが目の前で変わるなら説明は要らない。[構成を編集する管理画面](./decisions/overlay-editor.md)）
- **形で表せるコマンド（追加する・コピー・前面へ／背面へ・外す）はアイコンだけのボタンにします。** 文字を残すのは形では表せないもの（「プレビューを見る／閉じる」「構成を保存する」）だけです（同上）
- **文字が要る箇所（通知・説明文・読み上げの名前）では「足す」ではなく「追加する」と書きます**（ページごとに言い方が混ざらないように。同上）
- **読み上げに渡す名前は、どれも見えている文字を含むものにします**（音声で操作する人が画面に見える言葉で呼べるように。WCAG 2.5.3。同上）

### 10. 用語は、配信者の見え方に合わせる

実装の都合ではなく、配信者がOBSやテレビで見ている形に名前と構造を合わせます。

- **オーバーレイ＝OBSのブラウザソース1つ、その中に素材を積む**（当初の「段に置くレイヤー」から改めた。OBSではブラウザソースの重なりがレイヤーなので、内側をレイヤーと呼ぶと逆立ちする。[素材を重ねる合成ページ](./decisions/overlay-stage.md)）
- **素材の一覧は、構成の並びを逆にして前に出るものから並べます**（OBSのソース一覧と同じく上にあるものが前。[構成を編集する管理画面](./decisions/overlay-editor.md)）
- **サイドスーパーは2行で固定です**（テレビのサイドスーパーが枠の形を変えず中身だけを差し替えるため。行数が回ごとに変わると、出しっぱなしのテロップではなくその都度出る通知に見える。[サイドスーパー](./decisions/side-super.md)）

### 11. 機械が作った文は信用せず、人が書いたものと混ぜない

- **LLMが返した文面は信用しません**（500文字を超えていたら切り詰めずに送るのをやめ、失敗も黙って固定文言に落とさない。[トリガーの動作](./decisions/alerts-actions.md)）
- **あらすじと人物像は、材料であって指示ではないことをプロンプトで明示します**（どちらも視聴者の発言を材料にLLMが作ったもので、指示のように書かれた文が混ざりうるため。同上）
- **人物像（`summary`）は配信者が書くメモ（`note`）と別の列に持ち、画面でも別々に出します**（機械の推測と人が書いたものを混ぜない。[視聴者の記録](./decisions/viewers.md)）
- **配信者の発話が1件も無ければ、視聴者の発言があってもあらすじを作りません**（ゆかコネNEO を動かし忘れた配信で、視聴者の書き込みが配信で起きたこととして書かれたため。[これまでのあらすじ](./decisions/stream-summary.md)）

### 12. 役割を終えた形は残さず消す

自分ひとりのためのツールなので、使わない道を互換のために抱えません。消す前に、何を確かめたら消してよいかを先に決めます。

- **素材ごとの単独ページとギャラリーをすべて消しました**（合成ページを入れた時点では残し、「メモリの実際の減り方」「数時間の配信での描画の乱れ・接続の切れ」「1素材の失敗が他に波及しないこと」を実配信で確かめてから issue #107 で消した。[素材を重ねる合成ページ](./decisions/overlay-stage.md)）
- **中身が空になる画面は消します**（`/side-super/` は単独ページのURLと寄せる向きの選択だけだったので画面ごと消し、固有の操作を持つ `/focus/`・`/triggers/` は残した。同上）
- **保存済みの設定に後方互換を持ちません**（開発中で保つ必要がないため、暗黙の読み替えを増やさない。[トリガーの既定メニューと照合](./decisions/alerts-triggers.md)）

## 要約

HDAD が目指すのは汎用の配信ツールではなく、作者ひとりの配信に最適化されたアシスタントです。設定して合わせるのではなくすでに合っていることを目指し、手を動かすのはAIエージェントである前提に立ちます。他の配信者には汎用化で応えず、MIT License でフォークして特化させてもらう形を採ります。

これまでの判断からは、次の12の方針が繰り返し現れています。**既定を決め切る**・**打ち間違いは打たせないことで防ぐ**・**配信中に変える設定はURLに入れない**・**黙って辻褄を合わせずエラーにする**・**その例外は数えられるだけに留める**・**分からないことはそのまま持つ**・**外部の現実に形を合わせる**・**無料枠とデータベースの枠が設計を決める**・**画面では説明せず見せる**・**用語は配信者の見え方に合わせる**・**機械が作った文を人が書いたものと混ぜない**・**役割を終えた形は残さず消す**。
