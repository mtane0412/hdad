# 注目コメント（`/focus/`）

注目コメント（`/focus/`）は視聴者の発言1件を配信画面に大きく出しっぱなしにする仕組みで、オーバーレイ（`focus/overlay/index.html`）はサイドスーパーと同じく `vite.config.ts` の `categories` ではなく入力に直接足している（`/focus/` をアプリのページに使うため）。

## 取り上げ方は2通りを1つの保存先で表す

**取り上げ方は2通りを1つの保存先で表す**（`worker/focus-config.ts` の `FocusTarget`。KVのキーは `focus-target`）。`viewer` は人に追従し（ログイン名だけを持ち、オーバーレイが匿名IRCで届く発言を絞って最新の1件へ差し替える）、`message` は発言1件を固定する（選んだ時点の本文を写して持つ）。

**取り上げる相手をURLに入れない**（配信中に相手を変えるたびにOBSのURLを貼り替えることになるため。読み上げの設定をURLから移した issue #86 と同じ考え方である）ので、配送はポーリング（`GET /api/overlay/focus`。10秒）で行う。サイドスーパーの30秒より短いのは、配信者が「今から怖い話をする」と言い出した人を見つけてから取り上げるので、映るまでの待ちを短くするためで、読むのはKVの1件だけである。

`message` で本文を写して持つのは、発言の記録（`stream_chat_messages`）が人物像を作り終えた時点で消えるためである。

## 何を映すかの判断は1か所に持つ

**何を映すかの判断は `src/focus/focused.ts` だけが持つ**（通信もDOMも持ち込まない形に切り出し、`withTarget`・`withMessage`・`withRemoval` の3つで表す）。

- **同じ指定を読み直したときは状態を据え置く**（読み直しのたびに作り直すと、追従中は映していた発言が消え、固定中はモデレーターに消された発言が復活する）
- **人に追従する指定へ切り替えた直後は何も映さず、その人の次の発言から映す**（IRCは過去の発言を送ってこないので、切り替える前の発言は手元に無い。貯めて掘り返すこともしない）
- **モデレーターの操作（発言の削除・BAN・タイムアウト・全消去）で映しているものが消えたら映すのをやめる**（配信画面に残すと取り返しがつかない。そのため固定中もIRCにつなぐ）

## 画面では2つのモードを別の場所で選ばせる

**画面では2つのモードを別の場所で選ばせる**（`src/focus/focus-page.tsx`）。追従は「誰を追うか」を決める操作なので相手の指定（ログイン名）が要り、取り上げは「どの発言を出すか」を決める操作なので誰の発言かによらない。そのため直近の発言の一覧に「この人に追従する」は置かない（一覧に混ぜると、コメントを選んでいるのか人を選んでいるのかが行ごとに曖昧になる）。

相手を打ち間違えずに指定できるよう、追従の側には「発言した人から選ぶ」選択欄を置き、選ぶとログイン名の欄が埋まるだけにする（送る道を1つに保つため）。並べる人は直近の発言から重複なく取り出す（`src/focus/form.ts` の `speakersOf`。同じ人はいちばん新しい発言の表示名で1回だけ並べる）。手で打つ欄を残すのは、その配信でまだ発言していない人には選択欄が使えないためである。

取り上げる発言を選ぶ一覧は `worker/stream-chat-store.ts` の `readRecentChatToPick` が読む（いま進んでいる配信の直近の発言を新しい順に、発言者の名前を `viewers` から添えて読む。あらすじ・サイドスーパーの材料が名前を返さないのと意識して違える＝配信者が人を見て選ぶためである。記録が無い人の発言は返さない）。

経路は `worker/focus-routes.ts`（`GET`/`PUT /api/admin/focus`・`GET /api/admin/focus/messages`）とオーバーレイ側（`overlay-routes.ts` の `getFocus`）で、値の検証は `focus-config.ts` だけが持つ。

## 見た目

サードパーティ（7TV・BTTV・FFZ）のエモートは読み込まない（取得の失敗を知らせる場所がこのページに無く、1件を大きく映すのに要らない。公式エモートと Cheermote は絵で出る）。

見た目（`src/focus/focus.css`）はサイドスーパーと違って**本文に半透明の板を敷く**（取り上げるのは語りや質問そのもので読ませる量が多く、袋文字では読みにくいため）。
