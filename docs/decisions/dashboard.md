# ダッシュボード（`/`）

ダッシュボード（`/`）はログイン後に最初に出す画面（`src/stats/stats-page.tsx`）で、Workerが貯めた配信の記録（`/api/admin/stats/*`）を読み、期間（7・30・90日）の概要・フォロワー数の推移・配信の一覧を出す。配信を選ぶと、その配信の視聴者数の推移を読み込んで一覧の中に出す。

Workerの呼び出し（`src/stats/api.ts`）と集計・整形（`src/stats/summary.ts`）を画面から分けてテストするのは、ほかのアプリのページと同じ分け方である。

## Recharts は1つのファイルだけが読み込む

**グラフ（`src/stats/time-chart.tsx`）だけが Recharts（`@/components/ui/chart`）を読み込み、ダッシュボードはそれを `React.lazy` で切り離して読み込む。**

Recharts は重いので、まとめて読み込むとギャラリーや管理画面を開くだけでグラフの実装まで運ぶことになる。切り離しの効き目はこのファイル以外から Recharts を読み込まないことに依存するので、約束としてファイルの冒頭にも書いてある。

読み込んでいるあいだはグラフと同じ高さの `Skeleton` を出し、読み込みの前後で画面の高さが変わらないようにする。

## 色はテーマのトークンを使う

**折れ線の色は固定の色ではなくテーマのトークン（`--chart-2`）を使う**（`CHART_CONFIG`）。明暗はOSの設定に従うので、どちらの地色でも読める中間の濃さが要る。明るい地色に合わせて選んだ色は暗い地色で沈み、その逆も起きる。

グラフの中身（SVG）は読み上げても意味が通らないので、`role="img"` と説明（`aria-label`）を付けてひとつの図として読ませる。

## 記録が無いことと 0 を区別する

**記録が無い値は `null` のまま持ち、表示のときだけ「—」にする**（`summary.ts` の `formatCount`・`formatDelta`）。0 として出すと「その日は誰も見ていなかった」と「その日は記録できていなかった」が同じ見た目になり、収集が止まっていることに気づけない（Fail-Fast）。

読み込みそのものに失敗したときも、記録が無いように見せず理由を出す。

日時は配信者のブラウザのタイムゾーンで出す（配信者が自分の配信を振り返るための画面なので、UTCで出すと配信した時間帯と合わない）。
