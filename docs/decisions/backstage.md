# 裏方をまとめたページ（`overlay/backstage/`）

**裏方をまとめたページ（`overlay/backstage/`）は、OBSに置くWebのページのうち映すものを持たないもの（チャットの読み上げ・文字起こしの中継）を1つのブラウザソースにまとめる**（issue #108）。実ファイルを `/overlay/backstage/` に置くのは `/overlay/` を構成の管理画面に使うためで、`vite.config.ts` の `categories` ではなく入力に直接追加している。

## 合成ページの素材にはしない

**合成ページ（`overlay/stage/`）の素材にはしない。** 裏方は映すものを持たないので位置も大きさも持たず、素材にすると構成が持つ `rect` が意味を失う。

読み上げの起動の失敗は配信画面の小さな箱の中に出しても配信者は見ないので、「素材の失敗はその箱の中だけに出す」という約束とも前提が合わない。また合成ページのブラウザソースは「配信画面に映すもの」なので、同じPCのループバックへしかつなげない裏方を混ぜるとその見方が崩れる（案として「素材の種類にする」と「そのままにする」も比べたうえで、裏方だけの1枚を採った）。

## 動かす裏方はURLで指定する

**動かす裏方はURLで指定する**（`?speech=false`・`?transcript=false`。既定は両方）。合成ページの `?overlay=<名前>` と同じ「このブラウザソースが何をするか」という構造の指定なので、配信中に変える設定をWorkerへ移した issue #86 とは扱いを分ける。

ひとつも動かさないURLは組み立てない（`src/backstage/url.ts` の `backstageUrl`。貼っても何もしないブラウザソースを作らせない＝素材を1つも持たないオーバーレイを保存しないのと同じ考え方である）。

## 片方の失敗をもう一方に広げない

**1つの裏方の失敗で、もう一方は動かし続ける**（合成ページが素材について設けた例外と同じ。1枚にまとめたせいで片方の失敗がもう一方を巻き込まないため）ので、裏方ごとに箱（`.backstage-task`）を置いて失敗はその中に出す。そのため `src/transcript/transcript.css` の `.transcript` は `position: fixed` から `absolute` に直してある（素材のCSSを直したのと同じ理由である）。

裏方そのものは `src/speech/task.ts` の `startSpeech` と `src/transcript/task.ts` の `startTranscript` にあり、単独ページと同じものを呼ぶ（判定や通信を2か所に書き分けない）。**単独ページ（`speech/reader/`・`transcript/relay/`）は残してある**（素材の単独ページと同じく、消すかどうかは別に決める）。

アプリのページ（`src/backstage/backstage-page.tsx`）は動かす裏方の選択とゆかコネNEO のポート、それにOBSに貼るURLを受け持ち、URLの組み立ては `url.ts` に分けてテストする（ポートの検証は `src/transcript/url.ts` の `assertTranscriptPort` を共有する。2か所で書き分けると、同じ入力欄に対して片方だけが通るURLを出してしまう）。

## アプリのページをコネクターにまとめる

はじめはサービスごとにアプリのページを分けていた（読み上げ `/speech/`・文字起こし `/transcript/`・画面の取り込み `/screen/`・タブの映像 `/tab/`・裏方のURL `/backstage/`）。しかし、文字起こしのページは裏方のURLと同じポートの入力欄とURLを出すだけで、読み上げのページのURLも裏方のURLと重なっていた。配信者は、裏方の1枚を貼るのに、設定をするページとURLをコピーするページを行き来する必要があった。

そこで、外部のサービスとつなぐもの（VOICEVOX・ゆかコネNEO・Gyazo・HDAD-tab）を1つのアプリのページ「コネクター」（`/connectors/`）にまとめた。HDAD-tab は裏方ではない（映すのは合成ページの素材「タブの映像」）が、「HDAD の外のもの（Chrome 拡張）とつなぐ」という点で同じ場所に置いた。ページ名は、「裏方」では HDAD-tab が入らず、何をするページかも伝わりにくいので「コネクター」にした。

- **項目はサービスの名前で呼ぶ**（「チャットの読み上げ」ではなく VOICEVOX）。配信者が実際に起動して設定するのはそのサービスなので、名前が一致しているほうが迷わない
- **説明文は項目ごとに並べない。** 一度読めば済む説明（外部サービス側の CORS の設定・拡張の入れ方・入力値の目安）が画面の大半を占め、配信中に開くたびに読み飛ばす必要があった。要る説明は見出しの右のヘルプボタン（`src/components/help-button.tsx`）の中に入れる。ただし、状態によって出るもの（再読み込みが要るという知らせ・読み込みの失敗）は説明ではないので、これまでどおり画面に出す
- **OBS側のページの名前（`overlay/backstage/`）は変えない。** 配信者がすでにブラウザソースに貼っているURLを、貼り替えずに済ませるためである。単独ページ（`speech/reader/`・`transcript/relay/`）も同じ理由で残すが、アプリはそのURLを出さなくなった（新しく貼るなら裏方の1枚で足りる）
- 古いパス（`/speech/` など）には転送を置かず、「見つからない」画面を出す。HDAD は配信者本人が使う道具で、サイドバーとページ検索（言い換えとして「読み上げ」「文字起こし」などを残してある）から移れば足りる

## 文字起こしの中継を外した（issue #192）

文字起こしの認識をアプリの枠の音声認識（issue #189）へ移したので、裏方から ゆかコネNEO の中継（`?transcript=`・`?host=`・`?port=`）と単独ページ `transcript/relay/` を消した。コネクターのページからも ゆかコネNEO の印とポートの入力欄を外し、ポートの検証（`src/transcript/url.ts` の `assertTranscriptPort`）も使う先が無くなったので消した。裏方は読み上げ・画面の取り込み・BGMの3つになり、既定で動くのは読み上げだけなので、読み上げを外すときはほかのどれかを選ばないとURLを出さない。以前のURLに残った `?transcript=` などを読み替えない理由は `docs/decisions/transcript.md` に書いた。
