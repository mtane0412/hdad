# VRMの演出とマスコット

配信者がアップロードした VRM のキャラクターを、トリガーで短いあいだだけ出して動かす演出（issue #358）として始め、段階 B（#359）で出しっぱなしのマスコットに置き換えた。VRM をオーバーレイに描く3段階（A 演出 #358 → B 出しっぱなしのマスコット #359 → C 配信者自身のアバター #360）の最初で、B へ進むかは A で OBS の負荷を測ってから決める。

## 動きは手で作る（VRMA を使わない）

VRMA（VRM Animation）のファイルを使うと動きは自然になるが、VRMA のアップロードと選択の経路が増え、動きの中身がファイル任せになって種から変えられない。
段階 A は「出てきて、手を振って、お辞儀して、帰る」の決まった長さの演出なので、正規化された骨の回転をコードで書いた（`src/vrm/motion.ts`）。種と経過時間だけから決まる関数にでき、テストも書ける。配信者が着手時に選んだ。

## どのトリガーにも置ける

ペロペロ（相手1人のアイコンを舐める）やツイスター（レイドした配信者と対戦する）と違い、この演出は相手を必要としない。置ける項目を絞る理由が無く、負荷を測るにも試しやすいので、すべての項目に置けるようにした。配信者が着手時に選んだ。

## 出す VRM は全体で1つ

トリガーの行ごとに VRM を選ばせると、動作の設定と検証が増える。ペロペロの効果音と同じく、トリガーのページのカードで1つ選んで KV に持ち、どの行と試し再生も同じ VRM を出す。配信者が着手時に選んだ。

## VRM は素材の種類 `vrm` にし、アラートの素材から外す

VRM はリポジトリに入れられない（再配布できないモデルがある）ので、音声と同じく R2 の素材としてアップロードする。VRM は glTF のバイナリと同じ形なので `model/gltf-binary` で受け取る。`application/octet-stream` はどのファイルにも付きうるので、受け付けると種類の判定が意味を失う。ブラウザは .vrm に種類を付けないため、管理画面が拡張子を見て付ける。
素材の種類はアラートの素材の選択と共有しているので、アラートに VRM を選べないよう Worker の検証と画面の選択肢の両方で外した（Worker は「存在しません」ではなく「VRM なのでアラートには使えません」と返す）。

## 段階 A では SpringBone を使わなかった

`vrm.update` は髪や服の揺れ（SpringBone）を前のコマの状態から計算するので、描画は経過時間だけから決める約束（`docs/decisions/rendering.md`）の例外になる。段階 A は約束の範囲で作ると決めていたので、`humanoid.update` と `expressionManager.update` だけを呼ぶ。揺れ物は段階 B（#359）で、例外として記録してから足す。

## プレビューは配信者のセッションで VRM を読む

合成ページのプレビュー（`?demo=true`）はオーバーレイ用キーを持たず、Worker の押し出しにつながない（`docs/decisions/overlay-stage.md`）。しかし VRM の演出は VRM が無いと何も映らず、見栄えと置き場所を決められない。
プレビューは管理画面の中で開かれ配信者のセッションがあるので、`GET /api/admin/vrm/model` を1回だけ読み、`/api/media/<ID>`（セッションで読める）から VRM を読み込む。押し出しの接続やポーリングは増やさないので、「配信中のものに加えてもう1組動く」ことは起きない。

## 実物の VRM で向きを確かめた

骨の回転の向き（腕を下ろす・お辞儀を前へ・進む向きを向く）は、three-vrm の VRM 1.0 のサンプル（`VRM1_Constraint_Twist_Sample.vrm`。約10MB）を一時的に置いたページで、手を振る・お辞儀・歩いて出てくる場面を描いて確かめた（2026-10-13。読み込みは手元の開発サーバーで約0.4秒）。VRM 0.x は公開されたサンプルが無く、実物では確かめていない（three-vrm の VRMA の読み込みと同じく、X・Z の回転を反転して当てる）。

## 検証の結果（段階 B へ進む）

段階 B へ進むかを決める材料として、配信者が OBS で次を確かめた（2026-10-13）。

- OBS のブラウザソースで流しているあいだも、CPU 使用率は VRM を置かないときとほとんど変わらなかった
- ペロペロ・ツイスターと同じオーバーレイに置いても、WebGL の描画はどれも問題なく出た
- 手元のモデルは `MAX_MEDIA_BYTES`（50MB）に収まり、上限は変えずに済んだ

負荷に問題が見られなかったので、段階 B（#359 出しっぱなしのマスコット）へ進む。B では出しっぱなしで描き続けるので、待機の動きと揺れ物を足したあとに改めて負荷を見る。

## 段階 B: 演出を出しっぱなしのマスコットに置き換えた

段階 B（#359）は、段階 A の素材の種類 `vrm` を出しっぱなしのマスコットに変えた。別の素材の種類を足して A の「歩いて出てきて帰る演出」を残す案と、素材のパラメータで演出とマスコットを切り替える案もあったが、どちらも同じ VRM を2つの箱で二重に読み込みうるか、設定項目が1つ増える。配信者が着手時に、既存の `vrm` を変える案を選んだ（2026-10-13）。トリガーの呼び出しは、歩いての出入りをやめ、その場で手を振ってお辞儀する反応にした。

- マスコットは呼び出しが届く前から立たせるので、合成ページが VRM の URL を自分で読む経路（`GET /api/overlay/vrm/model?key=`）を足した。読むのは配送先につながるたび（`onOpen`）で、ポーリングはしない。配送先に VRM の設定を持たせない（Durable Object は判定者ではない）
- 待機の動き（呼吸・瞬き・視線のゆらぎ）は約束の範囲（種と時刻だけから決める）で作った。瞬きは「前に瞬いてからの時間」を覚えず、時刻を区切った番号と種から区切りごとの瞬く時刻を決める
- 反応は待機の姿勢に足す形で重ね、反応のはじめと終わりが同じ時刻の待機の姿勢とつながるようにした（テストで確かめている）。置き換えると、反応が始まった瞬間に呼吸で反った胸が戻るなど、姿勢が飛ぶため
- 推奨の大きさは、歩いて出入りしなくなったので配信画面いっぱいから縦長（480×720px）に変えた

#359 は「① 出しっぱなしと待機の動き → ② 揺れ物（SpringBone） → ③ 読み上げとの口パク → ④ チャットへの反応」の順に PR を分けて進める。口パクの音源と口の形は ③ に着手するときに決めた（下の「読み上げとの口パク」）。

## 髪や服の揺れ（SpringBone）を、経過時間だけから描く約束の例外にした

出しっぱなしのマスコットでは、ツイスターのように物理を先に計算して記録しておくことができない（いつ何が届くか分からず、終わりもない）。そこで段階 B の ②（#359）で、髪や服の揺れだけを経過時間だけから描く約束（`docs/decisions/rendering.md`）の例外にした。骨の回転・表情は今までどおり時刻だけから決め、揺れ物は `humanoid.update` で骨を写したあとに `springBoneManager.update` で進める。`rendering.md` の「例外を作るときに書き残すこと」に従い、次の2つを書いておく。

- **コマが落ちたときに何が起きるか**: 1コマで揺れ物を進める時間を、前のコマからの時間差と上限 1/30 秒の小さいほうにする（`src/vrm/spring.ts` の `springStepSeconds`）。OBS がソースを隠していた・負荷が高くてコマを落としたあとでも、揺れ物は1コマぶんしか進まず、少し遅れて追いつくだけになる。大きな時間差を一度に計算して髪が跳ね飛んだり、体を突き抜けたりはしない。最初のコマ・時刻が戻ったときは進めない（0 秒）。モデルを読み替えたら前のコマの時刻を持ち直す
- **テストで確かめられないこと**: 揺れ物は前のコマの状態から決まるので、時刻を渡してもその時刻の髪や服の姿が決まらず、テストで確かめられない。テストするのは、進める時間の決め方（`springStepSeconds`）だけである

揺らさずに硬いまま描く案とも見比べて決める。比べるために、素材のパラメータ `spring`（既定は揺らす）を一時的に置いた。保存すれば OBS にもそのまま反映されるので、配信中の画面で切り替えて見比べられる。どちらにするか決めたら、パラメータを消して決めたほうだけを残す（設定項目は増やさない）。

OBS で見比べた結果、揺らすほうに決めた（2026-10-14）。パラメータ `spring` は消し、揺れ物はいつも揺らす。消す前に `spring` を保存していた構成は、ほかの素材と同じく「未対応のパラメータ」のエラーを出す（黙って読み捨てない）ので、構成の画面で保存し直す。

## 読み上げとの口パク（どの読み上げにも合わせ、音量で開け閉めするだけ）

段階 B の ③（#359）で、マスコットの口を読み上げに合わせた。配信者が着手時に次の2つを選んだ（2026-10-13）。

- **どの読み上げに合わせるか**: 裏方の読み上げ（別のブラウザソース）にも、同じ合成ページの中のワイプにも合わせる。ワイプだけに合わせる案はページをまたがない確かさがあるが、裏方で読み上げている配信では口が動かない。マスコット自身が読み上げる案は、ワイプ・裏方の読み上げとの二重読みを防ぐ検証を広げることになる
- **口の形**: 音量で表情 `aa` を開け閉めするだけにした。母音まで合わせる案は VOICEVOX の `audio_query` のモーラを使えば作れるが、合成の経路を変える必要があり、さくらのAI Engine で同じ情報が取れるかは確かめていない

音量の渡し方は、鳴っている音を `AnalyserNode` で毎コマ測ってページをまたいで送るのではなく、読み上げのページが鳴らす前に音声を読み解いて区切りごとの音量の列を作り、鳴りはじめに「時刻と列」を1回だけ配る形にした。マスコットは列とその時刻から口の開きを決めるので、口パクは経過時間だけから描く約束の範囲に収まり、テストで時刻ごとの開きを確かめられる。知らせは鳴らす1件につき2回（鳴りはじめと止まったとき）で済む。止まった知らせを受け取れなくても、列の長さを過ぎれば口は閉じる。

ページをまたぐ受け渡しには BroadcastChannel を使う。OBS のブラウザソースどうしで届くかは、実機で確かめる。

## チャット・トリガーへの反応は、項目ごとに決め切る

段階 B の ④（#359）で、反応を「手を振ってお辞儀」の1種類から、お礼・大喜び・手を振る・うなずくの4種類に増やした。配信者が着手時に次の2つを選んだ（2026-10-13）。

- **反応の決め方**: トリガーの項目ごとに Worker が既定を決め切る（`worker/vrm-call.ts` の `vrmReactionOf`）。動作ごとに配信者が選ぶ欄を足す案は、設定項目と検証が増える（`docs/principles.md` の「配信者に決めさせず、既定を決め切る」）。種でランダムに選ぶ案は、出来事と反応の意味が結びつかない。割り当ては、支えてもらった出来事にお礼、大きな出来事に大喜び、来た人と場面の切り替わりに手を振る、たくさん届くふだんの出来事にうなずく、とした
- **混んでいるとき**: 反応の最中（流している・読み込んでいる・待っている呼び出しがある）に届いたうなずきは捨てる。うなずきは「すべての発言」のように速いチャットで次々届く項目に当てるので、待たせると待ちが積もって何分も前の発言にうなずき続ける。ほかの反応は1回ずつ意味を持つので、今までどおり待って流す

発言への反応は、マスコットがチャットを自分で受け取る形にはせず、トリガーの項目（すべての発言・キーワードなど）に動作 `vrm` を置く形に乗せた。issue の「反応の内容は段階Aの動作と同じ仕組みで流す」のとおりで、照合の持ち主（`worker/alert-event.ts` の `matches`）を1つに保つためである。

## 段階 C（配信者自身のアバター）は作らない

#360 で、カメラで追った顔の動きを VRM に映し、配信者自身のアバターにする段階 C を検討し、作らないと決めた（2026-10-14）。

- 配信者は顔の追跡にすでに Webcam Motion Capture を使っている。HDAD で作る理由は「別のツールを増やしたくない」だったので、MediaPipe で追跡を作り直すより Webcam Motion Capture の値を受け取る形が先に候補になった
- Webcam Motion Capture が外のアプリへ出せるのは VMC プロトコル（OSC を UDP で送る）だけで、WebSocket や HTTP では出せない。ブラウザ（合成ページもアプリの枠も）は UDP を受け取れないので、手元の PC で UDP を WebSocket に中継するプログラムを配信のたびに起動する必要がある。拡張機能（`extension/`）でも UDP は扱えない
- 中継を足すと「ツールを増やしたくない」という理由と逆になり、得られるもの（トリガーや読み上げとの連動）に対して過剰と判断した。配信者のアバターは Webcam Motion Capture から OBS に直接出し、HDAD の VRM はマスコットだけに使う

マスコットの口をマイクの声にも合わせる案（#368）も、同じときに見送った。マスコットは「コメントを読む相棒」の役割に留め、配信者の分身にはしない。分身は Webcam Motion Capture のアバターが受け持つので、マイクの声に合わせるためにマイクの拾い方と、口の開きを経過時間だけから決める約束の例外を足すことはしない。
