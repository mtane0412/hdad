# 構成を編集する管理画面（`/overlay/`）

構成を編集する管理画面（`/overlay/`。`src/overlay/overlay-page.tsx`）は、オーバーレイの追加・削除と、その中の素材の一覧・並べ替え・置くオーバーレイの選び直し・位置と大きさ・パラメータ・オーバーレイごとのOBS用URLを受け持つ（issue #103）。

Workerの呼び出しは `src/overlay/admin-api.ts`（応答の形の確かめ `readOverlays` は合成ページの `api.ts` と共有する）、入力欄の値の変換とデザインのスキーマの引き当ては `form.ts`、URLの組み立ては `url.ts` に分けてテストする。

## 画面の作りと並べ替え

**画面はオーバーレイ1つを1枚のカードにし、その中に素材を並べる**（保存の形と同じ入れ子なので、配信者が見ている枠がOBSのブラウザソース1つに対応する）。

**構成では素材の並びがそのまま重ねる順（あとのものが前）だが、一覧では並びを逆にして前に出るものから並べる**（`form.ts` の `frontFirstItems`）。OBSのソース一覧と同じく上にあるものが前で、上下の向きと重なりの前後が一致するためである。保存の形は変えないので、構成での位置（`ItemSlot.position`）を添えて返し、並べ替えと外す操作はその位置で行う。

動かすボタンは「前面へ」（ひとつ上）・「背面へ」（ひとつ下）と言う。**オーバーレイ同士も「上へ」「下へ」で並べ替えられる**が、こちらは重なりと関わらない（別々のブラウザソースなので）ので上下で言う。並べ替えはどちらも `form.ts` の `moveDraft` が行い、並びの外へ出る動かし方では並びを変えずに返す（切り取った1件が別の場所へ回り込まないため）。

## 入力と検証

素材のパラメータの入力欄はスキーマからの自動生成を使う（`src/core/fields.tsx` の `ParamField`。当初はギャラリーと共有するため `gallery.tsx` から切り出したもので、ギャラリーを消したあと（issue #107）は管理画面だけが使う）。組み立てたクエリ文字列は `src/core/url.ts` の `serializeParams` が作り、既定値のままのパラメータは書かない。

**値の検証は `worker/overlay-layout.ts` だけが持つ**ので、画面は空欄を 0 に丸めず NaN のまま送り（JSONでは `null`）、返ってきた問題点を `describeOverlayProblem` で送った順のオーバーレイと素材の名前へ読み替えて並べる（`/triggers/` の `describeProblem` と同じ考え方である。`overlays[1].items[0].rect.width` では場所が伝わらない）。

**素材を1つも持たないオーバーレイは送らない**（`savableOverlayDrafts`。Workerが拒むため）。足した名前は画面が覚えておき、素材を置いた時点で保存される＝「効果をひとつも持たない行は保存しない」と同じ考え方である。

**素材を置くオーバーレイは選択欄から選ばせ、手で打つのは「オーバーレイを足す」ときだけにする**（名前はOBSに貼るURLに載るので、打ち間違いに気づくのが「配信中に何も映らなかったとき」になる）。

**保存済みの値が読めない素材（レジストリに無いデザイン・範囲外のパラメータ）でも黙って捨てない**（捨てると、開いて保存しただけでその素材が消える）。理由をその行に出し、レジストリに無いデザインは選択欄にそのまま残して（`/llm/` のモデルと同じ扱い）、パラメータは保存されていたクエリ文字列を持ち越す。

**React の key には位置ではなく採番した識別子（`ItemDraft.key`・`OverlayDraft.key`。構成には保存しない）を使う**（位置をキーにすると、並べ替え・外したときに入力欄が別の素材のものとして使い回され、入力欄が覚えている内容（透過にする前の色）が混ざる）。

## ドラッグで置く

**位置と大きさは、数値（％）で打つほかにドラッグでも決められる**（issue #105）。オーバーレイのカードの中に配信画面と同じ縦横比の「配置用の枠」（`overlay-page.tsx` の `PlacementBox`）を出し、素材を四角として描いて動かす・端と角のつまみで大きさを変える。

**書き戻す先は数値欄と同じ `ItemDraft.rect` の文字列**なので、ドラッグで置いた値がそのまま数値欄にも出る（保存の形は割合（％）のまま変えない）。画素から割合への変換と四角の計算は `src/overlay/drag.ts` に切り出してテストする（通信もDOMも持たない。`form.ts` と同じ分け方である）。

**ドラッグのあいだは「つまんだ時点の四角」から毎回計算する**（動かすたびに前の結果へ足すと、0.1％まで丸めている端数が積み上がる）。

**位置と大きさの範囲（0〜100％・1％以上）を `drag.ts` が押し込めるのは、「検証は Worker だけが持つ」（issue #86）の例外ではない。** マウスでは範囲の外を「打ち間違える」ことができず、枠の外へ運べてしまうとドラッグで置いただけの素材が保存のときに拒まれるためで、数値欄は今までどおり丸めずに送る。

**位置を数として読めない素材（数値欄を空にした直後）は四角にせず理由を添える**（つまんだ時点の四角が決まらないため）。四角をつまむとその素材の設定が開く（どの四角がどの素材かを数値欄と見比べられるようにする。ドラッグでもキーボードでも開くだけで畳まないので、二重に押しても同じ結果になる）。**枠に描くのは四角と名前だけで、素材の中身は映さない**（中身はプレビューが受け持つ）。

## プレビュー

**重なりと見た目は、オーバーレイのカードの中で開くプレビュー（`overlay-page.tsx` の `PreviewFrame`）で確かめる**（issue #106）。中身は合成ページ（`overlay/stage/?overlay=<名前>&demo=true`）をそのまま iframe に出す＝本番と同じ描画のコードで、実寸（1920×1080）で描いて枠の幅に合わせて縮小する（iframe の枠と待ち時間の仕掛けは `src/core/preview.tsx` の `Preview`・`useSettled`）。

**素材の中身はすべてサンプルにする**（`?demo=true`。チャットボックスはパラメータの `demo` を立て、アラート・サイドスーパー・注目コメントは単独ページと同じサンプル（`src/*/demo.ts`）を `startSampleCycle` で順に流す）ので、匿名IRC・アラートのWebSocket・ポーリングが配信中のものに加えてもう1組動くことがない（issue #106 で数えた代償をこれで無くす）。つながないのでオーバーレイ用キーも要らず、iframe のURLに合言葉が載らない。

**映す構成は Worker から読まず、この画面から postMessage で渡す**（`src/overlay/preview.ts`。プレビュー側が「構成を待っている」と先に知らせ、親が編集中の構成を返す）。保存してからでないと映らない作りにしないのは、**保存はその時点で配信画面（OBSに貼った合成ページ）へ反映されるため、「保存してから確かめる」では配信画面に出してから確かめることになる**からである。渡す相手は同じサイトの窓だけに限り（`origin` を照合）、構成の形の確かめは Worker の応答に使う `readOverlays` を共有する。届かなければ黙って空にせず理由を出す（Fail-Fast）。

**プレビューは見ているあいだだけ動かし、同時に開くのは1つだけにする**（畳んだら iframe ごと外す）。重なりの1枚を丸ごと動かすので何枚も動かさないためで、あわせて「構成を待っている」知らせに答える相手も1つに定まる＝何枚も開けると別のカードのプレビューへ自分の構成を渡してしまう。

**位置と大きさを数として読めない素材は渡さず、配置用の枠と同じように理由を添える**（読めない値を渡すと構成そのものが読めないものになる）。**編集が進んだら iframe ごと作り直す**（動いているものを差し替えるより確かで、打っている途中で何度も作り直さないよう `PREVIEW_DELAY_MS` だけ待つ）。**吸着（グリッド・他の素材の端に合わせる）は入れていない**（まず動かせることを先にする。別 issue である）。

## 素材を足したときの大きさ

**素材を足したときの大きさは、種類ごとの推奨の大きさ（`src/overlay/layout.ts` の `RECOMMENDED_ITEM_SIZES` を `form.ts` の `defaultRectFor` が割合へ直す）にする。**

すべてをオーバーレイいっぱい（100％×100％）で足していたころは、時計とチャットボックスが配信画面ぜんたいへ引き伸ばされた状態から毎回縮めることになり、それぞれの素材に合う大きさ（時計600×240px・チャット480×800px）とも食い違っていた。

配信画面と同じ大きさで使う素材（壁紙・アラート・サイドスーパー・注目コメント）は今までどおりいっぱいにする（素材のCSSが箱の中で寄せる場所を決めるため、余白ごと重ねる）。

**推奨の大きさは `RECOMMENDED_ITEM_SIZES` 1か所に持つ**（当初はギャラリーのプレビューの実寸も同じ値を見ていた。2か所に数を書くと、片方を直したときに食い違う）。

置き場所だけは決められないので左上（0・0）から始め、配置用の枠で動かしてもらう。割合の丸めの細かさ（0.1％）は `drag.ts` の `roundPercent` を共有する。

## オーバーレイを足す欄は、説明文ではなくURLそのものを見せる

**「オーバーレイを足す」欄では、名前がOBSに貼るURLに載ることを文章で説明せず、打っている名前の入ったURLをその場に出す。**

もとは同じ欄に「オーバーレイを足す」がカードの見出し・入力欄の見出し（「足すオーバーレイの名前」）・ボタンの3か所に出ており、そのうえで「名前はOBSに貼るURLに載るので、変えないかぎりURLは貼り替えなくてよい」と文章で説明していた。**打てばURLが目の前で変わるなら、その説明は要らない**（Krug の「説明せずに見せる」）。そこで入力欄の見出しは読み上げにだけ残し（`aria-label`）、ボタンは「足す」に縮め（読み上げには `aria-label` で「オーバーレイを足す」を渡し、見えている文字を含む名前にする）、空いた場所に下書き用のURL（`src/overlay/url.ts` の `overlayStageUrlOutline`）を出す。

**下書き用のURLではオーバーレイ用キーを `…` に置き換える**。名前を打っているあいだ画面に出したままになるので、カードのURL欄を伏せ字にしているのと同じ理由で、配信画面に映り込んでも読めないようにする。

**すでにある名前のときは、その場所に理由を出す**（前はボタンが押せなくなるだけで、理由がどこにも出なかった）。URLと理由は同じ1行を使い、打ち始めても行がずれないよう高さを確保しておく。

## オーバーレイのカードからも、繰り返しの説明を外す

同じ方針を、オーバーレイ1枚ぶんのカードにも広げた。

- **カードごとの説明文（「OBSのブラウザソース1つぶん。この中の素材は、上にあるものが前に出る…」）をやめた。** 前者はカードの下にあるURL欄（貼る先そのもの）が示しており、オーバーレイの枚数だけ同じ文章が並んでいた。後者（並びの意味）は文章の代わりに、素材が2つ以上あるときだけ一覧の上端に「前面」・下端に「背面」の目印を出す。
- **素材を足す行から、入力欄の見出し（「足す素材の種類」「足す素材のデザイン」）を画面から外し、読み上げにだけ残した**（`aria-label`）。選んだ種類とデザインは選択欄にそのまま見えており、「足す」はボタンが持つ。ボタンは「足す」に縮め、読み上げには `aria-label` で「素材を足す」を渡す。
- **プレビューの注意書きは、開いているあいだだけ出す。** 閉じているカードでは、映っていないものについての注意書きが場所を取るだけだった。文面も「中身はサンプルです（配信中のものにはつながりません）。」まで詰めた（つながらない先の一覧は `docs/guide/overlay.md` が持つ）。
- **位置と大きさの入力欄から、単位（％）の4回の繰り返しを外した。** 見出しを「オーバーレイの中での位置と大きさ（％）」にまとめ、入力欄には「左・上・幅・高さ」だけを出す。読み上げには今までどおり「左端の位置（％）」まで渡す（`RECT_FIELDS` の `short` と `label`）。
- **「URLをコピー」ボタンは「コピー」に縮めた**（読み上げには `aria-label` を残す）。見出し・伏せ字のURL欄・ボタンで「URL」が3回出ていたため。推奨の大きさの行からも「中の位置と大きさは割合で決まる」を外した（％の入力欄が示している）。

**読み上げに渡す名前は、どれも見えている文字を含むものにする**（「足す」⊂「素材を足す」、「左」⊂「左端の位置（％）」）。見えている文字と読み上げの名前が食い違うと、音声で操作する人が画面に見える言葉で呼べなくなるためである（WCAG 2.5.3）。

## 形で表せるコマンドは、アイコンだけのボタンにする

**足す（＋）・コピー（⧉）・ひとつ前面へ／背面へ・ひとつ上へ／下へ・外す（ごみ箱）は、文字を出さずアイコンだけのボタンにする。** 「足す」のような短い動詞は、日本語にすると文としても据わりが悪く、形（＋）がそのまま同じことを言っている（ノーマンの signifier）。

**名前は読み上げ（`aria-label`）とホバー（`title`）の両方へ同じものを渡す**（`src/core/icon-button.ts` の `iconButtonName`）。ページをまたいで同じ扱いにするため、この画面だけでなく**アプリのページ全体へ広げた**（URLのコピー・記録や素材の削除・視聴者の検索・注目コメントの読み直し・配色の色を足す／減らす）。置き場所を `src/core/` にしたのは、ページ（`src/*/…-page.tsx`）とパラメータの入力欄（`src/core/fields.tsx`）の両方から読むためである（ページ側へ置くと、`fields.tsx` がページへ依存することになる）。アイコンが何を指すか分からない人のために、名前そのものは残す必要があるためで、2か所に同じ文字列を書き分けないよう1か所にまとめてある。

**文字を残すのは、形では表せないものだけにする**: 「プレビューを見る／閉じる」（いまどちらの状態かを文字で言う）と「構成を保存する」（押すと配信画面へ反映される、取り返しの重い操作）。
