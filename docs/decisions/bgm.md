# BGM（`/bgm/`・裏方の `?bgm=true`）

BGMは、配信で流す曲とそのクレジット表記・クレジット先のURL・曲調・流したい場面を HDAD の中で管理し、管理画面から流す曲を切り替える仕組みである（issue #151）。クレジットを配信画面とチャットに出すのは issue #152、Jev で配信の話題に合う曲へ切り替えるのは issue #153 で足す。

## 音声は R2 に上げたものだけを使う

曲の音声は、アラートの素材と同じく管理画面から R2（MEDIA）へ上げたものだけを使う。**フリーBGMの配布元の多くは直リンクを禁じている**ので、配布元のURLをそのまま鳴らす形は採らなかった。YouTube の埋め込みも、広告と権利の扱いが配信に持ち込まれるので採らなかった。そのため曲が持つURLは音声の読み先ではなく、視聴者に紹介するための出典（クレジット先）である。クレジット先には視聴者が開くものなので `http://`・`https://` で始まるURLだけを受け取り、`javascript:` などは入れさせない。

アップロードは既存の「アップロード」のページで行い、`/bgm/` はそこで上げた音声から選ぶ。**音声1つにつき曲は1つにし、素材のIDを曲の識別子にした**。同じ音声を別のクレジットで2曲として持つ理由が無く、曲のIDを別に振るとその採番と重複の確かめが要るためである。

## 曲の一覧と「いま流す曲」を別の鍵に置く

曲の一覧（KV `bgm-tracks`）はたまにしか直さないが、流す曲と音量（KV `bgm-playback`）は配信中に何度も変える。1つの鍵にまとめると、流す曲を切り替えるたびに一覧ごと書き直すことになり、一覧を編集している最中の画面と食い違いやすいので分けた。

**流している曲は一覧から外させない**（Worker が拒み、画面でも外すボタンを押せなくする）。外せてしまうと、裏方のページが流す曲を引けずに黙って無音になる。同じ理由で、BGMの曲に使われている素材は「アップロード」のページから消させない（トリガーに使われている素材と同じ扱い）。

## 切り替えは押し出し、専用の Durable Object は足さない

読み上げの設定は30秒おきのポーリングで配っているが、BGMは配信中に「いまこの曲にしたい」と思って切り替えるものなので、数十秒遅れるのでは使いものにならない。KV を短い間隔で読む案も、KV の反映に最大60秒かかるので採れない。そこで、流す曲や音量を変えたら Worker が「いま流している曲」を Durable Object へ押し出し、裏方のページへ WebSocket で届ける形にした。

**押し出しの宛先には専用の Durable Object を足さず、アラートの配送（`AlertChannel`）を使い回した。** 新しい Durable Object を足すと、PR ブランチの Workers Builds のプレビュービルドが失敗するためである。ただし合成ページはアラートの接続で届いたものをアラートとしてしか読めないので、**接続を受け入れるときに目印（タグ `alerts`・`bgm`）を付け、アラートはアラートの接続へ、BGMはBGMの接続へだけ配る**（`getWebSockets(tag)`）。どちらの目印で受け入れるかは Worker が経路で決める（`/api/overlay/socket` はアラート、`/api/overlay/bgm/socket` はBGM）。手書きの中継（`DrawChannel`）が描ける接続と見るだけの接続を目印で分けているのと同じ作りである。`AlertChannel` はBGMの状態も持たず、配送者のままである。

裏方のページは開いたときに `GET /api/overlay/bgm` を読んで鳴らし始め、押し出しの接続をつなぎ直したときにも読み直す。つながっていない間の切り替えを取りこぼさないためである。

## 裏方のページで鳴らし、既定では鳴らさない

BGMは映すものを持たないので、合成ページの素材にはせず裏方のページ（`overlay/backstage/`）で鳴らす（位置と大きさを持たないものを素材にすると、構成の `rect` が意味を失う。`docs/decisions/backstage.md`）。**`?bgm=true` のときだけ鳴らし、既定では鳴らさない。** 既にOBSに貼ってある裏方のブラウザソースが、配信者が曲を選んだ途端に黙って鳴り出さないようにするためである。

## 同じ曲なら鳴らし直さない

裏方のページは届いた「いま流している曲」と自分が鳴らしている曲を比べ、切り替える・音量だけ変える・止める・何もしない、のどれかを選ぶ（`src/bgm/change.ts` の `bgmChangeOf`）。曲が同じかは素材のIDで見る。流している曲の情報（曲名・クレジット）を直したときも押し出すが（issue #152 でクレジットを配信画面に出すため）、それで曲が頭から流れ直すと配信の邪魔になるためである。

切り替えは次の曲を鳴らし始めてから前の曲を下げ、2秒かけてつなぐ。**次の曲を鳴らせなかったら前の曲を流したままにする**（切り替えの失敗で配信が無音になるより、前の曲が続くほうが害が小さい）。音量の変化はタイマーで刻み、刻むたびに経過時間から音量を決める。OBSのブラウザソースは画面に映っていないと描画を間引くことがあり、`requestAnimationFrame` に合わせるとフェードが止まったままになるためである。

## クレジットは素材「再生中の曲」と差し込み語 `{bgm}` で見せる（issue #152）

**配信画面には合成ページの素材「再生中の曲」（種類 `bgm`）を足した。** 壁紙や時計のようにレジストリにデザインを並べる形にはせず、サイドスーパー・注目コメントと同じくデザインもパラメータも持たない種類1つにした。見た目の選択肢が要るほど目立たせるものではなく、選ばせる項目を増やすだけになるためである。鳴らす裏方のページと映す合成ページは別のページなので、BGMを素材にしないという上の判断とは矛盾しない（素材が映すのはクレジットの文字で、位置と大きさを持つ）。

**素材は裏方のページと同じ押し出し（`/api/overlay/bgm/socket`）で切り替えを知る。** ポーリングにすると、曲を変えてから表示が変わるまでに数十秒ずれ、流れている曲と違うクレジットを映すことになるためである。`AlertChannel` は目印 `bgm` の接続すべてへ配るので、裏方と合成ページの両方がつないでも Worker 側の変更は要らない。止めているのは正常な状態なので、素材は何も映さずエラーにもしない。

**チャットには専用のコマンドを作らず、応答文の差し込み語 `{bgm}` にした。** `{summary}` と同じく、コマンド名や前後の文言を配信者が決められるようにするためである。止めているときは流していないと分かる文言に置き換える（無応答だと、壊れているのか止めているのか視聴者に区別できない）。

`{bgm}` は曲名・クレジット表記・クレジット先のURLを並べるので、Phase 1 の上限（100・200・500文字）のままでは Twitch の1通（500文字）に収まらなかった。応答文の長さの検証は保存の時点で差し込み語を最大の長さで見積もる（送る段になって弾かれないようにする）ので、**曲の項目の上限を60・100・200文字に縮め、`{bgm}` が最大364文字になるようにした**（`worker/bgm-credit.ts` の `MAX_BGM_CREDIT_LENGTH`）。送るときに切り詰める案は、クレジットの一部が黙って欠けるので採らなかった。上限を縮める前に保存した曲は読み出しでは検証し直さないので、並べた文が364文字を超えたら組み立ての時点で直し方を添えて投げ、応答の失敗（`chat-reply-failed`）として記録する。

アラートのトリガーの文言で `{bgm}` を使えるようにするのは見送った。トリガーの文言にはあらすじと同じ経路（`worker/alert-actions.ts` から `fillMessage` まで）で曲を渡す必要があり、変更が広がるためである。

## 失敗の扱い

起動のときの失敗（いま流している曲を読めない・再生を始められない）は投げて、裏方の箱に出す（Fail-Fast）。**配信中の切り替えの1回の失敗では止めず、その裏方の箱に出したうえで次の切り替えを待つ。** 1回の失敗でBGMの裏方ごと止まるとOBSの再読み込みが要るためで、読み上げが1件の失敗を飛ばすのと同じ、数えられる例外である。押し出しの失敗は Worker が握りつぶさず管理画面へ返す（保存は済んでいるので、裏方のページはつなぎ直したときに新しい曲を読む）。
