# ワイプ（素材の種類 `wipe`）

ワイプはバラエティ番組のワイプのように、チャットの発言を1件ずつ、発言した人の Twitch のアイコンを映した枠と吹き出しで出す素材である（`src/wipe/`・合成ページの `mountWipe`）。

## どの発言を出すか: チャットのすべてを順番に

注目コメント（`docs/decisions/focus.md`）は配信者が選んだ1件を出しっぱなしにするが、ワイプは**届いた発言をすべて、1件ずつ順に出す**。視聴者の発言に「その人が画面に差し込まれて話している」演出を付けるためで、選ぶ手間をかけない。

出す発言は**読み上げる発言と同じ**にした（`src/wipe/comment.ts` は `src/speech/text.ts` の `speechTextOf` を呼ぶだけ）。読み上げない人（bot）・コマンド・エモートだけの発言を「出すが読まない」にすると、吹き出しを出しておく長さを決める文が無く、判断も2か所に分かれるためである。待ちの上限も読み上げと同じ列（`src/speech/queue.ts`。型を引数にした）を使う。

## 読み上げはワイプ自身が行う

「読み上げがオンなら、読み上げているあいだだけ吹き出しを出す」を満たす作り方は2つあった。

1. **ワイプ自身が読み上げる**（採用）: 合成ページの素材が順番待ち・合成・再生を持つ
2. 裏方の読み上げ（`overlay/backstage/`）が読み始めたら、Worker を経由してワイプへ押し出す

2 は音と表示のあいだに通信ぶんのずれが出るうえ、発言ごとに Worker への要求と押し出しが増え、ミュート中も裏方が順番を刻み続けるという分かりにくい作りになる。1 なら音と表示が同じページで決まり、ずれない。合成ページはすでに音を鳴らしている（市町村紹介）ので、OBSの設定も増えない。

そのため、読み上げのうち「設定の読み直し・合成先・ミュートの受け取り」を `src/speech/voice.ts` の `startSpeechVoice` に切り出し、裏方の読み上げ（`src/speech/task.ts`）とワイプの両方から使う。どの発言をいつ読むか（ミュートしたら待ちを捨てるか、出し続けるか）は使う側が決める。

### 二重読みは黙って避けず、エラーにする

1 の代償は、裏方の読み上げとワイプが同時に動くと同じ発言が二重に読まれることである。片方を黙って止めると、配信者は「なぜ裏方が読まないのか」に気づけない（`docs/principles.md` の Fail-Fast）。そこで次の2つで防ぐ。

- 裏方の読み上げは起動のときに構成を読み、ワイプがあれば読み上げを始めずに理由と直し方（`?speech=false`）を画面に出す（`src/wipe/layout.ts` の `wipeOverlayNameOf`）。起動のあとも30秒おきに構成を読み直し、あとからワイプが置かれたら読み上げをやめて同じ理由を出す。最初は起動のときだけ確かめていたため、裏方を開いたまま `/overlay/` でワイプを置くと、実配信で二重に読まれた
- 構成全体でワイプは1つまでとし、Worker が保存のときに断る（`worker/overlay-layout.ts`）。別々のオーバーレイに置いても、ブラウザソースが2つあれば2つが読むためである

## 次の発言が無ければしばらく残す

最初は読み終えて0.8秒で引っ込めていたが、実配信ではワイプが一瞬しか映らず、誰が言ったのかを見届けられなかった。そこで次の発言が無いときは6秒（`LINGER_MS`）残し、そのあいだに届いた発言へは引っ込めずにそのまま替える。残している発言がモデレーターに消されたら、残すのをやめてすぐ引っ込める。

## ミュート中は時間で進める

ミュート中もワイプは止めず、読み上げる文の長さに応じた時間（3〜8秒。`silentDurationOf`）だけ出して次へ進む。「チャット全部を順番に出す」を、読み上げのオン・オフにかかわらず保つためである。裏方の読み上げはミュートで待ちを捨てるが、ワイプは捨てない（ミュートは音を止めるだけ）。読み上げの途中でミュートしたら、鳴っている1件だけを止め、読み終えたときと同じく少し残して次へ進む。

## アイコンは発言のたびに Worker が引く

匿名IRCではアイコンのURLが届かないので、`GET /api/overlay/wipe/icon?login=` で Worker が Twitch から引く（`worker/wipe-routes.ts`）。合成ページはログイン名ごとに覚え、同じ人では引き直さない。前の1件を読んでいるあいだに次の人のアイコンを引き始めておく。

引けなかった1件は**出さずに飛ばし、失敗を素材の箱に出す**。アイコンの欠けたワイプを映すより、気づける形にする（注目コメントが「引けなければ保存しない」としたのと同じ考え方）。一方で1件の失敗でワイプ全体は止めない（読み上げと同じ例外。`docs/principles.md` の 5）。引けなかった人は覚えず、次の発言で引き直す。

## 吹き出しは行数で打ち切る

ワイプは画面の隅に置く小さな素材なので、注目コメントのように字を小さくして500文字を収めることはしない。本文は4行で打ち切り、末尾に「…」を出す（CSSの `line-clamp`）。打ち切ったことが見た目で分かり、読み上げも長さの上限で打ち切っているので、全文はチャットボックスかコメントビューアーで読む前提にした。
