# 字幕（素材の種類 `caption`）

issue #190。アプリの枠の音声認識（issue #189。`src/transcript/recognition-context.tsx`）が認識した暫定・確定の文を、合成ページの素材「字幕」へ流す。ゆかコネNEO が出していた字幕を置き換えるためのもので、翻訳（issue #191）とゆかコネNEO の中継の撤去（issue #192）はこの後に続く。

## 配り方は手書きの Durable Object を別の名前で使う

字幕を配る仕組みとして、新しい Durable Object のクラスを足さず、**手書きの中継 `DrawChannel`（`worker/draw-channel.ts`）を、名前 `caption` の別のインスタンスとして使う**。

- 役割が手書きと同じである。送る側（アプリの枠）から見るだけの側（合成ページ）へ、中身を読まずに配る。送る側と見るだけの側を受け入れるときの目印（タグ）で分けるところも同じで、オーバーレイ用キーだけでは字幕を出せない
- インスタンスを分ければ、手書きの線と字幕は互いの接続にも負荷にも混ざらない（手書きは1本の線で毎秒20〜30通流れる）
- 同じ作りのクラスを2つ持たずに済み、Durable Object の追加（`wrangler.jsonc` のマイグレーション）も要らない。新しいクラスを足すと PR ブランチのプレビュービルド（Workers Builds）が失敗することも避けられる

採らなかった案:

- **アラートの配送（`AlertChannel`）に相乗りする**: アラートは「Workerが押し出し、DOは配るだけ」で、接続から接続へ中継する作りを持たない。話しているあいだは1秒に数通流れるので、アラートの配送がこの負荷を被る
- **新しいクラス（`CaptionChannel`）を足す**: 名前は分かりやすくなるが、中身は `DrawChannel` の写しになる。翻訳（issue #191）で字幕の中継先が中身を読む必要が出たら、そのときに分ける

翻訳（issue #191）は、確定した発話を記録する `POST /api/admin/transcripts` の応答で訳文を返し、アプリの枠がそれを字幕の中継先へ送る形にすれば、中継先は中身を読まないままでいられる。

経路は手書きと同じ置き分けで、送る側は配信者のセッションで守る `GET /api/admin/caption/socket`（`worker/caption-routes.ts`。WebSocketはGETなので `Origin` も自分で確かめる）、見るだけの側はオーバーレイ用キーで守る `GET /api/overlay/caption`（`worker/overlay-routes.ts`）である。

## 送るのは認識しているタブだけ

アプリの枠の中でも、字幕の中継先へつなぐのは Web Locks の鍵を取って認識している1つのタブだけにする。鍵を待っているタブもつなぐと、そのタブが送る「途中の文が空」の知らせが、認識しているタブの字幕を消してしまう。

話している途中の文は、認識の状態が変わるたびではなく**途中の文そのものが変わったときだけ**送る（状態はつなぎ直しの回数などでも変わる）。空になったことも送る（話し終えた・認識が途切れたことを字幕から消すため）。確定した文は、記録（`POST /api/admin/transcripts`）とは別に、届いたその場で字幕へ送る（記録の応答を待つと字幕が遅れる）。

つながっていないあいだの分は貯めずに落とす。字幕は流れていくもので、つなぎ直してから古い文が現れるほうが紛らわしい。

## 見た目の既定を決め切る

`docs/principles.md` の方針1に従い、行数・位置・消えるまでの時間を設定項目にしない。値は `src/caption/captions.ts` と `src/caption/caption.css` だけが持つ。

- **2行まで**（`CAPTION_LINES`）。確定した直前の1文と、いま話している途中の文が並ぶ。それより多いと配信の画面を隠す
- **確定した行は6秒で消す**（`FINAL_LIFETIME_MS`）。2026-10-01 の配信では1発話が平均14文字ほどで、読むのに3〜4秒かかる。次の発話が続けて確定しても前の行は上に残るので、少し長めに取る
- **途中の文は10秒書き換わらなければ消す**（`INTERIM_LIFETIME_MS`）。認識していたタブが閉じられると「途中の文が空」の知らせが届かず、話しかけの文が配信画面に残り続けるため
- **箱の下端に中央寄せ、白い太字に黒の縁取り**。板を敷くと何も話していないときにも板の分だけ画面を隠すので、文字だけにする。素材の箱は配信画面と同じ大きさを推奨にし（`src/overlay/layout.ts` の `RECOMMENDED_ITEM_SIZES`）、下端の余白はCSSで取る（サイドスーパー・再生中の曲と同じ考え方）

映す行は届いた時刻と「いまの時刻」だけから決め（`visibleCaptions`）、合成ページの描画ループが毎フレーム呼ぶ。消すためのタイマーを持たない。表示（`src/caption/view.ts`）は前と同じ行なら要素に触れない。

## 失敗の出し方

手書きと同じく、**字幕の箱には切断を出さない**。字幕の箱はふつう配信画面と同じ大きさに置くので、失敗の表示（箱全体を塗る）が配信画面全体を覆う（手書きの issue #174 と同じ問題）。箱に出すのは一度もつながらないときと、届いた1通が読めないときだけである。

送る側の失敗（つながらない・切れた）は、コネクターのページの Web Speech API の区画に出す（`RecognitionContextValue` の `captionWarning`）。認識と記録は字幕とは関係なく続ける。
