# これまでのあらすじ（`{summary}`）

配信の「これまでのあらすじ」（`{summary}`）は、配信者が喋った内容（`transcripts`）と配信中の視聴者の発言（`stream_chat_messages`）を材料に、cron（`worker/collect.ts` の `summarizeStream`）が5分おきに作り、`stream_summaries`（`migrations/0010_stream_summaries.sql`。配信の区切りごとに1行）に貯める。配信が変われば行も別になるので、前の配信のあらすじは持ち越されない。

## 前回のあらすじに積み上げる

**毎回ゼロから作り直さず、前回のあらすじに積み上げる**（`worker/stream-summary.ts` の `buildStreamSummaryPrompt`。LLMを呼ばないのでテストする）。長い配信でも1回あたりの入力が一定に保たれ、Workers AI の無料枠を食い潰さないためである。

そのため「どこまでを材料にしたか」を材料ごとに持つ（`transcripts_until`・`chat_until` と、それぞれのメッセージID）。1組にまとめて両方の最大時刻を入れると、遅れているほうのテーブルの行が次回の読み出しから漏れる。

**目印は日時だけでは足りず、メッセージIDと組で持つ**（`(spoken_at, message_id) > (?, ?)`）。記録する時刻はWorkerが受け取った時刻なので立て続けの2件が同じ時刻になることがあり、そこで件数の上限に当たると、残った同時刻の行が次からの「この日時より後」に一度も入らず永久に漏れるためである。

新しい材料が1件も無ければLLMを呼ばない（`alert-state.ts` の「要らなければ読まない」と同じ考え方である）。

## 配信者の発話が無ければ作らない

**配信者の発話（`transcripts`）が1件も無ければ、視聴者の発言があっても作らない。** ゆかコネNEO を動かし忘れた配信で、書き込みの中身（「美少女声いらないかも」）が配信で起きたこと（「美少女になっていた」）として書かれたためで、材料の出所を行ごとに書いても防げなかった。目印を進めないので、文字起こしが届いた回でそのあいだの発言もまとめて材料になる。

## モデルと文体

**あらすじの既定だけは大きいモデルにしてある**（`llm-config.ts` の `LARGE_MODELS`。ほかの3か所は `LIGHT_MODELS`。どちらも配信者が画面で変えられる）。8bでは「〜と言いました」の羅列・同じ句の繰り返しによる字数超過・視聴者の書き込みの取り違えが実際に起き、同じ材料で比べて確かめた。

文体はテレビ番組のナレーションに寄せ、材料の1行ごとに「配信者」「視聴者」を付けて渡す。文体を指定しないと出来事が並ぶだけの議事録になり、途中から来た人にはどれが今の話か分からない。

読み出しは `readTranscriptsSince`・`readSessionChatSince` で行う（人物像づくりの `readViewerMessages` が「終わった配信を人ごとに」読むのに対し、こちらは「いま進んでいる配信を時系列で」読む。同じ `stream_chat_messages` を別の切り口から読む）。材料には視聴者の名前を渡さない（個人の話として書かれるため）。

## 出し方は差し込み語

出し方は**差し込み語**で、コマンドの応答文（`worker/chat-command.ts` の `needsStreamSummary`）とアラートのトリガーの文言（`worker/alert-event.ts` の `requiresStreamSummary`）の両方で使える。どちらも `{summary}` を含む文言があるときだけ `readCurrentStreamSummary` を呼ぶ（トリガーでは、文面をLLMに作らせる動作（`aiChat`）があるときも読む。文言を持たない動作なので差し込み語では届かず、材料として渡すためである）。

トリガーでは1通知につき1回だけ読み、チャット・アナウンス・オーバーレイの文言で使い回す（オーバーレイの文言に入れればOBSの画面に出る。`src/alerts/` は差し込み後の文字列を受け取るだけで、あらすじを知らない）。トリガーの差し込み語はふつうイベント種別ごとに決まるが、`{summary}` だけは通知の中身ではなく配信の状態から決まるのでどのイベントでも使える。

差し込む値は `fillMessage` が受け取るだけで、読み出しは呼び出し側（`worker/webhook-routes.ts`）が行う（`ConditionState` と同じ作りである）。語と「無いときの文言」は `worker/stream-summary.ts` に置いて2か所で共有する。

**コマンドやトリガーのたびにLLMは呼ばない**（応答を待たせず、無料枠が視聴者の発言数しだいにならないようにするため）。あらすじが無いときは無応答にせず「まだあらすじがありません」を差し込む。LLMの失敗（枠切れを含む）では前回のあらすじを消さずに残し、`stream-summary-failed` として記録して収集そのものは止めない。

長さの上限は400文字で、`worker/bot-config.ts` が応答文の長さ（500文字）を見積もるのにも使う。
