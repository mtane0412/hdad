# 配信タイトルの候補（試験運用ののち廃止）

**2026-10-13 に機能ごと廃止した**（末尾の「廃止」を参照）。以下は段階0を作ったときの判断の記録として残す。

配信中に何を話しているか・何が映っているかは、文字起こし・画面の文字・章・あらすじとして手元にある。これを材料に配信タイトルを配信の流れに合わせて変えられないかを確かめたい（issue #268）。ただし配信者には2つの懸念があった。

- 喋った内容がそのままタイトルになり、公開にふさわしくない発信になること（個人的な雑談・怖い話・センシティブな話）
- 思わず覗きたくなるタイトルを、安定して作れるか

後者は作らせてみないと判断できない。そこで**段階0として、Twitch には何も書き込まずに候補を作って記録し、見比べられるようにする**ところまでを先に作った（`worker/stream-title.ts`・`migrations/0028_stream_title_candidates.sql`）。2〜3回の配信の記録を見て、段階1（承認制か自動か）に進むかを決める。

## 採らなかった案

- **いきなり Twitch のタイトルを書き換える**: 不適切な候補がどのくらい出るか、Jev がそれを止められるかが分からないまま公開の場に出すことになる。書き換え（`PATCH /helix/channels`）には `channel:manage:broadcast` の追加と再ログインも要るので、段階1まで入れない
- **話した内容を書かせる**: 覗きたくなる一言には近いが、個人的な雑談やセンシティブな話がそのままタイトルに出る。「何をしているか」（作業・ゲーム・企画）だけを書かせれば、雑談の中身は出ようがない
- **コメントを材料にする**: 視聴者の書き込みでタイトルを操作できてしまう。章とあらすじは視聴者の反応にも触れるので、材料であって指示ではないことはプロンプトで明示する
- **候補を切り詰めて使う**: 方針11（機械が作った文は信用しない）に反する。1行でない・上限を超える候補は捨て、失敗として残す

## 章ごとに1回、最後の章だけ

候補は章（約30分ごと）が切り替わるたびに1つ作る。章が「この30分で何をしていたか」の要約になっていて、タイトルを変える頻度としても多すぎないためである。

作る対象は**配信の最後の章で、まだ候補の無いものだけ**にした（`readStreamTitleTarget`）。候補が無いこと自体が「まだ作っていない」という印になるので、LLM や Jev が失敗したときも、収集の予算を使い切ったときも、次の収集で作り直せる（`collect-budget-exceeded` の「次の収集へ回した」が嘘にならない）。次の章ができたら前の章には戻らない。タイトルは「いま」を表すもので、過ぎた章の候補には使い道が無いためである。同じ理由で、配信が終わってからできた最後の章にも作らない。

形の合わない候補も次の収集で作り直すことになるが、作り直しは次の章ができるまで（最大で約6回）に限られる。

## 設定で入れる（既定はオフ）

判定に使う Jev は OpenRouter から呼ぶので、鍵（`OPENROUTER_API_KEY`）の無い環境では必ず失敗する。常に動かすと、フォークした人の環境で毎回の失敗と大きいモデルの呼び出しが積み上がる。そこで BGM の自動の切り替え（`docs/decisions/bgm.md`）と同じく、**配信者が入れたときだけ動かす**（`worker/stream-title-config.ts`。KVは `stream-title-settings`）。鍵が無いときに黙って飛ばすのは暗黙の縮退になるので採らなかった。

スイッチは候補を見比べるダッシュボードに置き、切り替えたらすぐ保存する（保存ボタンを持たないので、未保存の変更の確認も要らない）。配信の記録がまだ無い状態でも出すのは、配信を始める前に入れておけるようにするためである。

## 決めたこと（issue の「決めること」）

- **候補の長さは20文字まで**（`MAX_STREAM_TITLE_CANDIDATE_LENGTH`）。Twitch のタイトルは140文字までで、配信者が書いた固定部分と区切り（「｜いま：」など）に100文字以上を残すため。配信者に確かめて決めた（2026-10-06）
- **Jev への問いは Noul の1つ**（「誰でも見られる配信タイトルとして、そのまま公開してよいか」）。「はい」「いいえ」それぞれに当たる場合（個人的なこと・センシティブな話題・不穏な表現）を `criteria` に書く。材料は候補の文面だけにした（判定したいのは文面が公開の場に出てよいかで、配信の記録には左右されないため）。確率はしきい値と比べずにそのまま残す。段階1のしきい値は、記録の中で不適切な候補と適切な候補の確率がどう分かれるかを見て決める（見当は、BGM の切り替えと同じく 0.7 以上）
- **「覗きたくなる」ことは求めるが、誇張は許さない**。プロンプトで「配信でしていることから外れた大げさな言い方（釣りタイトル）にしない」と明示する。釣りタイトルは配信内容とずれ、来た人を裏切るためである

## LLMの箇所を分ける

候補づくりには新しい箇所 `streamTitle` を足した（`LLM_USAGES`）。章はあらすじと同じ `streamSummary` を指名したが、そのときの理由（箇所を足すと保存済みの `llm-settings` が読めなくなる）は、足した箇所を読み出しで補うようになって（`fillAddedUsages`。`docs/decisions/llm.md`）なくなった。分けておけば、試験運用の呼び出し回数を使用状況で別に数えられ、モデルも別に試せる。既定のモデルはあらすじと同じ70B級にした（8bでは日本語の言い回しが弱いと見込むため）。Jev の用途にも `streamTitle` を足し、BGM の判定と分けて数える。

## 判断の材料（2〜3回の配信のあとに見る）

- 不適切な候補が何件出たか、そのうち Jev の確率が低かった件数
- 実際に使いたいと思える候補の割合
- 結果は issue #268 にまとめ、段階1に進むか（承認制か自動か）を決める

## 段階0の結果（2026-10-07〜10-12・5配信）

候補は46件記録できた（「公開してよい」の確率は平均0.674、0.5以上は38件）。詳細は issue #268 のコメントにまとめた。

- 「何をしているか」を書く方針はおおむね守られ、開発の配信では具体的な候補が出た
- ゲーム実況では「証言を整理して〜」の言い換えばかりになり、覗きたくなるタイトルを安定して作れるかという懸念は当たった
- 別の文字体系が混ざった候補・途中で切れた候補が出た。20文字の検査では弾けない
- Jev の確率は中身と対応せず（無害な怪談の候補が0.2〜0.3）、しきい値ひとつで公開の可否を分けられなかった

## 廃止

段階1へは進まず、候補づくり・記録の表（`migrations/0038_drop_stream_title_candidates.sql` で消した）・ダッシュボードのスイッチ・LLM と Jev の箇所 `streamTitle`・WebMCP の設定の対象をまとめて外した。理由は配信者の判断による次の2つである。

- **サイドスーパーと役割が重なる**。雑談のように話題が移る配信では「いま何をしているか」を出す効果があるが、それは配信画面のサイドスーパー（`docs/decisions/side-super.md`）がすでに担っている
- **配信タイトルは、その配信でやることの宣言である**。いまやっていることから逆算してタイトルを細かく書き換えるのは、宣言としてのタイトルの役割を崩すので悪手と判断した

保存済みの LLM の設定（KVの `llm-settings`）に残る `streamTitle` のキーは、読み出しが `LLM_USAGES` にある箇所だけを読むので無視される（`worker/llm-config.test.ts` で確かめている）。KVの `stream-title-settings` は読む箇所がなくなった。過去の `llm_usage` の `streamTitle` の行は、`/llm/` の全体の合計にだけ含まれる。
