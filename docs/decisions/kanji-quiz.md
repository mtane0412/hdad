# 漢字クイズ（issue #293・#300・#301）

チャンネルポイントの交換で熟語の読みを問い、制限時間内に正答できなければ配信を止める「配信終了漢字クイズ」（#293）を、3段階に分けた。段階1（#300）は問題集と出題の演出、段階2（#301）はチャットでの回答の判定、段階3（#302）は時間切れでの配信の停止である。

## 問題は自前の問題集だけから出す

LLM や辞書（読みの付いた単語の一覧）からその場で問題を作る案は採らなかった。段階3で正答の判定が配信の強制終了に直結するため、読みの誤り（正しく答えたのに不正解になる・答えが一意に決まらない）を事前に人の目で潰す必要がある。そこで問題集をリポジトリに JSON で持ち、形の誤りはテストで止め、中身は配信者が確かめる。下書きを LLM に作らせることは妨げない。

## 級は問題ごとに手で付ける

漢検の級別の漢字表は、機械で読める公開データが見つからなかった。10級〜5級は学年別漢字配当表と対応するが、4級以上は協会独自の割り振りである。見つかった唯一のデータ（fosskers/kanji）は GPL3 のため取り込めない。そこで級は推定させず、問題集が問題ごとに持つ。

## 問題の級は、字の級と読みの級の高いほうにする

LLM の下書き（48問）を、漢検協会の「漢字ペディア」と協会の資料で裏取りしたところ、級の誤りが5件、読みの漏れが7件見つかった（2026-10-10）。級の誤りのうち4件（境内・仮病・素直を6級、納屋を5級）は、字そのものの級は合っていたが、読み（ケイ・ダイ・ケ・ス・ナ）が中学・高校で習うもので、漢検ではその級で出題されないものだった。「熟語の中で最も上の級の字」だけでは拾えないので、読みの出題される級も見る約束にした。誤りの問題は、同じ級の読みが1つしかない熟語に差し替えた。読みが複数ある語（一日・黄色など）は、辞書の見出しにある読みをすべて正解に入れて残した。

そのうえで、級を決めるのは先頭の読み（想定する読み）だけにした。黄色の「こうしょく」のように、ほかの読みには級より上で習うもの（黄のコウは中学）がある。それを正解から外すと、知っている人が正しく答えて不正解になり、強制終了に直結する害のほうが大きい。逆に、ほかの読みに合わせて級を上げると、想定する読み（きいろ）が級に対してやさしすぎる問題になる。そこで、2つ目以降の読みは正解として受け付けるためだけに持ち、級を決めないことにした（PR #303 のレビューで指摘を受けて明文化）。

## 級の一覧と問題集は src/ に置き、Worker からも読む

問題を選ぶのは Worker（段階2で判定もする）、級を「漢検準2級」と出すのは合成ページ、級を選ぶのは管理画面で、3か所が同じ級の一覧を要る。2か所に書き分けると食い違うので、`src/kanji-quiz/grade.ts` と `problems.json` を Worker からも読む（ポモドーロの `phase.ts` と同じ例外）。

## チャンネルポイントのトリガーにだけ置く

視聴者がポイントを払って出題させるものなので、ほかのきっかけ（レイド・キーワードなど）には置かせない。ツイスターがレイドだけに限っているのと同じ形で、保存時に拒み、照合で見つかったら投げる。

## 制限時間は熟語が出たときから数える

熟語は奥から近づいてくるあいだも読めるので、近づき終えてからではなく、出たときから数える。長さは定数（30秒）で持ち、設定にはしない（段階2で判定の締め切りにも使うため、場面の計算と同じ `scene.ts` に置く）。

## 回答の判定は市町村紹介のクイズの形をなぞる（#301）

出題と最初の正解者は D1 の `kanji_quizzes` に持ち、正解者は1つの文（RETURNING）で決める。判定を AlertChannel に持たせない（配送者であって判定者ではない）のも、照らす処理の失敗を投げずに記録して Webhook のほかの処理を続けるのも、市町村紹介のクイズ（#251）と同じ理由である。

照合は、前後の空白を除きカタカナをひらがなに直してから、問題集の読みのいずれかと完全一致にした。部分一致・ローマ字・漢字まじりは受けない。段階3で時間切れが配信の停止に直結するので、緩く受けて誤って正解にするより、問題集の読みを漏れなく持つほうで守る（読みの漏れは前の節の約束で潰す）。

Webhook がチャットの全件で D1 を読まないよう、発言が問題集のどれかの読みと一致するときだけ D1 を読む。issue には「受付中の出題があるときだけ読む」と書いたが、受付中かどうかを D1 の外（KV など）に持つと書き込みが増え、読み違いの余地もできる。問題集の読みと一致しない発言は、どの出題に対しても正解になりえないので、この絞り込みで判定は変わらない（市町村紹介が「都道府県が1つだけ書かれた発言」で絞るのと同じ考え方）。

## 出題の行は、合成ページが流しはじめたときではなく Worker が選んだときに入れる（#301）

issue では市町村紹介と同じく「合成ページが流しはじめたときに行を入れる」としていた。しかし「同じ配信で出した問題を選ばない」判定をその行で行うと、交換が続いて合成ページの待ち行列にある問題は、まだ行が無いので「出した」に数えられず、同じ配信で同じ問題が重なりうる。そこで Worker が問題を選んだら、押し出す前に行を入れ（受付期限は空のまま）、合成ページが流しはじめたら `POST /api/overlay/kanji-quiz/open` で受付期限を書く形にした（配信者に確認して決めた。2026-10-10）。合成ページからは出題の識別子だけを受け取り、熟語は受け取らない（行の無い識別子は404）。

回答を受け付けるのは、流しはじめてから級を出し終えた（熟語が出た）ときから、制限時間に遅れの余裕（2秒）を足したところまで。熟語が出る前の回答は当てずっぽうなので受けない。合成ページも、熟語が出てから制限時間のうちに届いた正解者だけを出す。

試し再生で出した問題も「同じ配信で出した問題」に数える（配信中の試し再生も OBS の画面に映るため。配信者に確認して決めた）。配信していないときは「同じ配信」が無いので外さない。選べる問題が尽きたら、黙って重複させず、合成ページの素材の箱に理由を押し出し、`kanji-quiz-push-failed` として記録する（試し再生は409で理由を返す）。行は同じ配信の判定に使うので、長い配信でも足りるよう7日残す。
