# サイドスーパー（`/side-super/`）

サイドスーパー（`/side-super/`）は配信画面の隅に出しっぱなしにするテロップで、あらすじ（`stream_summaries`）と同じ機構だが**積み上げない**。

材料はその時点の直近の発話・発言（`readRecentTranscripts`・`readRecentSessionChat`。あらすじの「続きだけを読む」に対し、こちらは「新しいほうから N 件を読んで古い順に直す」）と、配信のカテゴリ・タイトル（`LiveStream` からそのまま渡す。カテゴリはD1を引かずに済む）である。話題が移ったときに古い文言を引きずらせないため、前回の文言をLLMへ渡さない。

作るのは cron（`worker/collect.ts` の `makeSideSuper`）で、貯める先は `side_supers`（`migrations/0011_side_supers.sql`。配信の区切りごとに1行）である。**前回作ったあとに新しい材料が1件も無ければLLMを呼ばない**（判定は材料そのものの時刻と前回の `updated_at` の比較で行い、目印の列を増やさない）。

## 2行の役割は意味として分かれている

**2行の役割は意味として分かれている。** 1行目は見出し（いまの配信が何の時間かを表すコーナー名。おもに配信のカテゴリ・タイトルから決まり、話題が少し動いても変わらない）、2行目は本文（いまの話題そのもの）で、`buildSideSuperPrompt` が役割を分けて指示する。役割を分けずに「2行以内」とだけ指示していたころは、どちらの行も「いまの話題」になって上下の階層が生まれず、表示がテロップではなくただの2行の文に見えていた。

文言の検分（`worker/side-super.ts` の `generateSideSuper`）は**ちょうど `SIDE_SUPER_LINES`（2）行であること**と、行ごとに違う長さ（見出し `MAX_SIDE_SUPER_HEAD_LENGTH` は14文字、本文 `MAX_SIDE_SUPER_BODY_LENGTH` は20文字）を見て、外れていたら補わず切り詰めずに投げる（配信画面に置いた枠からはみ出させず、見出しの無い片肺のテロップも出さないため）。

行数を上限ではなく固定にしているのは、テレビのサイドスーパーが枠の形を変えず中身だけを差し替えるからで、行数が回ごとに変わると出しっぱなしのテロップではなくその都度出る通知に見える。戻り値は `SideSuperLines`（`[string, string]`）で、保存側（`line1`・`line2`）も表示側も「見出しが無いかもしれない」場合分けを持たずに済む（2行に固定する前に保存された1行だけの行は `migrations/0013_side_super_two_lines.sql` が消す）。

## 配送と表示

配送はアラートと違って**ポーリング**で、オーバーレイ（`side-super/overlay/index.html`）が `GET /api/overlay/side-super` を30秒おきに読む（5分おきの作り直しに押し出しは要らず、`AlertChannel` を「配送者」のまま保てる）。オーバーレイは素材ページの約束どおりReactもログインも持たず、オーバーレイ用キーで受け付けてもらう。通信を伴わない部分（`api.ts`・`view.ts`・`url.ts`）をテストし、起動（`stage.ts`）は分ける。

`view.ts` は見出し（`.side-super-head`）と本文（`.side-super-body`）を**ひとつの箱に入れず別々の要素として出す**（ひとつの箱にまとめるとテロップではなくWebの通知カードに見える）。本文は地を持たず、太い黒フチの袋文字にする（`side-super.css`。縁取りに `-webkit-text-stroke` を使わないのは、グラデーションを載せるために塗りを透明にする必要があり、塗りが透明だと `paint-order` を指定しても縁取りの内側まで透けるためで、代わりに `drop-shadow` を4方向にずらして重ねる）。

2行でも0行でもない行数を渡されたら投げる（Fail-Fast。黙って片方だけ映すと、片方が届かなくなっていることに配信中は気付けない）。同じ文言を読み直したときは行の要素を作り直さない（作り直すと出現のアニメーションが30秒おきに走る）。起動のときの失敗は `showError` で画面に出し、2回目以降の読み出しの失敗は画面に出さず前の文言を映したままにする（一時的な通信の失敗で配信画面を汚さない）。

## デモとアプリのページ

文言は cron が作るものなので配信していないあいだや作られる前は何も映らず、そのままでは見栄えを確かめられない。そのため `?demo=true` でWorkerに接続せずサンプルの文言（`src/side-super/demo.ts`。上限いっぱいの文字数のものを必ず1件含める）を順に流す道を用意する（アラートの `?demo=true` と同じ考え方。文字数の上限は `worker/` を読み込めないのでこちらで持ち直す）。

アプリのページ（`src/side-super/side-super-page.tsx`）はOBSに貼るURLと出す位置の選択、それにデモへのリンク（アプリの外なので `Link` ではなく普通の `<a>`）を受け持ち、URLの組み立ては `url.ts` に分ける（文字起こしと同じ作りである。オーバーレイの実ファイルを `/side-super/overlay/` に置くのは、`/side-super/` をアプリのページに使うためである）。
