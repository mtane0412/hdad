# ポモドーロ（`/pomodoro/`・素材の種類 `pomodoro`）

作業配信で「みんなで同じリズムで作業している」感覚を出すため、25分の作業と5分の休憩を繰り返すタイマーを配信画面に出し、区切りでトリガーと BGM を動かすようにした（issue #208）。休憩の区切りは、配信者が視聴者に「進捗どうでした？」と声をかけるきっかけにもなり、作業机（[task-desk.md](task-desk.md)）の `!done` を促す。

## 長さは25分・5分に決め切る

作業と休憩の長さは `src/pomodoro/phase.ts` の定数に決め切り、設定にしない（方針1「既定を決め切る」）。長い休憩（4本ごとに15分など）も持たない。周期の計算が1段増えるうえ、配信の中で4本続けることは多くなく、変えたくなったらエージェントに定数を直させればよい。

## 状態は Worker が持ち、描画は始めた時刻と現在時刻だけから決める

タイマーの状態（始めた時刻・一時停止の時刻）は配信中に変えるものなので、URL には入れず Worker に持つ（方針3）。合成ページへ渡すのは「始めた時刻・経過の起点・一時停止した時刻」だけで、区間と残り時間は毎フレーム現在時刻から計算する。残り時間を数え下げる状態を持たないので、OBS を開き直しても、押し出しを取りこぼしても、表示がずれない（描画を現在時刻だけから決める時計と同じ考え方）。区切りの時刻にも押し出さない。

一時停止は「経過の起点（`anchorAt`）を止めていた時間だけ後ろへずらす」ことで表す。始めた時刻（`startedAt`）は変えずに残し、区切りごとのトリガーの鍵の素にする。

## 区間の計算を src と Worker で共有する

区間（作業か休憩か・何本目か・残り時間）の計算は `src/pomodoro/phase.ts` だけが持ち、Worker のアラームもこれを読み込む。同じ計算を2か所に書くと、合成ページの「00:00」とトリガーの鳴る時刻が食い違うためである。Worker から `src/` を読み込むのは `src/draw/strokes.ts` に続く2例目の例外で、そのためこのファイルは DOM にも通信にも触れず、ほかのファイルを読み込まない。

## 区切りの時計は AdBreakTimer の別のインスタンスに預ける

区切りの時刻に Worker が動くには Durable Object のアラームが要る（cron の5分おきでは区切りに合わない）。新しい Durable Object のクラスを足すと PR のプレビューのビルド（Workers Builds）が必ず失敗するので、広告の終了のタイマー（`AdBreakTimer`。[ad-break.md](ad-break.md)）と同じクラスの**別のインスタンス**（名前 `pomodoro`）を使う。アラームはインスタンスごとに1つなので、広告の予約とは取り合わない。クラス名は広告のまま残した（名前を変えるには Durable Object のマイグレーションが要る）。`AdBreakTimer` は `/pomodoro/` のパスとアラームを `worker/pomodoro-timer.ts` へ振り分けるだけにし、アラームからトリガーを動かす文脈の組み立ては `worker/alarm-actions.ts` に移して広告の終了と共有した。

状態は KV ではなく、そのインスタンスの storage に持つ。KV は書いた場所と別の場所で読むと古い値が返りうるので、アラームの中で「一時停止したのに区切りが鳴る」が起きうるためである。操作もすべてこのインスタンスを通すので、操作とアラームは1つずつ順に処理される。

## 配信していないときの区切りではタイマーを止める

配信のあとに止め忘れたタイマーが動き続けると、次の配信で「37本目」として出てくるうえ、bot が配信外に休憩を告げることになる。そこで区切りを迎えた時点で配信していなければ、トリガーを動かさずにタイマーを止める（休憩の前の曲へは戻す）。一方で始めるのは配信の前でもよい（始めたときのトリガーだけ、配信していなければ動かさない）。配信の直前に始めておく使い方を断らないためである。

## 区切りはトリガーの区分「ポモドーロ」に置く

作業の開始・休憩の開始は、既存のトリガーの仕組みに乗せる（休憩の文言を管理画面で直せ、bot の書き込み・アラート・アナウンスを選べる）。区切りは視聴者の行動でも GitHub の出来事でもないので、新しい区分「ポモドーロ」にした。イベント種別はどちらも Worker が作る擬似イベントで、頭の `hdad.` で Twitch・GitHub の種別と見分ける。

区切りには相手がいないので、差し込み語に `{user}` を持たない（書かれていれば置き換えずに残し、配信者が誤りに気づけるようにする）。代わりに `{round}`（何本目か）と `{minutes}`（区間の長さ）を差し込める。

## 休憩の曲は1つ選び、休憩が明けたら戻す

休憩の曲は BGM の一覧から1つ選ばせる。BGM の「流したい場面」の自由記述に「休憩」と書いた曲を探す案もあったが、どの書き方なら当たるのかが曖昧で、当たらなかったときに配信中まで気づけないので採らなかった（方針2）。選ばなければ休憩中も曲を変えない。

休憩の曲は繰り返しで流す（繰り返しを切っていると、休憩のあいだに曲が終わって次の曲へ進むため）。休憩が明けたら休憩の前の「流す曲」と「繰り返すか」だけを戻し、休憩中に配信者が変えた音量とシャッフルは戻さない（配信者の操作を巻き戻さない）。

休憩中に Jev が曲を変えないよう、専用の印は持たせなかった。切り替えた時刻を記録すれば、Jev の切り替えを控える時間（10分）が5分の休憩を覆うためである。この関係はテスト（`worker/pomodoro-bgm.test.ts`）で固定してある。休憩中に長く一時停止すると Jev が曲を変えうるが、休憩が明ければ前の曲へ戻すので害は小さい。

## 読み上げは変えない

休憩中に読み上げを控えめにする案もあったが、読み上げの設定は押し出しではなく30秒ごとの読み直し（`src/speech/task.ts`）なので区切りに合わせにくく、この issue では扱わなかった。

## タイマーはアプリの枠が持つ（issue #237）

下部バーにも操作を置いたので、`/pomodoro/` が開いたときに読むだけの作りのままだと、バーで始めてもページが「止めています」のまま残るなど、2か所が食い違う。BGM（#236）と同じく、タイマーと押し出しの接続をアプリの枠の Provider（`src/pomodoro/timer-context.tsx`）に移し、バーとページはそこから読む形にした。

別の窓での操作や、配信していないときの区切りで Worker が止めたことを知る手段は、合成ページがすでに使っている押し出し（`/api/overlay/pomodoro/socket`。始めた・一時停止・再開・止めたときに届く）に枠からもつなぐことにした。区切りでは押し出さないが、区間と残り時間は現在時刻から計算するので要らない。定期的な読み直し（合成ページの5分おき）は持たせず、つなぎ直したときだけ読み直す（BGM と同じ。アプリは配信画面と違い、開き直せば読み直せるため）。

## 失敗の扱い

合成ページへの押し出し・BGM の切り替え・トリガーの失敗は投げずに記録する（`pomodoro-push-failed`・`pomodoro-bgm-failed`・`pomodoro-trigger-failed`）。どれも区切りを止める理由にはならず、合成ページは開き直しと5分おきの読み直しで追いつくためである（方針5）。休憩の曲が BGM の一覧から消えていたときは、黙って無音にせず曲を変えずに記録する。

テストでは本物の `AdBreakTimer` に storage とアラームの代役を渡して動かす（`worker/fake-timer-instances.ts`）。
