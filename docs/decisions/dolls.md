# 人形（`/dolls/`。視聴者が所持する人形）

配信で視聴者に「ごほうび」を渡し、集めたものとして残る仕組みが欲しかった。クイズ番組で正解者に人形を渡すように、ふつうの人形と、その3つ分の価値を持つスーパー人形の2種類を用意し、さまざまな条件で渡したり使わせたりする土台を作った（issue #418。トリガーで渡すのは #419、ゲームの正解で渡すのは #420）。参考にした番組の名前とキャラクターの名前はリポジトリに書かない。

## 2種類を1組にし、比は 1:3 に決め切る

人形は配信ごとに好きなものへ替えたいので、名前と画像を持つ「組」として登録させる。一方で、1組に何種類持たせるか・スーパー人形が何個分かは設定項目にせず、2種類・1:3 に決めた（方針1）。番組の形がそうであり、配信者が選べても意味のある違いが生まれないためである。比は今のところ画面の説明にだけ使い、Worker には持たせていない（使い道を作る段階で、使う側に置く）。

## 手持ちは組ごとに残し、増減できるのはいまの人形だけにする

「1配信に1組」を前提に、配信で使う組を「いまの人形」として1組だけ選ばせる（`doll_sets.current`。1 か NULL の UNIQUE で、2組が同時に選ばれた状態を表の側で作れなくした）。配信の前に配信者が選び直す（選び直すまで、前の配信の組がいまの人形のまま残る）。

手持ちを配信の終わりで消す案と、点数（ふつう＝1・スーパー＝3）として通算する案も比べ、**組ごとに残す**ことにした。過去の配信の人形も「集めたもの」として見えるほうが、渡す意味が大きいためである。ただし減らせるのはいまの人形だけにした。過去の組まで使い道に充てられると、組ごとに渡した意味が薄れるためである。

## 所持数ではなく増減を台帳に残す

所持数を1人1行に足し込む形（方針8の「人を貯める」）ではなく、増減を1件1行の台帳（`doll_ledger`）にした。人形は「何で増えて何で減ったか」を後から追えないと、使い道を足したときに食い違いを確かめられないためである。受け渡しは発言ほど頻繁ではないので、行が増えても無料枠に響かない。

台帳には次の約束を持たせた。

- **書くのは `changeDolls` だけにする。** 手での増減・トリガー・ゲームの正解・今後の使い道で書き方が分かれると、所持数の確かめ方が食い違うためである
- **減らすときは、所持数の確かめと書き込みを1つの文で行う。** 「数えてから書く」に分けると、並んで届いた2つの消費がどちらも確かめを通り、所持数が負になるためである。足りなければ 0 で止めずにエラーにする（方針4）
- **きっかけの ID を UNIQUE にする。** Twitch の通知は再送されるので、同じ交換・同じ正解で二重に渡さないためである（方針7）。手での増減は押すたびに別の増減なので、毎回新しい ID を振る
- **記録した時点の配信を控える。** 配信外の増減では NULL のまま持つ（方針6）
- **増減の理由は表の CHECK にしない。** 段階ごとに理由の種類が増え、SQLite の CHECK を変えるには表を作り直す必要があるためである。種類は `worker/doll.ts` の型で確かめる

視聴者の記録（`viewers`）を指す外部キーにはしなかった。チャンネルポイントの交換のように、チャットで発言していない人にもトリガーで渡すためである。視聴者の記録を消すとき（本人から求められたとき）は、台帳も一緒に消す。

## トリガーで渡す（issue #419）

- **渡す相手は通知が持つユーザーIDで決める。** 台帳の鍵は Twitch のユーザーID なので、交換・フォロー・サブスク・発言の通知からも `user_id`（発言は `chatter_user_id`）を `extract` で読むようにした（同じ通知を2か所で読み解かないため、人形のためだけの読み取りは作らなかった）
- **置けるトリガーを、相手が視聴者に決まるものに絞る。** 広告は打った人が配信者自身のことがあり、開発の出来事は GitHub の人、ポモドーロには相手がいない。これらに置けると、配信者に人形が渡ったり、渡す相手が決まらずに毎回失敗したりするため、保存のときに拒む
- **再送での二重の付与は、台帳のきっかけの ID だけで防ぐ。** ほかの動作のように `reserveChatReply` で鍵を取ってから書くと、書き込みに失敗した通知を Twitch が再送しても、鍵が残っていて渡せなくなる。台帳の `source_id` は書き込みと同じ文で確かめるので、鍵を別に取る必要がない。ID には動作の位置を混ぜ、同じ通知に当てはまった2つの行がどちらも渡せるようにした
- **いまの人形が無いときは、渡さずに失敗として記録する。** 黙って飛ばすと、渡したつもりで渡っていないことに配信が終わるまで気付けないためである（方針4）。Twitch には2xxを返す（再送されても同じ理由で渡せない）
- **どのトリガーで渡したかは、トリガーの項目（`trigger_kind`）で控える。** トリガーは設定の一覧の中の位置でしか見分けられず、位置は並べ替えで変わる。変わらないのは項目の種類（`reward`・`raid` など）なので、それを台帳の列に持たせた。理由ごとに控える項目は `DollOrigin` の判別共用体にし、手での増減に項目を書けない形にした

## ゲームの正解者に渡す（issue #420）

- **渡せなくても、ゲームの進行は止めない。** いまの人形が選ばれていない・台帳に書けないときに投げると、チャットで推理では正解で終えたあとの報酬の切り替えと交換の完了が、漢字クイズでは正解者の押し出しが止まり、正解したのに画面に出ない・解説が出ないことになる。ゲームは配信中の見せ場で取り戻せないが、人形は配信の後でも手で渡し直せるので、渡せなかったことを `doll-grant-failed` として記録して進める（[方針5](../principles.md)の例外）。黙って飛ばさず記録に残す点は、トリガーで渡すときと同じである
- **何を渡すかはゲームごとに1つ持ち、個数は1で固定する。** 正解者は1つのゲームに1人なので、個数を選ばせても意味のある違いが生まれない（方針1）。ふつうとスーパーの選択だけを残し、既定は「渡さない」にした（人形を使わない配信者の台帳に、知らないうちに記録が増えないため）
- **設定はゲームごとに KV の鍵を分ける。** 2つのゲームの設定は別々のページから保存するので、1つの値にまとめると、片方のページが読んでから書くまでのあいだにもう片方の保存を上書きしうる
- **選び直したらその場で保存する。** 置き場所の漢字クイズのカードは音の設定の保存ボタンと未保存の印を持つ。そこに人形の欄を混ぜると、人形だけを変えたのに音の未保存の印が出るなど、保存の範囲が分かりにくくなる。いまの人形の選び直しと同じ扱いにした
- **きっかけの ID はゲーム・出題の ID から作る。** チャットで推理は `chatDeduction:<ゲームのID>`、漢字クイズは `kanjiQuiz:<出題のID>` にした。どちらのゲームも正解者を1人に決める確かめ（`solveGame`・`answerKanjiQuiz` の RETURNING）を先に通るが、台帳の側でも同じゲームで2度渡さないことを確かめられるようにするためである
- **漢字クイズの試し再生では渡さない。** 試し再生は見栄えと音を確かめるためのもので、配信を止めないのと同じく、視聴者に本物の人形を渡さない

## 渡したことのある組は消させない

台帳に記録のある組を消すと、集めた記録が何の人形か分からなくなる。そこで、記録のある組は消させず、名前と画像の書き換えだけを許した（記録は組の ID を指すので、直しても所持数はそのまま残る）。組が使っている画像も、素材のページから消させない（配信中に人形の画像が出なくなるのを防ぐ）。

## 見せるのは管理画面だけから始める

手持ちを見せる場所として、チャットのコマンド（`!人形`）・渡したときの合成ページの演出・ランキングの素材も挙がったが、最初は視聴者のページ（`/viewers/`）の開いた行だけにした。使い道（消費）をまだ決めていない段階で見せ方を作ると、使い道に合わない形が先に固まるためである。

## 渡したときの演出だけは足す

ゲームの正解者とトリガーで人形を渡せるようになると、配信の画面では正解者の名前は出ても、人形をもらえたことが視聴者に伝わらなかった。そこで、渡したときの合成ページの演出（素材の種類 `dollAward`「人形の獲得」）だけを足した。演出が見せるのは「誰が・どの人形を・いくつ獲得したか」という出来事で、手持ちの数は見せない。そのため、上の「使い道が決まる前に手持ちの見せ方を固めない」という判断とは食い違わない（チャットのコマンドとランキングは引き続き持たない）。

- **ゲームの演出に1行添えるのではなく、独立した素材にした**。正解者への付与とトリガーでの付与の両方で同じ見た目を出せ、漢字クイズとチャットで推理のそれぞれに人形の表示を書き分けずに済むため
- **出すのは自動で渡したときだけ**（トリガーとゲームの正解者）。配信者が `/viewers/` から手で増減させたものは出さない。手での増減には数え間違いの訂正も含まれ、配信の画面に出すべき出来事とは限らないため
- **押し出しは `worker/doll-award.ts` の `grantDolls` に集めた**。自動で渡す2つの経路はどちらもここを通り、台帳に書けたとき（同じきっかけの再送では書かないので、演出も2度出ない）だけ押し出す。台帳に書くのは引き続き `changeDolls` だけである
- **押し出せなくても渡したことは取り消さない**。オーバーレイ用キーが無い・配送先が失敗したときは `doll-award-failed` を記録する。演出が出なくても、所持は管理画面で確かめられるため
