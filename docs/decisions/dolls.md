# 人形（`/dolls/`。視聴者が所持する人形）

配信で視聴者に「ごほうび」を渡し、集めたものとして残る仕組みが欲しかった。クイズ番組で正解者に人形を渡すように、ふつうの人形と、その3つ分の価値を持つスーパー人形の2種類を用意し、さまざまな条件で渡したり使わせたりする土台を作った（issue #418。トリガーで渡すのは #419、ゲームの正解で渡すのは #420）。参考にした番組の名前とキャラクターの名前はリポジトリに書かない。

## 2種類を1組にし、比は 1:3 に決め切る

人形は配信ごとに好きなものへ替えたいので、名前と画像を持つ「組」として登録させる。一方で、1組に何種類持たせるか・スーパー人形が何個分かは設定項目にせず、2種類・1:3 に決めた（方針1）。番組の形がそうであり、配信者が選べても意味のある違いが生まれないためである。比は今のところ画面の説明にだけ使い、Worker には持たせていない（使い道を作る段階で、使う側に置く）。

## 手持ちは組ごとに残し、増減できるのはいまの人形だけにする

「1配信に1組」を前提に、配信で使う組を「いまの人形」として1組だけ選ばせる（`doll_sets.current`。1 か NULL の UNIQUE で、2組が同時に選ばれた状態を表の側で作れなくした）。配信の前に配信者が選び直す（選び直すまで、前の配信の組がいまの人形のまま残る）。

手持ちを配信の終わりで消す案と、点数（ふつう＝1・スーパー＝3）として通算する案も比べ、**組ごとに残す**ことにした。過去の配信の人形も「集めたもの」として見えるほうが、渡す意味が大きいためである。ただし減らせるのはいまの人形だけにした。過去の組まで使い道に充てられると、組ごとに渡した意味が薄れるためである。

## 所持数ではなく増減を台帳に残す

所持数を1人1行に足し込む形（方針8の「人を貯める」）ではなく、増減を1件1行の台帳（`doll_ledger`）にした。人形は「何で増えて何で減ったか」を後から追えないと、使い道を足したときに食い違いを確かめられないためである。受け渡しは発言ほど頻繁ではないので、行が増えても無料枠に響かない。

台帳には次の約束を持たせた。

- **書くのは `changeDolls` だけにする。** 手での増減・トリガー・ゲームの正解・今後の使い道で書き方が分かれると、所持数の確かめ方が食い違うためである
- **減らすときは、所持数の確かめと書き込みを1つの文で行う。** 「数えてから書く」に分けると、並んで届いた2つの消費がどちらも確かめを通り、所持数が負になるためである。足りなければ 0 で止めずにエラーにする（方針4）
- **きっかけの ID を UNIQUE にする。** Twitch の通知は再送されるので、同じ交換・同じ正解で二重に渡さないためである（方針7）。手での増減は押すたびに別の増減なので、毎回新しい ID を振る
- **記録した時点の配信を控える。** 配信外の増減では NULL のまま持つ（方針6）
- **増減の理由は表の CHECK にしない。** 段階ごとに理由の種類が増え、SQLite の CHECK を変えるには表を作り直す必要があるためである。種類は `worker/doll.ts` の型で確かめる

視聴者の記録（`viewers`）を指す外部キーにはしなかった。チャンネルポイントの交換のように、チャットで発言していない人にもトリガーで渡すためである。視聴者の記録を消すとき（本人から求められたとき）は、台帳も一緒に消す。

## 渡したことのある組は消させない

台帳に記録のある組を消すと、集めた記録が何の人形か分からなくなる。そこで、記録のある組は消させず、名前と画像の書き換えだけを許した（記録は組の ID を指すので、直しても所持数はそのまま残る）。組が使っている画像も、素材のページから消させない（配信中に人形の画像が出なくなるのを防ぐ）。

## 見せるのは管理画面だけから始める

手持ちを見せる場所として、チャットのコマンド（`!人形`）・渡したときの合成ページの演出・ランキングの素材も挙がったが、最初は視聴者のページ（`/viewers/`）の開いた行だけにした。使い道（消費）をまだ決めていない段階で見せ方を作ると、使い道に合わない形が先に固まるためである。
