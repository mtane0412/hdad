# 合成ページの文字の縁取り

配信の背景はゲーム・ブラウザ・カメラなど明るさも柄もまちまちなので、映像の上に直に置く文字は縁取りで読ませる。縁取りの作り方と太さは素材ごとにばらばらだった（2026-10-19 に全素材を洗い出した結果）。

| 素材 | それまでの縁取り | 起きていたこと |
|---|---|---|
| 字幕 | 8方向の影（3px・2px） | 太さが px で決まっていて、文字の大きさに追従しない |
| チャットの plain | 8方向の影（0.07em） | 返信元に縁が掛かっていなかった（名前・本文の外の要素のため）。ビッツは共通のCSSのぼかしで縁を上書きしていた |
| チャットの bubble・sticker | なし | 返信元だけがふきだし・シールの外に、暗い文字のまま直置きされ、暗い映像の上で消えていた |
| アラート | `-webkit-text-stroke` 0.22em ＋ `paint-order` | 線の角が尖り、「驚」「M」の角から縁が飛び出していた |
| 漢字クイズ | `strokeText`（見える幅 0.03em・黒60%） | 縁が細く半透明で、明るい映像の上で熟語の輪郭が途切れていた。カウントダウンは角が尖っていた |
| ツイスター・ペロペロ | `strokeText`（8px 固定・黒85%） | 大きな文字ほど縁が細くなる。ツイスターの紫の名札は黒い縁のため、暗い映像の上で文字ごと沈んでいた |
| デジタル時計 | `strokeText`（見える幅 0.04em） | 細い |

## DOM は16方向の text-shadow にした

背景を白・黒・灰・原色の縞・空色のグラデーションにして、作り方ごとに並べて比べた（`Zen Kaku Gothic New` の 900 で、44px と 110px）。

- **`-webkit-text-stroke` ＋ `paint-order: stroke fill`**: 縁は滑らかだが、線の角の形（`stroke-linejoin`）を HTML の文字では変えられず miter のままになる。0.16em を超えると鋭い角から縁が尖って飛び出す。塗りが透明の文字（サイドスーパー）にも使えない
- **8方向の text-shadow**: 0.1em まで太くすると、斜めの縁が階段状に欠ける
- **SVG の `feMorphology`（dilate）**: 四角く膨らむので角が角張る。フィルタを読み込む仕掛けも要る
- **16方向の text-shadow**: 角が丸く、尖らない。110px で 0.1em でもわずかに段が見える程度で、配信で使う 20〜100px では目立たない → これを採った

太さは em で決め、文字の大きさに追従させる。既定は 0.08em（44px で約3.5px。それまでの字幕の 3px と plain の 0.07em に近い）。アラートは目立たせたいので 0.11em（それまでの見える幅と同じ）にした。最後に真下への薄いぼかしを1つ足し、白っぽい映像の上でも文字が浮いて見えるようにした。

`--text-outline` はすべての要素に宣言している。`:root` で1度だけ組み立てると、中の `var(--outline-color)` が `:root` の値で固まり、素材ごとに変えた色が効かないため。

text-shadow の重ね掛けは古い Chromium でも動く。`paint-order` を HTML の文字に効かせる対応は Chromium 123 からと言われており、OBS のブラウザソースの版（OBS 31 で Chromium 127 とされる）によっては効かないおそれもあった。

## canvas は角を丸めた strokeText にした

canvas は `lineJoin = 'round'` を指定できるので、尖りの問題が無い。縁を描いてから塗り、線の内側の半分を文字で隠す。見える幅は DOM と同じ 0.08（線の太さはその2倍）に揃えた。縁は不透明にした（半透明の縁は、白い映像の上では薄い灰色になって縁の役をしない）。

## 縁の色は塗りと明暗を逆にする

黒い縁は明るい映像の上で効き、暗い映像の上では塗りの明るさが読ませる。暗い塗りに黒い縁を付けると、暗い映像の上ではどちらも効かない。そのため、ツイスターの紫（0番）の名札と番は白い縁にし、bubble・sticker の返信元はふきだし・シールの色（文字色と明暗が逆になるよう配信者が選んでいる）で縁取る。

## 書体は使っている太さまで読み込む

合成ページは Zen Kaku Gothic New を 700・900 しか読み込んでいなかったが、作業ログ・作業机は 400 を使っていた。同じく Zen Maru Gothic の 900（sticker の名前）、Noto Sans JP（チャットの card）、M PLUS 1 Code（チャットの terminal）は読み込んでいなかった。読み込んでいない太さはブラウザが近い太さで代用し、無い書体は配信PCの書体に置き換わる。これらを `overlay/stage/index.html` の読み込みに足した。Google Fonts は日本語を文字の範囲ごとに分けて配るので、使う字の分しか取りに行かない。

## 残したこと

- canvas の素材（漢字クイズ・市町村紹介・ツイスター・ペロペロ）の書体は `Hiragino Sans` が先頭で、DOM の素材（`Zen Kaku Gothic New`）と揃っていない。Windows の OBS では配信PCの書体に置き換わる。canvas から Web フォントを使うと読み込みが済むまで代わりの書体で描かれ、一度だけ描くテクスチャ（顔の頭文字）は代わりの書体のまま残るので、読み込みを待つ仕掛けと合わせて別に扱う
- サイドスーパーの本文は `drop-shadow` を上下左右に重ねて縁取ったままにした（重ねると四角く膨らみ、斜めにも縁が付く）
