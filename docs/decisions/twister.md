# ツイスター

レイドを受けたときに、レイドした人と配信者が3Dの人形でツイスターゲームをするネタ機能（issue #272）。人形の顔に2人の Twitch のアイコンを貼り、2〜3回スピナーを回して絡み合わせてから倒れ込ませ、勝敗を出す。

## 物理は再生のたびに計算せず、始めに計算して記録を再生する

倒れ込みは物理のラグドールで作る。物理はフレームごとに状態を持つので、「描画は経過時間だけから決まる形にする（フレーム間の状態を持たない）」という約束（`.claude/CLAUDE.md`）とぶつかる。案は2つあった。

- 案A: 演出を始めるときに、乱数の種を固定して物理を最後まで計算し、各時刻の姿勢を記録する。描画は記録を経過時間で引くだけにする
- 案B: 倒れ込みも物理を使わず、手作りのキーフレームで動かす

案Bは軽くて確実だが、毎回同じような倒れ方になる。配信者が案Aを選んだ。案Aなら約束を守ったまま、倒れ方は種ごとに変わり、勝敗も描画の前に決まる。記録は60fps ぶんで、合成ページが呼び出しを受けてから流しはじめる前に計算する（1回の対戦で十数ミリ秒）。

倒れ込むまで（手足を運んでいるあいだ）は物理を使わない。その時刻の手足の位置から IK で姿勢を解き、2人の体のめり込みだけを押し出す（重力も速度も持たない計算）。どちらも経過時間だけから決まる。倒れ込みの計算は、この求め方で出した倒れはじめの姿勢から始めるので、切り替わりで姿勢が飛ばない。

## 対戦は合成ページが計算し、Worker は種だけを押し出す

対戦の中身（指示・倒れ方・勝敗）は種だけから決まるので、Worker は種と2人の名前・アイコンだけを押し出す。Worker で計算しないのは、倒れ込みの物理（1回で十数ミリ秒）が Workers Free の CPU の上限（10ms）に収まらないためである（市町村紹介でも同じ上限に当たっている。[市町村紹介](./town-tour.md)の「CPU 時間」の節）。

## 物理ライブラリを使わず、関節を粒にした Verlet 積分を自前で持つ

cannon-es や Rapier は剛体と拘束でラグドールを組むが、カプセルの形を持たない・依存が増える・同じ入力から同じ結果になることをライブラリの中身に頼ることになる。人形は関節の位置だけで表せば足りるので、関節を粒、骨を長さの決まった棒にした Verlet 積分を `src/twister/physics.ts` に持った。胴の形は対角の長さも保って崩れないようにする。肘・膝の曲がる向きは縛らないので、倒れ込むと関節が逆に曲がることがあるが、人形の動きとして許す。

## 指示は純粋な乱数にせず、絡みやすい組み合わせを選ぶ

本物のツイスターではスピナーが手足と色を決め、どの円に置くかを人が選ぶ。純粋な乱数で手足と色を決めると、2人がそれぞれ自分の側で手足を動かすだけになり、「くんずほぐれつ」にならない。そこで手足・色・円の組み合わせをまとめて選び、スピナーはその手足と色に止まる演出にした。絡ませる指示は、空いていて届く円のうち相手の胴に近い円を優先する。最後の指示は届かない円を指し、伸ばした手足の向きへ倒れ込ませる。

## 倒れ込むまでは、手足の先のほかの部位を浮かせておく

60通りの種で試すと、倒れはじめてから数十ミリ秒で決着する種が多く、倒れる人でない側が負ける種も半分あった。絡み合った2人のめり込みを押し出すときに、相手の体にひじ・ひざがマットすれすれまで押し下げられ、倒れる前から着きかけていたためである。

体を支えているあいだは、手足の先のほかの部位をマットから少し（`STANDING_CLEARANCE`）浮かせるようにした。倒れる人の相手も、ぶつかられて手足を離すまでは浮かせたままにする。これで倒れる人が負けるのは60回中47回になった。絡み合った下側の部位が倒れはじめの直後に押しつぶされて着く種はまだ残るが、見た目は「相手につぶされた」決着なので許す（結果は倒れ込みを映し終えてから出すので、着いた瞬間の早さは見た目に響かない）。

## 倒れ込みはスローモーションで見せる

物理の時間のままだと、倒れきるまで1秒足らずで、配信の画面では何が起きたか追えない。記録を 0.4 倍の速さで再生する。対戦の長さは種によって25〜29秒になる。

## アイコンは Worker を経由せずに読む

Twitch の画像配信元（`static-cdn.jtvnw.net`）は `Access-Control-Allow-Origin: *` を返すので、合成ページが `crossOrigin` を付けて読めば WebGL のテクスチャにできる（読み込んだ画像の画素を読めることを実機で確かめた）。Worker に画像を取り次ぐ経路は作らない。

## ツイスターはレイドのトリガーにだけ置く

相手のアイコンを顔に貼って対戦するので、相手が配信者でなければならない。シャウトアウトと同じく、レイドの行にだけ置ける（[トリガーの動作](./alerts-actions.md)）。

## BGM は1曲だけ選ばせ、配信の BGM は市町村紹介と同じ仕組みで下げる

対戦のあいだ流す BGM は、市町村紹介の音（`worker/town-tour-sound.ts`）と同じく配信者がアップロードした音声から選ぶ（公開しているリポジトリに音声を入れられないため）。市町村紹介のように場面ごとの効果音の枠は持たず、BGM 1曲と音量だけにした（求められたのが BGM だけで、場面の切れ目を増やすと設定が重くなるため）。設定は KV の `twister-sound` に1つだけ持ち、レイドと試し再生が共有する。

Worker は呼び出しに音声の URL（オーバーレイ用キーつき）と音量を添えて押し出し、合成ページが流しはじめたときに鳴らして、対戦の終わりの2秒（`src/twister/bgm.ts` の `BGM_FADE_OUT_MS`）で下げて止める。止める時刻はタイマーで数える（OBS のブラウザソースは映っていないと描画を間引くため）。配信の BGM は、市町村紹介と同じく合成ページが「対戦の長さぶん下げておく」と Worker 経由で裏方へ知らせ、裏方が自分で戻す。対戦の長さは流しはじめた時点で決まっているので、市町村紹介と違って送り直さない。

BGM を選んでいるのにオーバーレイ用キーが未発行なら、黙って無音で流さずに押し出しの失敗として記録する（試し再生は409）。プレビューはキーを持たないので BGM を流さない。
