# ツイスター

レイドを受けたときに、レイドした人と配信者が3Dの人形でツイスターゲームをするネタ機能（issue #272）。人形の顔に2人の Twitch のアイコンを貼り、5〜7回スピナーを回して絡み合わせてから倒れ込ませ、勝敗を出す。

## 物理は再生のたびに計算せず、始めに計算して記録を再生する

倒れ込みは物理のラグドールで作る。物理はフレームごとに状態を持つので、「描画は経過時間だけから決まる形にする（フレーム間の状態を持たない）」という約束（`.claude/CLAUDE.md`）とぶつかる。案は2つあった。

- 案A: 演出を始めるときに、乱数の種を固定して物理を最後まで計算し、各時刻の姿勢を記録する。描画は記録を経過時間で引くだけにする
- 案B: 倒れ込みも物理を使わず、手作りのキーフレームで動かす

案Bは軽くて確実だが、毎回同じような倒れ方になる。配信者が案Aを選んだ。案Aなら約束を守ったまま、倒れ方は種ごとに変わり、勝敗も描画の前に決まる。記録は60fps ぶんで、合成ページが呼び出しを受けてから流しはじめる前に計算する（1回の対戦で十数ミリ秒）。

倒れ込むまで（手足を運んでいるあいだ）は重力も速度も使わない。その時刻の手足の位置から IK で姿勢を解き、2人の体のめり込みだけを押し出す。はじめは毎コマその場で計算していたが、#321 で倒れ込みと同じく記録して再生する形に変えた（「胴を上下に重ね、倒れるまでも記録する」の節）。倒れ込みの計算は、記録の最後の姿勢から始めるので、切り替わりで姿勢が飛ばない。

## 対戦は合成ページが計算し、Worker は種だけを押し出す

対戦の中身（指示・倒れ方・勝敗）は種だけから決まるので、Worker は種と2人の名前・アイコンだけを押し出す。Worker で計算しないのは、倒れ込みの物理（1回で十数ミリ秒）が Workers Free の CPU の上限（10ms）に収まらないためである（市町村紹介でも同じ上限に当たっている。[市町村紹介](./town-tour.md)の「CPU 時間」の節）。

## 物理ライブラリを使わず、関節を粒にした Verlet 積分を自前で持つ

cannon-es や Rapier は剛体と拘束でラグドールを組むが、カプセルの形を持たない・依存が増える・同じ入力から同じ結果になることをライブラリの中身に頼ることになる。人形は関節の位置だけで表せば足りるので、関節を粒、骨を長さの決まった棒にした Verlet 積分を `src/twister/physics.ts` に持った。胴の形は対角の長さも保って崩れないようにする。肘・膝の曲がる向きは縛らないので、倒れ込むと関節が逆に曲がることがあるが、人形の動きとして許す。

## 指示は純粋な乱数にせず、絡みやすい組み合わせを選ぶ

本物のツイスターではスピナーが手足と色を決め、どの円に置くかを人が選ぶ。純粋な乱数で手足と色を決めると、2人がそれぞれ自分の側で手足を動かすだけになり、「くんずほぐれつ」にならない。そこで手足・色・円の組み合わせをまとめて選び、スピナーはその手足と色に止まる演出にした。絡ませる指示は、空いていて届く円のうち相手の胴に近い円を優先する。最後の指示は届かない円を指し、伸ばした手足の向きへ倒れ込ませる。

## 倒れ込むまでは、手足の先のほかの部位を浮かせておく

60通りの種で試すと、倒れはじめてから数十ミリ秒で決着する種が多く、倒れる人でない側が負ける種も半分あった。絡み合った2人のめり込みを押し出すときに、相手の体にひじ・ひざがマットすれすれまで押し下げられ、倒れる前から着きかけていたためである。

体を支えているあいだは、手足の先のほかの部位をマットから少し（`STANDING_CLEARANCE`）浮かせるようにした。倒れる人の相手も、ぶつかられて手足を離すまでは浮かせたままにする。これで倒れる人が負けるのは60回中47回になった。絡み合った下側の部位が倒れはじめの直後に押しつぶされて着く種はまだ残るが、見た目は「相手につぶされた」決着なので許す（結果は倒れ込みを映し終えてから出すので、着いた瞬間の早さは見た目に響かない）。

## 倒れ込みはスローモーションで見せる

物理の時間のままだと、倒れきるまで1秒足らずで、配信の画面では何が起きたか追えない。記録を 0.4 倍の速さで再生する。

## 手数を増やし、後半の手番を速くする（#319）

はじめは絡ませる指示を2〜3回にしていた。種0〜9で試算すると、最初の2手は相手の胴から70〜88cm離れた円に置かれ、2人の体がほとんど触れ合わないまま倒れ込みに入っていた。相手の胴に0〜20cmまで近づくのは4手目以降だった。配信者から「もっとくんずほぐれつにしたい」と求められ（#318）、手数を5〜7回に増やした。8手まで続けても置ける候補は11以上残るので、指示の選び方は変えていない。

1手は約4秒（スピナー2.6秒＋運ぶ1.4秒）かかるので、そのまま増やすと対戦が40秒を超える。はじめの2手はスピナーと指示の読み方をつかめるようにゆっくり見せ、3手目からと最後の指示は針を1秒で止めて1手を2.6秒にした（`src/twister/game.ts` の `paceOf`）。対戦の長さは種によって31〜37秒になる。

手数を増やすと、倒れ込ませた人が負ける割合は60回中47回から55回に上がった。絡み合ってから倒れるので、倒れる人が先に相手の上へ崩れる種が増えたためと見ている。

体のひねり・相手をまたぐ・ブリッジといった姿勢の自由度は、#320〜#322 で段階的に広げる。

## 体をひねらせ、手足の交差を狙う（#320）

手数を増やしても（#319）、姿勢は「うつ伏せの四つんばいで、肩と脚の付け根が水平にまっすぐ並ぶ」1種類だった。指示の候補も「両手の中点が両足の中点より30cm前」に縛っていたので、体が横を向くことも無かった。

- 姿勢（`src/twister/pose.ts`）: 肩の線を両手の前後の差に合わせて水平に回し、左右の手が届く高さの差で傾ける。脚の付け根も両足で同じようにする。回す・傾ける角度はどちらも30°で止める（それより大きいと胴がねじ切れて見える）。超える分は高さを低いほうに合わせて届かせる
- 指示（`src/twister/plan.ts`）: 「30cm前」の縛りを「体の向きが始めの向きから80°以内」に替えた。両手が両足の後ろへ回り込む（体が裏返る）置き場所は引き続き除く。裏返る姿勢はブリッジ（#322）で扱う
- 指示の点数に、手足が上から見て交差する数の増え方を加えた（1つにつき相手の胴へ30cm近づくのと同じだけ）。手足は付け根から先までの線分とみなし、肘・膝の曲がりは見ない。高さの違う手足どうしでも、上から見て重なれば絡んで見えるので数える

60通りの種で、倒れる直前に2人の手足が交差している対戦は30回から57回に、交差の数は合計32から230に増えた。同じ人の手足どうしの交差も12から55に増えた。倒れ込ませた人が負けるのは60回中52回で、1回の対戦を作る時間は平均71ミリ秒だった。

## 胴を上下に重ね、倒れるまでも記録する（#321）

手足の交差を狙うようにした（#320）あと、60通りの対戦のうち57回で、2人の胴が上から見て重なっていた。ところが2人とも同じ高さに胴を置いていたので、胴どうしが突き抜けていた（倒れるまでの場面の約2割で、胴が5cm以上めり込んでいた）。

- 胴が上から見て近づいたら、片方を伏せさせる（`src/twister/pose.ts` の `solvePose` の `crouch`）。手足の先は円に届いたまま、肩と脚の付け根を伏せた高さまで下げる。伏せる度合いは胴の近さで連続して変え、姿勢が飛ばないようにした。もう片方の胴を持ち上げる案は採らなかった。IK はすでに手足が届くいちばん高い位置に胴を置いているので、それより上げると手足が円から浮く
- 下になるのは、最初に胴が重なった指示で手足を動かした人の相手（上に乗り込まれた人）で、その対戦のあいだ入れ替えない。重なるたびに決め直すと、上下が入れ替わる瞬間に姿勢が飛ぶ
- issue に書いた「重なりを狙う加点」は入れなかった。手足の交差の加点だけで、すでに60回中57回重なっていたため

1コマずつ関節の動きを調べるテストを足したところ、#320 の時点で姿勢がよく飛んでいたことが分かった（30対戦の倒れるまでで、1コマ5cm（秒速3m）を超える動きが4854件、最大40.8cm）。原因は2つあった。

- 肩の線を回す角度が、両手が交差する前後で+30°から−30°へ裏返っていた。左右の幅を向きでなく大きさで見るように直した（`twistYaw`）
- 毎コマ IK の姿勢からめり込みを押し出し直していた。IK は相手の体を見ないので、手足が相手の体を深く突き抜けた姿勢を出す。そこから「いちばん近い向き」へ押すと、関節が相手の骨の中心線を越えるたびに押す向きが裏返り、前のコマと反対側に押し出される

2つ目は、押し出しを前のコマの結果から続けて解く形（`src/twister/physics.ts` の `relaxFollowing`）にして直した。前のコマから続ければ、めり込みが浅いうちに同じ側へ押し出され続ける。ただしフレーム間の状態を持つことになるので、倒れ込みと同じく対戦を作るときに1コマずつ記録し、再生は記録を引くだけにした（`src/twister/game.ts` の `bakeStanding`）。あわせて次の扱いにした。

- 関節は前のコマの位置から目標（IK の姿勢）へ、1コマ4cmまで追いかける。手が肩のすぐ近くを通ると、IK の肘が1コマで46cm振れることがあり、それをそのまま写さないため
- 運んでいる途中の手足は円に留めない。弧の上に留めると相手の体を突き抜けて押しのけるため。運び終えた手足は、前のコマの位置から円へ1コマ4cmずつ寄せた位置に留める。相手の体に押し返されて遅れても、いきなり円へ戻して飛ばさないため。そのため手足は、運び終えた時刻ではなく、次の指示のスピナーの針が止まるまでに円に乗る
- 胴どうしだけ上下に押し分ける案も試した。だが横から触れた瞬間に一気に持ち上げて飛ぶので、採らなかった

これで、1コマ5cmを超える動きは160件（最大15.6cm）に減り、胴が5cm以上めり込む場面は1515場面中1つになった。倒れ込ませた人が負けるのは60回中57回。代わりに、1回の対戦を作る時間が平均44ミリ秒から約400ミリ秒に延びた。合成ページは呼び出しを受けてから流しはじめるまでに対戦を作るので、そのあいだ画面の描画が止まりうる。削減は #325 で扱う。残る速い動きは、手足が相手の体に押されて回り込むときに出る。相手の体を避ける経路を選ぶ案とあわせて、同じ issue に残した。

## 手を背中の向こうへ回して仰向けに裏返る（#322）

段階4として、手の指示で体を仰向けのブリッジ（カニ歩き）に裏返す指示を加えた（`src/twister/plan.ts` の `Move.flip`）。設計は Codex に相談し、回し方と候補の安全条件の指摘を取り込んだ。

- **裏返り方**: 体を背骨のまわりに半回転させる（`src/twister/pose.ts` の `solvePose` の `supine`）。手足の先の位置は変えずに回すので、仰向けでは人形の左右が入れ替わり、置いたままの手足は反対側の付け根から伸びる。体の向きを逆にする案は、肩と腰の位置まで入れ替わって手足が届かなくなるので採らなかった。裏返る指示で足も組み替える案は、「指された1本を動かす」という流れと置き場所の持ち方を広げることになるので採らなかった
- **回す途中**: 肩と腰の線は、うつ伏せの向きを前向きの軸のまわりに同じ角度だけ回す。うつ伏せと仰向けの向きを直線で混ぜる案は、向きが途中で消えて肩幅が縮む。回すと低いほうの肩・腰が下がるので、回した分だけ胴を持ち上げる。肘・膝は、曲げる向きの前後を角度の余弦で入れ替え、途中は横と上へ逃がす。前後をそのまま混ぜると、途中で曲げる向きが無くなって肘が1段で14cm振れた
- **候補の条件**: 仰向けでは、腕が胴の下をくぐる置き場所と、左右の脚がめり込む置き場所を候補にしない（`isSelfClear`）。物理は自分の体どうしのぶつかりを持たないため、置き場所で避ける。上から見て脚が交差するのは「足を組んだブリッジ」として許す。半分まで回したときにほかの3本が円から2cm以上離れる置き場所と、回す前後で相手の胴が近い（下で回ることになる）置き場所も除く
- **頻度**: 裏返る指示の候補に0.8（m 相当）を加点し、1人1回までにした。100対戦で46対戦に出た。裏返った人は戻さない（戻す指示を足すと、左右が入れ替わる場面がもう一度増える）
- **負けの判定**: 腰・脚の付け根は今も `LOSING_JOINTS` に入っているので、仰向けのための判定は足していない。仰向けで倒れ込んでも決着がつくことをテストで確かめている

あわせて、最後の指示で足を伸ばす途中に両足の中点が両手の中点を越え、体の向き（足から手へ）が一瞬で裏返って姿勢が1コマ20cm飛ぶ対戦が見つかった。最後の指示も、伸ばしきったところで体の向きが保たれる円だけを候補にした（ほかの指示は運び終えた置き場所で同じ条件を見ているので、運ぶ途中も回りすぎない）。30対戦で、1コマ5cmを超える動きは161件、いちばん大きな動きは17.0cm（裏返りのない対戦で、相手の体に押されて肘が回り込む場面。#325 で扱う）になった。

## 対戦を作る時間を縮める（#325）

#321 で倒れはじめるまでを1コマずつ記録するようにしてから、1回の対戦を作る時間が約300〜400ミリ秒に延びていた。合成ページは呼び出しを受けると画面側で同期的に `createGame` を呼ぶので、そのあいだほかの素材の描画が止まりうる。計測すると、時間の大半は押し出し（`src/twister/physics.ts` の `separatePlayers`・`satisfySpans`）だった。対戦の中身を変えない順に、次の3つを入れた（種0〜29の平均で、開発機で約300ミリ秒から約60ミリ秒）。

- **落ち着いたら記録を使い回す**（`src/twister/game.ts` の `bakeStanding`）: 前のコマの姿勢から押し出しても1ビットも動かず、目標の姿勢と運んでいる手足が前のコマとまったく同じあいだは、押し出しを省いて前のコマの記録を使い回す。`relaxFollowing` は同じ入力から必ず同じ結果を返すので、記録は変わらない。登場とスピナーを回すあいだが該当し、記録するコマの約半分を省ける。「動きが小さくなったら」のように誤差を許して打ち切る案は、記録が変わり、どこまで許すかの決め事が増えるので採らなかった
- **触れていない組を測らない**（`separatePlayers`）: 骨の両端を囲む箱を半径の和だけ広げても粒が外にある組は、めり込みを測らずに除く。箱の外なら必ずめり込みは無いので、結果は変わらない。あわせて、相手の骨だけをたどるよう、人ごとの骨の並びを1度だけ作るようにした
- **長さを Math.sqrt で測る**（`norm3`）: `Math.hypot` は桁あふれを避ける手間のぶん遅い。ここだけは記録が最後の桁で変わる（30対戦で関節の位置の差は最大 2×10⁻¹¹ m）が、勝敗・決着の部位・対戦の長さ・1コマ5cmを超える動きの数はどの種でも変わらなかった

採らなかった案は次のとおり。

- **押し出しの反復の回数を減らす**: 12回を8回・4回にして同じ30対戦で比べた。時間は縮むが、相手の骨に2cmを超えてめり込む関節（コマと関節と骨の組）が120件から8回で1669件、4回で6790件に増え、めり込みの最大も3.4cmから4.7cm・7.3cmに深くなった（倒れ込ませた人が負ける数も29から28に減った）。品質が落ちるので12回のままにした
- **Web Worker へ移す**: 上の3つで1回が平均約60ミリ秒（最大約90ミリ秒）になり、呼び出しを受けてから流しはじめるまでに数コマ止まる程度に収まった。Worker へ移すと、合成ページのビルドの入力・素材の起動・対戦の受け渡し（記録を構造化複製で渡す）を新たに持つことになり、それに見合う差が無いので見送った。OBS のブラウザソースで止まりが目立つようなら改めて検討する

## 手足が相手の体を避ける経路を選ぶ（#325）

運ぶ手足はいまの弧（持ち上げる高さだけが決まった弧）の上を追いかけ、相手の体に当たると押し返される。そのとき関節が速く動き、運び終えるのも遅れていた。いまの弧に「少し高く・低く運ぶ」「左右へ少し回る」形を加えた9つの候補（`src/twister/path.ts` の `PATH_SHAPES`）を用意し、指示ごとに1本選ぶようにした。

- **選び方は、実際に押し出して記録してから比べる**（`src/twister/game.ts` の `bakeStanding`）: はじめは、経路の上の点ごとに2人の IK の姿勢を解き、骨どうしの突き抜けの深さ・届かないずれ・経路の長さ（速さ）で選んだ。だが種0〜29で、1コマ5cmを超える動きは162件から150〜240件と良くならず、運び終えるのが遅れる指示も12から17〜22に増えた。IK の姿勢は、前のコマから押し出し続けた実際の姿勢（相手が押しのけられている・ほかの手足も遅れている）と離れていて、突き抜けを当てられなかった。たとえば伏せた人が相手の体の下で手を運ぶとき、IK では高く運ぶ経路が空いて見えるが、実際は持ち上げた腕が相手の脚に引っかかる。そこで、運ぶ区間（運びはじめから次の指示のスピナーの針が止まるまで）をいまの弧で記録し、関節が速く動いたか運び終えるのが遅れたときだけ、同じ直前の状態から候補ごとに記録し直して、悪さ（`windowScore`）がいちばん小さい記録を残すようにした
- **悪さ**: 1コマ5cmを超えて動いた関節の数、運び終えた時刻に手足の先が円から2cmを超えて離れていればそのずれ、2人の骨どうしの突き抜けの深さの和を重みつきで足す。突き抜けは骨（カプセル）の中心の線分どうしの距離で測る。物理は関節の粒と相手の骨の重なりだけを押し出すので、骨の途中どうしの交差を見逃すが、経路を選ぶときはそれも数える。物理の判定そのものを線分どうしに替える案は、押し出す向きと配り方を決め直すことになり、#325 の範囲を超えるので見送った
- **種から決まる形**: 候補の順は固定で、同点なら先の候補、関節が速く動かず遅れもしない候補が見つかったら残りは試さない。乱数を使わない。裏返る指示だけは、`plan.ts` が弧の頂点で体を半分回した姿勢（`flipMidPose`）を見て成り立つかを決めているので、いまの弧のまま運ぶ
- **低く運ぶ候補**: 高く・左右だけの6つでは、上の伏せた人の場面が直らなかった。低く運ぶ3つを足すと、速い動きが94件から36件に減った（記録して比べる選び方で、すべての候補を試したとき）

あわせて、IK（`src/twister/pose.ts` の `solveTwoBone`）は肩と手の距離をほぼ 0 まで許すのに、物理の `MIN_SPANS` は 20cm 未満を禁じていたので、手が肩の近くを通るときに目標の姿勢と押し出した姿勢が別の形を求めていた。下限を `src/twister/body.ts` の `LIMB_CHAINS` の `minSpan` にまとめ、IK と物理の両方がそれを使うようにした。腕の下限は 20cm から 18cm にした。伏せきった人（肩の高さ 16cm）の手が円に届く距離が約 19.9cm で、20cm のままだと IK が手を円から浮かせるためである。脚は 25cm のまま。

種0〜29で、変更前（#331 の後）と比べた結果は次のとおり。

| 指標 | 変更前 | 変更後 |
|---|---|---|
| 1コマ5cmを超える関節の動き | 162件 | 37件 |
| いちばん大きな1コマの動き | 17.0cm | 12.7cm |
| 運び終えた時刻に円から2cmを超えて離れていた指示（176のうち） | 12 | 12 |
| そのずれの最大 | 20.0cm | 9.5cm |
| 倒れ込ませた人が負けた対戦 | 29 | 29 |
| 1回の対戦を作る時間（開発機の平均） | 約57ミリ秒 | 約123ミリ秒 |

遅れる指示の数が減らないのは、残る遅れが速い手番（1秒）で1.2m運ぶ指示に出ているためである。押し出しで関節が前のコマの位置から目標を追いかける速さの上限（`src/twister/physics.ts` の `MAX_FOLLOW_STEP`、1コマ4cm）にいまの弧でも近く、どの経路でも追いつかない。押し返されていたぶんは無くなったので、ずれは半分ほどになった。上限を上げると姿勢が飛ぶ場面が戻りうるので、この issue では変えていない。手足は次の指示のスピナーの針が止まるまでには円に乗る。

候補を記録し直すぶん、対戦を作る時間は約2倍になった。#331 で約300ミリ秒から約60ミリ秒に縮めたあとなので、#331 の前（約300〜400ミリ秒）よりは短い。候補を試す区間を運び終えた時刻までに縮めると約100ミリ秒になるが、速い動きが52件に増える（運び終えたあとの着地で出る動きを比べられない）ので採らなかった。OBS のブラウザソースで止まりが目立つようなら、Web Worker へ移す案（前節）と合わせて改めて検討する。

## アイコンは Worker を経由せずに読む

Twitch の画像配信元（`static-cdn.jtvnw.net`）は `Access-Control-Allow-Origin: *` を返すので、合成ページが `crossOrigin` を付けて読めば WebGL のテクスチャにできる（読み込んだ画像の画素を読めることを実機で確かめた）。Worker に画像を取り次ぐ経路は作らない。

## ツイスターはレイドのトリガーにだけ置く

相手のアイコンを顔に貼って対戦するので、相手が配信者でなければならない。シャウトアウトと同じく、レイドの行にだけ置ける（[トリガーの動作](./alerts-actions.md)）。

## BGM は1曲だけ選ばせ、配信の BGM は市町村紹介と同じ仕組みで下げる

対戦のあいだ流す BGM は、市町村紹介の音（`worker/town-tour-sound.ts`）と同じく配信者がアップロードした音声から選ぶ（公開しているリポジトリに音声を入れられないため）。市町村紹介のように場面ごとの効果音の枠は持たず、BGM 1曲と音量だけにした（求められたのが BGM だけで、場面の切れ目を増やすと設定が重くなるため）。設定は KV の `twister-sound` に1つだけ持ち、レイドと試し再生が共有する。

Worker は呼び出しに音声の URL（オーバーレイ用キーつき）と音量を添えて押し出し、合成ページが流しはじめたときに鳴らして、対戦の終わりの2秒（`src/twister/bgm.ts` の `BGM_FADE_OUT_MS`）で下げて止める。止める時刻はタイマーで数える（OBS のブラウザソースは映っていないと描画を間引くため）。配信の BGM は、市町村紹介と同じく合成ページが「対戦の長さぶん下げておく」と Worker 経由で裏方へ知らせ、裏方が自分で戻す。対戦の長さは流しはじめた時点で決まっているので、市町村紹介と違って送り直さない。

BGM を選んでいるのにオーバーレイ用キーが未発行なら、黙って無音で流さずに押し出しの失敗として記録する（試し再生は409）。プレビューはキーを持たないので BGM を流さない。

## 試し再生でも配信者は自分の表示名で出す

はじめは、試し再生はレイドの通知（`to_broadcaster_user_name`）を持たないので配信者の名前を「配信者」と出していた。見栄えを確かめる試し再生で名札だけが本番と違うのを避けるため、ログインした配信者の表示名を Twitch から引くようにした。セッションは配信者のユーザーIDしか持たないので、既存の `getUserLogin`（ID→ログイン名）と `getUserByLogin`（ログイン名→表示名とアイコン）を続けて呼ぶ。保管庫（`TokenVault`）のトークンもログイン名を持つが、ログインしたときの値なので、Twitch でログイン名を変えると古くなり、元の名前を取った別人の顔と名前を出しうる。そのため使わない。表示名も変えられるので保存せず、試し再生のたびに引く。合成ページのプレビュー（`src/twister/demo.ts`）は Worker を通らずログインも持ち込まないので「配信者」のままにする。

## スピナーを大きく見せ、後半も速くしない

配信者から「ルーレットを視聴者に大きく見せたい」「後半に速くして時間を縮めているのを、縮めずにできないか」と求められた。

**スピナーの大きさ**: スピナーは右下の角に半径150px（1080の高さのとき）で出していて、配信の画面では針の行方を追いにくかった。ずっと大きく出すと人形とマットを隠すので、針を回して結果を見せるあいだ（`spinMs`）だけ右寄りの真ん中に半径330pxで出し、手足を運ぶあいだは右下の角へ戻すことにした。針を回すあいだは人形がほとんど動かないので、隠しても見どころを損なわない。大きさは回しはじめの0.3秒で大きくし、運びはじめの0.5秒で縮めて、置き場所が飛ばないようにした（`src/twister/spinner.ts` の `spinnerZoomAt`）。画面の真ん中に重ねる案は、人形をまるごと隠し、番と指示の文字の置き場所も無くなるので採らなかった。

**後半も速くしない**: #319 で手数を5〜7回に増やしたとき、対戦が40秒を超えないように3手目からと最後の指示を速くした（針1秒・1手2.6秒）。どの手番もはじめの速さ（針1.8秒・1手4.0秒、`src/twister/game.ts` の `TURN_PACE`）にして種0〜29で試すと、対戦の長さは31〜37秒から37〜45秒（平均34秒から40秒）に延びた。姿勢が飛ぶ・めり込む・運び終えるのが遅れるのを確かめるテストはすべて通り、倒れ込ませた人が負ける対戦も30回中29回で変わらなかった。運ぶ長さが1秒から1.4秒に延びるので、#325 で残った「速い手番で1.2m運ぶ指示が遅れる」場面にはむしろ余裕ができる。レイドの演出として6秒ほど延びるのは許せると判断し、後半も速くしないことにした。プレビューは対戦を流しきってから次を流すので、間隔を40秒から50秒に延ばした。
