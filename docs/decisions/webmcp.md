# エージェント向けのツール（WebMCP）

**アプリのページは WebMCP でページUIの操作をツールとして登録し、ブラウザのエージェントから HDAD を操作できるようにする**（issue #279〜#282）。手を動かすのは基本的にAIエージェントだという前提（`docs/principles.md`）を、コードを直すときだけでなく配信中の操作にも広げるためである。

## API は document.modelContext を使う

WebMCP の仕様は 2026年7月に `navigator.modelContext` から `document.modelContext` へ移った（ツールはブラウザ全体ではなく文書に属する、という理由）。Chrome は origin trial（149〜156）のあいだ両方を残しているが、古いほうは 150 で非推奨になったので新しいほうだけを使う。`provideContext`・`clearContext` は3月に仕様から消え、`unregisterTool` は出荷されなかったので、登録の解除は `registerTool` に渡す `AbortSignal` で行う。型は `webmcp-types` を開発時の依存に入れて使う。

origin trial のトークンはページに入れない。試すのは `chrome://flags/#enable-webmcp-testing` を有効にしたブラウザだけでよく、本番のオリジンを登録して期限つきのトークンを持ち回る手間に見合わないためである。

エージェント側の対応は、2026-10-07 時点では利用環境によって分かれている。ChatGPT のデスクトップアプリ（Windows・macOS）の組み込みブラウザーは、2026-08-25 の発表で WebMCP に対応し、対応したページのツールを見つけて使う（GPT-5.6 Sol・Terra に限り、Enterprise・Edu のワークスペースでは使えない）。発表で対応が挙げられたのはこの組み込みブラウザーだけで、Chrome で開いたページのツールを ChatGPT が使うことは発表されていない。Chrome で開いたページのツールを試すときは、Model Context Tool Inspector 拡張を使う。

## 段階を分ける

ツールにできる操作はページUIのほぼすべてにわたるので、配信への影響が小さい順に4段階に分けた。段階1（#279）は下部バーでできること（BGM・ポモドーロ・読み上げのミュート・文字起こし）とページの移動、段階2（#280）は配信に直接出る操作（チャットの送信・注目コメント・試し再生）、段階3（#281）は記録の読み取り、段階4（#282）は設定の読み書きである。下部バーの操作から始めたのは、配信中に手を離せない場面で言葉で頼みたいのがまずこれらであり、どれも取り消せる操作だからである。

## ツールは画面のボタンと同じ道を通す

BGM とポモドーロのツールは、Worker の Api を直接呼ばずにアプリの枠の `BgmPlayerProvider`・`PomodoroTimerProvider` を通す。Api を直接呼ぶと、エージェントが曲を切り替えても下部バーが古い曲を出し続け、配信者がそれを見てボタンを押すと意図しない操作になるためである。同じ理由で、ツールは状態が変わるたびに登録し直さず、呼ばれたときに最新の状態を ref から読む（登録し直すと、エージェントへツールの一覧が変わったという知らせが出続ける）。

読み上げのミュートだけは、下部バーのボタン（`src/speech/speech-mute-control.tsx`）が開いたときに一度読むだけで状態を共有していないので、ツールは Api を直接呼ぶ。ツールで切り替えても、ボタンの見た目はページを開き直すまで変わらない。ボタンを押せば映っている状態の逆が保存されるだけで、壊れはしないので段階1では直していない。

## 対応していないブラウザでは何もしない

`document.modelContext` が無いのは、ブラウザが WebMCP に対応していない（Chrome でも flag か origin trial が要る）ということで、失敗ではない。そのときに下部バーへ知らせを出すと、WebMCP を使わない配信者の画面にいつも知らせが出てしまうので、何も登録せず何も出さない。一方、対応しているのに登録を断られたときは、エージェントから呼べないことに気づけないので、下部バーに理由を出す（Fail-Fast）。途中のツールで断られたときは、先に登録できたツールも消す。一部のツールだけが呼べる状態を残すと、エージェントが「できること」を見誤るためである。

## 入力は execute でも確かめる

ツールの入力の形は `inputSchema` で示すが、ブラウザがそれで検証してから呼ぶとは仕様に書かれていない。そのため `execute` でも確かめ、受け付けない値（範囲外の音量・知らない操作の名前など）は既定値に丸めずに投げる。投げた理由はそのままエージェントに返るので、エージェントが直してやり直せる。
