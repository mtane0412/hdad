# ページUIの枠（`src/app/`）

## 未保存の変更があるページからの移動は、確認を出して止める

ページUIは `src/app/app.tsx` で `key={pathname}` によりページを作り直すので、保存ボタンを押す前にサイドバー・ページを探す窓（Cmd+K）・ブラウザの「戻る」で移ると、編集した内容が確認なしに消えていた（issue #182）。配信者は保存されていないことに配信中に気づくことになり、[開発方針](../principles.md) の「黙って辻褄を合わせず、エラーにする」と同じ問題である。

止め方は、移る前に自動で保存する案ではなく、確認（「保存せずに移る / 留まる」）にした。自動で保存すると、保存の失敗や Worker の検証で拒まれたことが移動の裏で起き、配信者が気づけない別の「黙って」を生むためである。

止める判断は `src/app/router.tsx` だけが持つ。ページは `useUnsavedChanges` で未保存かどうかを知らせるだけにし、`navigate`（`Link` とページを探す窓が使う）とブラウザの「戻る・進む」（`popstate`）の両方を同じ場所で止める。「戻る」はURLが変わったあとに知らせが届くので、`history.state` に履歴の位置を持たせ、止めたときは `history.go` で未保存のページの位置まで戻し、戻し終わるまでも同じページを出し続ける。再読み込みとタブを閉じる操作は `beforeunload` でブラウザに止めてもらう（文面はブラウザが決める）。未保存のときだけ登録するので、保存済み・未編集のときの移動は速いままである。

対象にしたのは、すでに未保存かどうかを判定していたトリガー（`/triggers/`）・オーバーレイ（`/overlay/`）・チャットボット（`/bot/`）の3ページである。ほかの保存ボタンを持つページ（`/speech/`・`/llm/`・`/screen/`・`/bgm/`・`/viewers/` のメモ・`/rewards/`）は、未保存の判定を足したうえで `useUnsavedChanges` を呼べば同じ仕組みに乗る。

## 上部バーをなくし、配信中の操作を下部バーにまとめる

配信中は文字起こしのオン・オフや BGM の操作をどのページからでも触りたいが、それぞれの操作は専用のページ（コネクター・`/bgm/` など）にしかなく、そのページへ移る手間がかかっていた（issue #235）。そこで本文の下端に固定するバー（`src/app/bottom-bar.tsx`）を置き、配信中に何度も触る操作を項目として並べることにした。BGM・ポモドーロ・読み上げのミュートは #236〜#238 で足す。

あわせて、本文の上にあったバー（サイドバーの開閉・ページの見出し・ページを探す）をなくした。見出しを出す以外の仕事が少なく、下部バーと合わせると上下で本文の高さを二重に削るためである。開閉と「ページを探す」はサイドバーの上部へ移し、見出しは本文の先頭に置いた（ページを移ったら見出しへフォーカスを移す扱いは変えない）。狭い画面ではサイドバーが重ねて開く形になり、閉じているとサイドバーの中の開閉ボタンが見えなくなるので、そのときだけ下部バーの左端に開くボタンを出す。

文字起こしの状態はこれまでサイドバーの末尾に出していたが、オン・オフのボタンの横に出すほうが見落としにくく、同じ情報を2か所に出さないため、下部バーへ移してサイドバーからは消した。

下部バーの形は音楽プレーヤー（Spotify など）にならい、本文の中ではなくサイドバーの下まで画面の幅いっぱいに通し、サイドバーと本文はバーの上で終わらせた（高さはどちらも `--bottom-bar-height` から決める）。並びは左（いま流している曲）・中央（再生の操作）・右（そのほかの切り替え）の3つに分ける。ボタンはプレーヤーの操作と同じく文字を出さずアイコンだけにし、オンのあいだはアイコンの色で示す。ただし文字起こしの状態（「聞いています」「途切れています」など）は言葉でも出す（途切れたことを色だけで伝えると見落とすため）。
