# テキスト（素材の種類 `text`）

配信で「今何をしているか」「何を目指しているか」を見せたかったが、いまの素材は機械が推したもの（サイドスーパー）・起きたことの記録（作業ログ）・視聴者の宣言（作業机）のどれかで、配信者自身の意図を人が書いたものとして持つ場所が無かった。そこで、配信者が自由に書いた文字をそのまま映す素材「テキスト」を追加した（issue #294）。LLM による自動の書き換えは段階2（issue #295）に分けた。

## GTD のツールにしない

はじめは「今やっていること」を出すために、タスクの一覧や状態（未着手・作業中・完了）を持つ GTD のようなツールを検討した。しかし、タスクの管理は汎用すぎて「既定を決め切る」（方針1）とぶつかるうえ、配信中は入力の手間がいちばん効く。画面に出したいのは管理の結果ではなく一言なので、名前と本文だけを持つ自由入力のテキストに絞った。

## 本文は D1 に持ち、URL にも素材のパラメータにも入れない

本文は配信中に書き換えるものなので、URLにも素材のパラメータ（構成のクエリ文字列）にも入れない（方針3）。構成は KV（`overlay-layout`）にあるが、テキストは新しい表 `texts`（`migrations/0029_texts.sql`）に置いた。KV は書いた直後に古い値が返りうるので、書き換えて押し出した直後に合成ページが読み直したときに古い本文へ戻りうるためである。

## 素材からテキストをIDで指し、名前の選択欄で選ばせる

テキストは複数持てるので、素材はどれを映すかを持つ必要がある。構成の素材（`OverlayItem`）は素材を見分けるIDを持たないため、「テキストがどの素材に映るか」をテキストの側に持たせることはできない。そこで素材のパラメータ `text` にテキストのIDを持たせた。

IDは手で打たせず、管理画面（`/overlay/`）ではテキストの名前の選択欄から選ばせる（方針2）。選択欄で見分けられるよう、名前はほかのテキストと重ねさせない（`UNIQUE` と `worker/text.ts` の検証）。選択欄はパラメータの自動生成（`src/core/fields.tsx` の `ParamField`）では作れない（選択肢が Worker にあるため）ので、構成のページがテキストの一覧を読み、`text` の種類だけ専用の選択欄を出す。

IDは `AUTOINCREMENT` にして、消したテキストのIDを次のテキストに使い回さない。使い回すと、消えたテキストを指していた素材が、黙って別のテキストを映してしまうためである。

## 選んだテキストが消されていたら、素材の箱にエラーを出す

選んだテキストが消されていた・まだ選んでいないときは、黙って空の札にせず、札を隠して素材の箱にエラーを出す（方針4）。空の札では、消したことに配信中は気付けないためである。管理画面では、消されたテキストを指す素材の選択欄に「消されたテキスト（ID ◯）」を残す（開いただけで別のテキストへ移らないように。レジストリに無いデザインと同じ扱い）。テキストを消す前には、映している素材がエラーになることを確認の文面で伝える。

一方、本文が空のあいだは札ごと隠す。本文を空にするのは「いまは書くことが無い」という配信者の意図なので、エラーにはしない。

## 上限を超えた本文は切り詰めずに拒む

本文は100文字・4行、名前は20文字、テキストは20件までにした。本文の上限は画面の隅の札（追加したときの枠は720×220px）で読み切れる量で、超えたら切り詰めずに拒む（方針4）。黙って切り詰めると、書いたものと違う文が配信画面に出るためである。文字数は作業机と同じく見た目の1文字（書記素クラスタ）ずつ数える。上限の数は Worker だけが持ち、画面は返ってきた問題点をそのまま並べる（同じ数を2か所に書かない）。

## 押し出しは作業机と同じ形にする

書き換えたら `AlertChannel` に相乗りして合成ページへ押し出す（作業机・ポモドーロと同じ。新しい Durable Object を足すと PR ブランチのプレビュービルドが失敗するため）。テキストは少ないので、変わった1件ではなく一覧を丸ごと送り、素材は自分が映すテキストをIDで引き直す。合成ページは開いたとき・つながるたび・5分おきにも読み直し、押し出しを取りこぼしても戻る。

押し出しに失敗しても保存は取り消さない（合成ページは5分以内に読み直して映す）。ただし黙って成功にもせず、保存は済んだことを添えて502で返す。

## 入口はページと下部バーの2つにする

追加・名前の変更・削除はアプリのページ（`/texts/`）だけに置き、下部バーには本文の書き換えだけを置いた。配信中にいちばん触るのは本文で、下部バーは狭く保ちたいためである（ポモドーロの休憩の曲と同じ考え方）。

ページではテキストを1件ずつ別々に保存する。1件を書き換えるために、ほかのテキストの書きかけまで送らないためである。下部バーは窓を開くたびにテキストを読み直す（ページや別の窓で書き換えた本文を、古いまま上書きしないため）。下部バーの書きかけは窓を閉じたら捨てる。バーはページを移っても残るので、書きかけを抱えたままにすると、ページを移るたびに「保存していない変更があります」と確認が出てしまうためである。窓を開いて書きかけているあいだだけ、再読み込みの前に確認を出す。
