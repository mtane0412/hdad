# チャンネルポイント報酬（`/rewards/`）

チャンネルポイント報酬の管理画面（`/rewards/`）は issue #160 で追加した。それまでのHDADは報酬の一覧を読む（トリガーの管理画面で報酬を選ぶため）ことと交換の通知を受け取ることしかできず、報酬を作る・直す・消すにはTwitchのクリエイターダッシュボードへ行く必要があった。

## Twitchのダッシュボードで作った報酬は変更できない

Twitchの Helix API は、報酬の更新（`PATCH /helix/channel_points/custom_rewards`）と削除を**同じ Client ID で作った報酬にしか許さない**。これはTwitch側の制約で、スコープを増やしても回避できない。

そのため一覧では、すべての報酬と `only_manageable_rewards=true` で取った「HDADが作った報酬」の2つを取り、後者に含まれるものに `manageable` を立てて画面へ返す（`worker/reward-routes.ts` の `getRewards`）。画面は `manageable` が `false` の報酬に編集欄も削除のボタンも出さない。押せるのに必ずTwitchに拒まれるボタンを置くと、配信者は失敗してから初めて制約を知ることになるためである。既存の報酬をHDADから管理したい場合は、HDADで作り直してもらう。

## 扱う項目を5つに絞った

Twitchの報酬は待機時間・1配信あたりの上限回数・1人あたりの上限回数・背景色・交換を待たずに完了にするか、などの項目を持つが、HDADで扱うのは名前・必要ポイント・説明・交換できるか・メッセージの入力を求めるかの5つだけにした。設定項目は増やせることではなく減らせることを価値とする（`docs/principles.md` の方針1）。ほかの項目はTwitchの既定のままになる（HDADの更新は5つの項目しか送らないので、ほかの項目の値には触れない）。要る項目が出てきたら、そのときに1つずつ追加する。

交換の完了・返金（`PATCH .../redemptions`）も今回は持たない。交換はTwitchの既定どおり「未処理」の待ち行列に入るので、処理はTwitchの画面で行う。

## 書き換えのスコープが無ければ、Twitchへ送る前に断る

書き換えには配信者のトークンの `channel:manage:redemptions` が要る。このスコープは issue #160 で追加したので、それより前にログインしたトークンには無い。そのまま送るとTwitchが英語の403を返し、原因が分かりにくい。そこで Worker が送る前にトークンのスコープを確かめ、`missing-scope` でログインし直しを求める（コメントビューアーの `user:write:chat` と同じ扱い）。

一覧の取得は `channel:read:redemptions` で足りるので確かめない。トリガーの管理画面がスコープの追加前のトークンでも報酬を選べるようにするためである。

## トリガーに使われている報酬は消させない

トリガーの条件に使われている報酬を消すと、配信中に交換されてもアラートが出ないまま気づけない。素材の削除（`media-in-use`）と同じく、トリガーの設定から外すまで削除を断る（`reward-in-use`）。
