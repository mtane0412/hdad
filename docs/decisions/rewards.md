# チャンネルポイント報酬（`/rewards/`）

チャンネルポイント報酬の管理画面（`/rewards/`）は issue #160 で追加した。それまでのHDADは報酬の一覧を読む（トリガーの管理画面で報酬を選ぶため）ことと交換の通知を受け取ることしかできず、報酬を作る・直す・消すにはTwitchのクリエイターダッシュボードへ行く必要があった。

## Twitchのダッシュボードで作った報酬は変更できない

Twitchの Helix API は、報酬の更新（`PATCH /helix/channel_points/custom_rewards`）と削除を**同じ Client ID で作った報酬にしか許さない**。これはTwitch側の制約で、スコープを増やしても回避できない。

そのため一覧では、すべての報酬と `only_manageable_rewards=true` で取った「HDADが作った報酬」の2つを取り、後者に含まれるものに `manageable` を立てて画面へ返す（`worker/reward-routes.ts` の `getRewards`）。画面は `manageable` が `false` の報酬に編集欄も削除のボタンも出さない。押せるのに必ずTwitchに拒まれるボタンを置くと、配信者は失敗してから初めて制約を知ることになるためである。既存の報酬をHDADから管理したい場合は、HDADで作り直してもらう。

## 扱う項目を5つに絞った（のちに10個へ広げた）

Twitchの報酬は待機時間・1配信あたりの上限回数・1人あたりの上限回数・背景色・交換を待たずに完了にするか、などの項目を持つが、HDADで扱うのは名前・必要ポイント・説明・交換できるか・メッセージの入力を求めるかの5つだけにした。設定項目は増やせることではなく減らせることを価値とする（`docs/principles.md` の方針1）。ほかの項目はTwitchの既定のままになる（当時のHDADの更新は5つの項目しか送らなかったので、ほかの項目の値には触れなかった）。要る項目が出てきたら、そのときに1つずつ追加する。

### 背景色・待ち行列・待機時間・上限回数を加えた

その後、Twitchのダッシュボードと行き来せずに報酬を作りきれるよう、背景色（`background_color`）・交換をすぐ完了にするか（`should_redemptions_skip_request_queue`）・待機時間（`global_cooldown_seconds`）・1配信あたりの上限回数（`max_per_stream`）・1人あたりの上限回数（`max_per_user_per_stream`）を加えた。どれもHelixの作成・更新が受け付ける項目である。

- 待機時間・上限回数は「有効か」と「値」の2つでなく、値の `null`（画面の空欄）を「制限なし」とする1つの欄にした。Twitchは無効の項目を 0 で返し、0 は送れない値なので、応答を読むときに `null` へ読み替える。送るときは無効の印だけを送り、回数・秒数は送らない
- 待機時間はHelixなら1秒から受け付けるが、60秒未満はTwitchの画面に出ず視聴者から待機中だと分からないため、Twitchのダッシュボードと同じ60秒を下限にした。上限はTwitchの制約の604800秒（7日）。単位は秒のまま扱う（ダッシュボードで90秒のように分で割り切れない値にされても、読み書きで値が変わらないように）
- 応答に背景色や制限の設定が欠けていたら、制限なしとして黙って扱わずに投げる
- 一時停止（`is_paused`）は「交換できる」と役目が近く、配信中の操作になるので加えていない
- 画像などHDADで扱えない設定のために、画面からTwitchの報酬のページ（`dashboard.twitch.tv/u/<login>/viewer-rewards/channel-points/rewards`）を開けるようにした

交換の完了・返金（`PATCH .../redemptions`）も今回は持たない。「交換したらすぐ完了にする」を付けていない報酬の交換は「未処理」の待ち行列に入るので、処理はTwitchの画面で行う（付けた報酬の交換はすぐ完了になり、待ち行列に入らない）。

## 画像は表示だけにする

Helix の作成・更新は画像を受け付けない（送れる項目に画像が無く、応答の `image`・`default_image` で読めるだけである）。そのため画像の登録・変更は持たず、一覧で報酬を見分けやすくするために表示だけを行う。配信者がアップロードした画像（`image`）があればそれを、無ければTwitchの既定の画像（`default_image`）を使う（`worker/twitch.ts` の `toCustomReward`）。既定の画像まで無い応答は想定した形でないので、画像の無い報酬として黙って扱わずに投げる。

## 書き換えのスコープが無ければ、Twitchへ送る前に断る

書き換えには配信者のトークンの `channel:manage:redemptions` が要る。このスコープは issue #160 で追加したので、それより前にログインしたトークンには無い。そのまま送るとTwitchが英語の403を返し、原因が分かりにくい。そこで Worker が送る前にトークンのスコープを確かめ、`missing-scope` でログインし直しを求める（コメントビューアーの `user:write:chat` と同じ扱い）。

一覧の取得は `channel:read:redemptions` で足りるので確かめない。トリガーの管理画面がスコープの追加前のトークンでも報酬を選べるようにするためである。

## トリガーに使われている報酬は消させない

トリガーの条件に使われている報酬を消すと、配信中に交換されてもアラートが出ないまま気づけない。素材の削除（`media-in-use`）と同じく、トリガーの設定から外すまで削除を断る（`reward-in-use`）。
