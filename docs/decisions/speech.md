# チャットの読み上げ（`speech/reader/`）

チャットの読み上げ（`speech/reader/`）は、映すものを持たず音だけを出す単独のページで、`vite.config.ts` の入力に直接追加している（映すものを持たないので合成ページの素材にはできない。`docs/decisions/backstage.md`）。

チャットの受け取りはチャットボックスと同じ匿名IRC（`src/chat/connection.ts`・`channel.ts` を流用）なのでTwitchのトークンは持たないが、**読み上げの設定を Worker から読むためオーバーレイ用キーは持つ**（`?key=`。接続先のチャンネル名だけは、キーの要らない公開API `/api/chat/channel` から受け取る）。

## 合成は同じPCの VOICEVOX ENGINE に任せる

合成は**同じPCで動く VOICEVOX ENGINE**（既定 `http://localhost:50021`）に任せる。Workers AI に合成させないのは、発言のたびに無料枠を消費させないためで、ループバックへつなぐ根拠は文字起こしの中継ページと同じである（そのため `host` は `localhost` か `127.0.0.1` しか受け取らない）。

ただし**ENGINE は既定（`--cors_policy_mode localapps`）では localhost・`app://`・ブラウザ拡張からの通信しか受け付けないので、配信者が設定ページ（`<ENGINEの起点>/setting`）でこのサイトのオリジンを許可して ENGINE を再起動する必要がある**（中継ページが設定なしでつながるのは WebSocket が CORS の対象外だからで、fetch には同じ理屈が通らない。実機で拒まれることを確認済み）。

つながらない理由はブラウザからは見分けられない（どれも `TypeError: Failed to fetch` になる）ので、考えられる原因（起動していない・ポート番号が違う・CORSで拒まれている）と直し方をすべてエラーの文面に並べる（許可すべきオリジンを出すために `pageOrigin` を渡す）。

## 合成先にさくらのAI Engine を選べるようにする（issue #225）

配信PCで ENGINE を動かし続ける手間と、CORS の許可と再起動の手間をなくすため、**合成先（`engine`）に、さくらのAI Engine の音声合成（VOICEVOX）を選べるようにした**。ただし**既定はローカルのまま**にした。さくらは従量課金（3円/1万モーラ。無料枠は月50リクエストで、チャットの読み上げには足りない）で、無料枠で動かし続けるという方針（`docs/principles.md` の「8. 無料枠とデータベースの枠が、設計を決める」）に対して、配信者が選んだときだけ費用を払う形にとどめるためである。

上の「Workers AI に合成させない」という判断は、無料枠を発言のたびに消費させないためのものだった。さくらは Cloudflare の無料枠を使わず（発言1件につき Worker のリクエスト1回と KV の読み出し2回（オーバーレイ用キーと設定）で、1配信500件でも無料枠の1%程度）、課金は**合成したモーラ数の合計**で1件ごとの切り上げが無い（2026-10-04 に実機で、8回の合成が8リクエスト・83モーラと記録されることを確認した。`audio_query` と失敗した呼び出しは数えられない）。月20配信×500件でも約90円の見込みなので、選べる合成先として加えてよいと判断した。

- **APIキーはブラウザに置かず、Worker のシークレット `SAKURA_AI_API_KEY` に持たせる**。そのため合成は Worker が受け持ち（`worker/speech-routes.ts`・`worker/speech-sakura.ts`）、読み上げのページはオーバーレイ用キーで `POST /api/overlay/speech/synthesis` を呼ぶ（`src/speech/sakura.ts`。`voicevox.ts` と同じ `Voicevox` の形にそろえ、`task.ts` が合成先で差し替える）。Worker の中で `audio_query` と `synthesis` を続けて呼び、発言1件を1リクエストで済ませる
- **オーバーレイ用キーは配信画面に映りうるので、Worker は保存済みの設定の合成先が `sakura` でなければ409で断り、さくらを呼ばない**（さくらを選んでいない配信者に課金を起こさない）。話者と速度も要求の本文ではなく保存済みの設定から取り（設定の持ち主を Worker の1か所にする）、読み上げ文の長さは読み上げのページが作りうる長さ（本文の上限200字＋表示名25字＋読点）までに限る
- **合成した WAV は加工せずに返す**（MP3 への変換などで Workers Free の CPU 10ms を使わない）。外への呼び出しの約束どおり `withTimeout` で包むので本文は Worker で一度読み切るが、これは通信の待ちであって CPU 時間はほとんど使わない
- **起動時の確認は、課金されない `audio_query` だけを呼ぶ**（`POST /api/overlay/speech/check`）。さくらには ENGINE の `/version` と `/speakers` が無い（404）ので `checkReady` の代わりにこれを使い、APIキーの誤りや、規約に同意していない話者（`This model is not available.`）を配信の前に画面に出す
- **話者は ID を入力させる**（ローカルと同じ欄）。さくらには話者の一覧を返す経路が無く、規約に同意したキャラクターを API から知る方法も無いためである。コントロールパネルではずんだもん（ノーマル）が `3` と表示されるが、`/tts/v1/audio_query` は `3` を `This speaker is not available.` で拒み、`1` と `7` は通る（原因は未確認）。区画のヘルプと利用者向けの説明に書いておく
- **費用は、区画で合成先にさくらを選んだときにその場で出す**（選択肢の名前にも「従量課金」と入れる）。合成先はホスト・ポートと同じく起動のときにしか使わない（`src/speech/engine.ts` の `speechEndpointOf` で見分け、変わったらOBSの再読み込みを知らせる）。さくらはホストとポートを使わないので、選んでいるあいだはその欄を出さない
- 合成先を選べるようになる前に保存した設定には `engine` が無いので、`loadSpeechSettings` はローカルとして読む（それまではローカルしか無かったため。保存し直さなくても読み上げを止めない）

## 読み上げの作り

通信を伴わない変換（`text.ts`・`queue.ts`・`form.ts`）と、ENGINE の呼び出し（`voicevox.ts`）・Workerの呼び出し（`api.ts`）・URLの組み立て（`url.ts`）（いずれも `fetch` を差し替えてテスト）を、DOM・WebSocketを扱う部分（`audio.ts`・`stage.ts`）から分ける。読むかどうかの判断も `text.ts` が持つ（コマンド・エモートだけの発言・`ignore` に挙げた人の発言は読まない）。

読み上げは耳で一度しか聞けないので、URLは「URL」に、同じ文字の3つ以上の連打は2つに縮めてから渡す。ENGINE は2段で呼ぶ（`/audio_query` で読み方を作らせ、`speedScale` を差し替えて `/synthesis` へ渡す）。

**読み上げ速度は合成の時点で指定し、音量は再生する側（`audio.ts`）が持つ**（再生速度で速さを変えると声の高さまで上がる／音量は合成しなおさずに変えられる）。読み上げは1件ずつ順に行い、待ちが `MAX_WAITING_SPEECH` を超えたら古いほうから捨てる（数分前の発言を読み続けても配信の役に立たない）。

**起動のときの失敗（VOICEVOX が動いていない・拒まれた・チャンネル名が読めない）は画面に出して止め（`checkReady` をつなぎ始める前に呼ぶ）、鳴らしている途中の1件の失敗ではその1件だけを飛ばす**（1件のために以降ずっと無音になるとOBSの再読み込みが要る）。

## 設定は Worker が持つ

**読み上げの設定（話者・速度・音量・長さ・名前を読むか・読み上げない人）は Worker が持つ**（`worker/speech-config.ts`。KVのキーは `speech-settings`。検証は `bot-config.ts`・`moderation-config.ts` と同じ作りで、問題点をすべて集めてから拒む）。

経路は `GET`/`PUT /api/admin/speech`（`requireAdmin`）と `GET /api/overlay/speech`（`requireOverlayKey`）で、**値の範囲の検証は Worker だけが持つ**（画面とWorkerで二重に持たない。そのため画面は空欄を 0 に丸めず NaN のまま送り、返ってきた問題点を並べる）。

かつては設定をすべてURLのクエリに埋めていたが、それだと配信中に音量ひとつ変えるにもOBSのURLを貼り替えることになるため移した（issue #86）。配送は**ポーリング**（30秒。サイドスーパーと同じ理由で押し出しは要らない）で、設定を変えるとOBSの再読み込みなしで次に読む1件から効く。

**ホストとポートだけは起動のときにしか使えない**（つなぎ先が変わるのでつなぎ直しが要る）ので、`voicevox.ts` はつなぎ先（`origin`・`pageOrigin`）を作るときに受け取り、話者と速度は `synthesize` のたびに受け取る。変わったことに気づいたら読み上げのページは `showError` で（一度だけ）知らせ、管理画面も入力を変えた時点で知らせる（黙って古いつなぎ先のまま読み続けない）。設定の読み直しの失敗では止めず、前に読んだ設定のまま読み上げを続ける。

## アプリのページと、裏方との共有

アプリのページ（`src/speech/speech-page.tsx`）は設定の保存とOBSに貼るURL（キーだけが入る）を受け持ち、URLの組み立ては `url.ts`、入力欄の値の変換は `form.ts` に分ける。のちに画面はコネクターのページの VOICEVOX の区画（`src/speech/speech-section.tsx`）になり、OBSに貼るURLは裏方の1枚に任せて `url.ts` を消した（[裏方をまとめたページ](./backstage.md#アプリのページをコネクターにまとめる)）。

このページだけは `botApi.status()` を読み、接続しているbotを「読み上げない人」に追加するボタンを出す（botの応答まで読み上げさせないため。設定はWorkerに保存されるものなので勝手に書き換えず、押したときだけ追加する。接続状態を読めなかったときは未接続扱いにせず理由を出す）。

読み上げそのもの（設定の読み出し・VOICEVOX への接続・チャットの受け取り）は `src/speech/task.ts` の `startSpeech` に切り出してあり、単独ページ（`stage.ts`）はURLパラメータを読んでそれを呼ぶだけである（裏方をまとめたページからも同じものを呼ぶため。issue #108）。
