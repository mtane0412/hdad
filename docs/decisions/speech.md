# チャットの読み上げ（`speech/reader/`）

チャットの読み上げ（`speech/reader/`）は、映すものを持たず音だけを出す単独の素材ページで、`alerts/` と同じく `vite.config.ts` の `categories` ではなく入力に直接足している。

チャットの受け取りはチャットボックスと同じ匿名IRC（`src/chat/connection.ts`・`channel.ts` を流用）なのでTwitchのトークンは持たないが、**読み上げの設定を Worker から読むためオーバーレイ用キーは持つ**（`?key=`。接続先のチャンネル名だけは、キーの要らない公開API `/api/chat/channel` から受け取る）。

合成は**同じPCで動く VOICEVOX ENGINE**（既定 `http://localhost:50021`）に任せる。

Workers AI に合成させないのは、発言のたびに無料枠を消費させないためで、ループバックへつなぐ根拠は文字起こしの中継ページと同じ（そのため `host` は `localhost` か `127.0.0.1` しか受け取らない）。

ただし**ENGINE は既定（`--cors_policy_mode localapps`）では localhost・`app://`・ブラウザ拡張からの通信しか受け付けないので、配信者が設定ページ（`<ENGINEの起点>/setting`）でこのサイトのオリジンを許可して ENGINE を再起動する必要がある**（中継ページが設定なしでつながるのは WebSocket が CORS の対象外だからで、fetch には同じ理屈が通らない。実機で拒まれることを確認済み）。

通信を伴わない変換（`text.ts`・`queue.ts`・`form.ts`）と、ENGINE の呼び出し（`voicevox.ts`）・Workerの呼び出し（`api.ts`）・URLの組み立て（`url.ts`）（いずれも `fetch` を差し替えてテスト）を、DOM・WebSocketを扱う部分（`audio.ts`・`stage.ts`）から分ける。

読むかどうかの判断も `text.ts` が持つ（コマンド・エモートだけの発言・`ignore` に挙げた人の発言は読まない）。

読み上げは耳で一度しか聞けないので、URLは「URL」に、同じ文字の3つ以上の連打は2つに縮めてから渡す。

ENGINE は2段で呼ぶ（`/audio_query` で読み方を作らせ、`speedScale` を差し替えて `/synthesis` へ渡す）。

**読み上げ速度は合成の時点で指定し、音量は再生する側（`audio.ts`）が持つ**（再生速度で速さを変えると声の高さまで上がる／音量は合成しなおさずに変えられる）。

読み上げは1件ずつ順に行い、待ちが `MAX_WAITING_SPEECH` を超えたら古いほうから捨てる（数分前の発言を読み続けても配信の役に立たない）。

つながらない理由はブラウザからは見分けられない（どれも `TypeError: Failed to fetch` になる）ので、考えられる原因（起動していない・ポート番号が違う・CORSで拒まれている）と直し方をすべてエラーの文面に並べる（許可すべきオリジンを出すために `pageOrigin` を渡す）。

**起動のときの失敗（VOICEVOX が動いていない・拒まれた・チャンネル名が読めない）は画面に出して止め（`checkReady` をつなぎ始める前に呼ぶ）、鳴らしている途中の1件の失敗ではその1件だけを飛ばす**（1件のために以降ずっと無音になるとOBSの再読み込みが要る）。

**読み上げの設定（話者・速度・音量・長さ・名前を読むか・読み上げない人）は Worker が持つ**（`worker/speech-config.ts`。KVのキーは `speech-settings`。検証は `bot-config.ts`・`moderation-config.ts` と同じ作りで、問題点をすべて集めてから拒む）。

経路は `GET`/`PUT /api/admin/speech`（`requireAdmin`）と `GET /api/overlay/speech`（`requireOverlayKey`）で、**値の範囲の検証は Worker だけが持つ**（画面とWorkerで二重に持たない。そのため画面は空欄を 0 に丸めず NaN のまま送り、返ってきた問題点を並べる）。

かつては設定をすべてURLのクエリに埋めていたが、それだと配信中に音量ひとつ変えるにもOBSのURLを貼り替えることになるため移した（issue #86）。

配送は**ポーリング**（30秒。サイドスーパーと同じ理由で押し出しは要らない）で、設定を変えるとOBSの再読み込みなしで次に読む1件から効く。

**ホストとポートだけは起動のときにしか使えない**（つなぎ先が変わるのでつなぎ直しが要る）ので、`voicevox.ts` はつなぎ先（`origin`・`pageOrigin`）を作るときに受け取り、話者と速度は `synthesize` のたびに受け取る。

変わったことに気づいたら読み上げのページは `showError` で（一度だけ）知らせ、管理画面も入力を変えた時点で知らせる（黙って古いつなぎ先のまま読み続けない）。

設定の読み直しの失敗では止めず、前に読んだ設定のまま読み上げを続ける。

アプリのページ（`src/speech/speech-page.tsx`）は設定の保存とOBSに貼るURL（キーだけが入る）を受け持ち、URLの組み立ては `url.ts`、入力欄の値の変換は `form.ts` に分ける。

このページだけは `botApi.status()` を読み、接続しているbotを「読み上げない人」に足すボタンを出す（botの応答まで読み上げさせないため。設定はWorkerに保存されるものなので勝手に書き換えず、押したときだけ足す。接続状態を読めなかったときは未接続扱いにせず理由を出す）読み上げそのもの（設定の読み出し・VOICEVOX への接続・チャットの受け取り）は `src/speech/task.ts` の `startSpeech` に切り出してあり、単独ページ（`stage.ts`）はURLパラメータを読んでそれを呼ぶだけである（裏方をまとめたページからも同じものを呼ぶため。issue #108）。
