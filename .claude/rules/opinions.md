# 意見ボード（`/opinions/`・素材の種類 `opinions`）

意見ボードは、配信者が出したテーマについて視聴者がチャットに書いたコメントから LLM が意見を取り出し、論点（観点）ごとに並べて映す機能（issue #306。いどばたビジョンにならう。続きは #307 観点の提案・#308 取りこぼしの救い出しと論点の統合・#309 配信後のまとめ）。**多数決に見せない**: 合成ページへは人数を渡さず（`readOverlayBoard`）、論点の大きさ・並びを人数で変えず（左右3つずつの枠へ作った順に交互に置き（`splitTopics`）、枠の高さは列の中の論点の数で等分する。論点の中は新しい順で、件数では切らず、枠に収まらない古い札は見た目（`opinions.css` の `.opinions-cards`）が丸ごと隠す）、意見は賛否ではなく札の種類（`OPINION_KINDS`: 課題・解決策・問い・気づき）で区別する。中央の「いま紹介している意見」は人数ではなく作った順に回す（`src/opinions/entry.ts` の `spotlightAt`）。人数は管理画面（`readAdminBoard`）にだけ出す。

テーマ・論点・意見・コメントは D1（`migrations/0033_opinions.sql`・`0034_opinion_prompts.sql`・`0035_opinion_summaries.sql`・`0042_opinion_regroup.sql`・`0043_opinion_theme_dismissed.sql`）に持ち、読み書きは `worker/opinion-store.ts` だけが行う。開いているテーマは1つだけで、開くときの確かめは1つの文で行う（`openTheme`）。Worker は締め切ったテーマも次を開くまで合成ページへ渡し（最後に開いたテーマを読む）、合成ページ（`src/opinions/view.ts`）が締め切ってから `ENDED_REVEAL_MS`（`src/core/ended-reveal.ts`。チャットで推理の終えたゲームと共有する1分）たったら現在時刻と `closedAt` だけから消す（プレビューのサンプルでは消さない）。下部バーの「演出を消す」で片付けたテーマ（`opinion_themes.dismissed_at`。締め切った最後のテーマにだけ書く `dismissClosedTheme`）は、`readOverlayBoard` がテーマの無いボードとして返す（開いているテーマは片付けない）。

コメントは、チャットの受け口（`worker/webhook-routes.ts` の `recordOpinionCommentFromChat`。自動モデレーションと `stream_chat_messages` の記録のあと）が、テーマを開いているときだけ貯める（出していなければ通知の断片も読み解かない）。断片と返信先の読み取りはコメントビューアーと共有する（`worker/comment-feed.ts` の `readChatBody`）。コマンド・エモートだけ・短い反応は規則で落とし（`worker/opinion.ts` の `dropReasonOf`。返信は短くても落とさない）、理由を付けて `dropped` として残す。失敗は投げずに `opinion-record-failed` として記録する。

振り分けは `AdBreakTimer` の別のインスタンス（名前 `opinions`。`worker/opinion-timer.ts`）のアラームが、テーマを開いているあいだ `OPINION_SORT_INTERVAL_MS`（45秒）ごとに1回分（`worker/opinion-run.ts` の `runOpinionSorting`）を進める。同じ人が `MERGE_GAP_MS`（20秒）以内に続けて書いたコメントは1つの発言につなげ、続きを待つ（`readyUtterances`）。渡せる発言が無ければ LLM を呼ばない。OpenRouter の鍵があれば、振り分けの前に Jev（箇所 `opinionFilter`。`worker/opinion-filter.ts`）へその回の発言をまとめて1回で尋ね（返信は返信先も添える）、確率を `opinion_comments.jev_score` に残して、`OPINION_FILTER_THRESHOLD` に届かない発言は `filtered` にして LLM に渡さない（しきい値はいま 0 で、記録だけして落とさない。実配信の記録を見て決める）。Jev の失敗はその回の発言を `failed` にして `opinion-filter-failed` を記録する（黙って全件を通さない）。鍵が無ければアラーム（`worker/opinion-timer.ts`）が Jev を null にして絞り込みを飛ばす。LLM（箇所 `opinionSort`。`worker/opinion-sort.ts`）には、いまの論点と意見（隠したものも含む）と新しい発言をラベル（C・T・O）付きで渡し、発言ごとに ignore・join・new を返させる（問いかけを出しているときは、問いかけへの答えなら `answersPrompt` も）。振り分けは新しい発言だけを扱い、論点を分ける基準（`TOPIC_CRITERIA`。論点の作り直しと共有）を伝える。**返事は `parseOpinionSorting` だけが照合し**（発言の漏れ・重なり・知らないラベル・種類・文字数・論点の数）、外れたら切り詰めず補わずに拒む。拒んだ回と LLM を呼べなかった回の発言は `failed` にして `opinion-sort-failed` を記録する（振り分け待ちに残さない）。振り分けの結果は `applySorting` が1つの batch で書く（作った意見は `first_comment_id` で指す。どの文もテーマがまだ開いているときだけ書くので、LLM を待つあいだに締め切られたら何も書かず、コメントは振り分け待ちのまま残る）。

論点の作り直し（issue #402）は、隠していない意見すべてを LLM（箇所 `opinionRegroup`。`worker/opinion-regroup.ts`）に渡し、論点を分け直させて名前を付け直させる。作り直すのは論点への割り当てと名前だけで、意見そのもの（1文・札の種類・もとのコメント）は書き換えない。行うのは、振り分けの回で新しい意見ができ、前に引き受けてから意見が `REGROUP_OPINION_STEP`（5件）増えたとき（問いかけを待たせないよう回の最後）と、テーマを締め切ったとき（1件でも増えていれば。`runClosedThemeFinish` がまとめと並べて行う。waitUntil の打ち切りに間に合わせるため順には待たない）。引き受けは `claimRegroup` が1つの文で確かめて数（`opinion_themes.regrouped_opinions`）を覚え、失敗しても戻さない。**返事は `parseOpinionRegrouping` だけが照合し**（意見の漏れ・重なり・知らないラベル・意見の無い論点・論点の数・名前の文字数・重なり・使えない名前・配信者が付けた名前の使い忘れ）、外れたら切り詰めずに拒んで前の論点を残し、`opinion-regroup-failed` を記録する。分け直した論点は `planRegrouping` が、配信者が名前を付けた論点を同じ名前の論点へ先に対応させ、残りを、もとの論点のうち隠していない意見の重なりが最も大きいものへ対応させてIDを保ち（合成ページの枠の位置を保つ）、対応しない論点は新しく作り、意見が無くなった論点は消す（残る隠した意見は、その論点の意見を最も多く受け取った論点へ移す）。隠した意見しか無い論点は作り直しに加えず、その数だけ上限を減らし、その名前を使わせない。配信者が名前を変えた・まとめ先にした論点（`opinion_topics.title_locked`。`renameTopic`・`mergeTopics` が立てる）の名前は LLM に必ずそのまま使わせ、名前とIDを残す（中の意見は入れ替わりうる）。書き込みは `applyRegrouping` が1つの batch で行い（12文字より長い仮の名前を経て UNIQUE に当たらないようにする）、最初の文で盤面（`readRegroupBoard` の論点の名前と固定・意見の論点と隠したか）と最後に開いたテーマかを確かめ、違えば batch ごと失敗させて書かずに `opinion-regroup-failed` を記録する。

視聴者への問いかけ（合成ページの中央下の「こんな観点からも聞いてみたい」。issue #307）はテーマの行（`opinion_themes.prompt`）に1つだけ持つ。LLM（箇所 `opinionPrompt`。`worker/opinion-prompt.ts`）が、テーマと隠していない意見（`readVisibleBoard`）と前の問いかけから、まだ出ていない切り口を1文で作る。作り直すのは、問いかけが無いあいだに新しい意見ができたときと、振り分けが問いかけに答えた発言を返したときだけ（`runOpinionSorting`。新しい意見が無いあいだは作り直さない）と、配信者が `/opinions/` の「別の問いかけにする」（`POST /api/admin/opinions/themes/:id/prompt`）を押したとき。1行でない・40文字（`MAX_PROMPT_LENGTH`）を超える問いかけは `parseOpinionPrompt` が切り詰めずに拒み、前の問いかけを残す（振り分けの回は `opinion-prompt-failed` を記録、経路は502）。どちらも `replaceOpinionPrompt` を通る。テーマを締め切ったら合成ページは問いかけを隠す。

拾えなかったコメントの救い出しと論点の整理（issue #308）は配信者が行う（整えた名前は論点の作り直しでも変えない）。対象は最後に開いたテーマ（管理画面に出ているもの）だけで、締め切ったあとも行える。救い出せるのは `dropped`・`filtered`・`ignored`・`failed` と、締め切ったあとの `pending`（開いているあいだは振り分けと取り合うため。`worker/opinion-store.ts` の `rescuable`）。「新しい意見にする」は、まず `POST /api/admin/opinions/comments/:id/draft` が LLM（箇所は振り分けと同じ `opinionSort`。`worker/opinion-draft.ts`）に下書きを作らせて保存せずに返し、配信者が直したものを `/opinion` で保存する。下書きの照合と配信者の入力の検証は同じもの（`worker/opinion.ts` の `parseRescuedOpinionInput`・`topicChoiceProblem`）を通る。既にある意見への統合（`/join`）、論点の名前の書き換え（`PUT /api/admin/opinions/topics/:id`）、2つの論点の統合（`/merge`。まとめ先の名前を残し、まとめた側の論点を消す）がある。振り分けの LLM を待つあいだに論点がまとめられた・上限に達したときは、`applySorting` がその意見を書かずにコメントを振り分け待ちに残す（次の回に振り分け直す）。コメントビューアーの行には意見になったかの印を付けない（救い出しは `/opinions/` で完結させる）。

配信後のまとめ（issue #309）は、テーマを締め切ったときに LLM（箇所 `opinionSummary`。`worker/opinion-summary.ts`）が、隠していない意見（`readVisibleBoard`）から「合意が見える点・意見が分かれた点・残った問い」を作る。**機械が作ったもので、配信者のメモと混ぜない**（`/opinions/` では `src/opinions/summary-card.tsx` の「AIのまとめ」の枠に分けて出す）。人数は材料にもまとめにも入れず、合成ページにも渡さない（`readOverlayBoard` は読まない）。保存は `opinion_summaries`（テーマのIDが主キー。各欄は JSON の配列）で、`saveThemeSummary`（締め切ったテーマにだけ書く・置き換える）と `readThemeSummary`（テーマのIDで読む。壊れた中身は黙って空にせず投げる）が `worker/opinion-store.ts` にあり、管理画面の意見ボード（`readAdminBoard` の `summary`）にも添える。**返事は `parseOpinionSummary` だけが照合し**（JSON・3つの欄が配列・各欄5個まで（`MAX_SUMMARY_ITEMS`）・1個80文字まで（`MAX_SUMMARY_ITEM_LENGTH`）・全部の欄が空でない）、外れたら切り詰めずに拒む。締め切りの経路（`postCloseOpinionTheme`）は応答を待たせず `waitUntil` で、論点を作り直してから作らせ（`runClosedThemeFinish`。作り直しの失敗はまとめを止めない）、作れなくても締め切りは取り消さず `opinion-summary-failed` を記録して行を書かない。隠していない意見が無ければ LLM を呼ばず何も書かない。配信者は `POST /api/admin/opinions/themes/:id/summary`（最後に開いて締め切ったテーマだけ。隠す・論点の整理のあとの反映にも使う）で作り直せ、作れなければ前のまとめを残して502（`opinion-summary-failed`）、意見が無ければ409（`opinion-summary-empty`）にする。

開く・締め切る・振り分ける・論点を作り直す・問いかけを替える・隠す・救い出す・論点を整理するたびに、意見ボードを丸ごと `AlertChannel` の目印 `opinions`（`pushOpinions`・`connectOpinionSocket`）で押し出す。経路（`worker/opinion-routes.ts`）の押し出しの失敗は保存を取り消さずに502（`opinion-push-failed`）、振り分けの押し出しの失敗は `opinion-push-failed` として記録する。合成ページ（`src/overlay/stage.ts` の `mountOpinions`）は開いたとき・つながるたび・5分おきに `GET /api/overlay/opinions` で読み直し、読んでいるあいだに押し出しが届いたら読んだ結果は捨てる（作業机と同じ）。表示は `src/opinions/view.ts`（札は意見のIDごとに使い回す）、見た目は `src/opinions/opinions.css`。

アプリのページ（`/opinions/`。`src/opinions/opinion-page.tsx`）は、テーマの開始と締め切り（確かめてから）、いまの問いかけと替える操作、意見の隠す・戻す、意見ごとの人数ともとのコメント、コメントの内訳と救い出し（`src/opinions/rescue-list.tsx`）、論点の名前の書き換えと統合（確かめてから。`src/opinions/topic-tools.tsx`）、締め切ったテーマの配信後のまとめと作り直す操作（`src/opinions/summary-card.tsx`）を出し、15秒おきに読み直す。救い出しと論点の整理は保存したら手元で書き換えずに読み直す。入力しかけのテーマ・書きかけの下書き・名前・統合先があるあいだは `useUnsavedChanges(true)` を呼ぶ。操作で表示を書き換えたら世代を進め、操作の前に始めた読み直しの結果は捨てる。配信後の振り返り（issue #309）はダッシュボード（`/`）の配信の詳細に出す。`GET /api/admin/stats/sessions/:id/opinions`（`worker/stats-routes.ts` の `getStatsSessionOpinions`）が、配信の開始から終了（配信中なら現在）までに**開いた**テーマを `readThemeReviews`（`worker/opinion-store.ts`。読むだけで書かない）で古い順に読み、テーマごとの区切り（`OpinionThemeReview`: 全論点・全意見・コメントの内訳・締め切ったときのまとめ（`readThemeSummary`。無ければ null））で返す。テーマと配信は時刻で結ぶ。意見は隠したものも `hidden` つきで含め、人数ともとのコメントを付ける（合成ページに人数を出さない方針は変えない）。意見にならなかったコメントは件数の内訳だけで、原文は出さない。画面は `src/stats/session-opinions.tsx`。締め切ったテーマには区切りの中にまとめを `/opinions/` と同じ「AIのまとめ」の枠（`SummaryCard`）で出し、作り直しの操作は渡さない（読むだけの場所。作り直しは `/opinions/` で行う）。→ `docs/decisions/opinions.md`

利用者向けの説明は `docs/guide/opinions.md`。
