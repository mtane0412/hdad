# コメントビューアー（`/comments/`）

コメントビューアー（`/comments/`）は配信中に配信者が横に開いておく画面で、チャットの発言と出来事（サブスク・ギフト・レイド・ビッツ・チャンネルポイントの引き換え・フォロー）を届いた順に1本の流れとして並べる。Webhook で届いた通知を `worker/comment-feed.ts` の `toFeedItem` が1件に直し（通信を持たない）、配送先の Durable Object（`worker/comment-channel.ts` の `CommentChannel`）へ押し出す。押し出しはほかの処理（自動モデレーション・トリガー・応答）より先に行い、失敗しても2xxを返して `comment-feed-failed` を記録する（コメントビューアーのためにトリガーや応答を止めない）。**サブスク・ギフト・レイドは `channel.chat.notification` から読み**、同じ出来事の `channel.subscribe`・`channel.subscription.message`・`channel.raid` は流さない（二重に並ぶため。逆にお知らせのほうは数えずトリガーにもかけない＝`FEED_ONLY_EVENT_TYPES`）。**Durable Object は中身を読まない配送者で**、直近 `RECENT_LIMIT` 件を保管に覚えてつないだ直後に履歴として渡す。形の確かめと並べ方（同じ通知のメッセージIDは、モデレーターの操作も含めて二度当てはめない・消された発言は並びから消さず印を付ける）は `src/comments/feed.ts` だけが持つ。アイコンは1件に添えず、画面が初めて見た人のIDだけをまとめて `GET /api/admin/comments/icons` に問い合わせる。WebSocketの接続は手書きと同じく `Origin` を自分で確かめる。発言は行のボタンから注目コメントに設定でき、保存は `src/focus/api.ts` の `save`（`PUT /api/admin/focus`）を使う（本文はエモートを名前の文字のままつなげる＝`toFocusPick`）。いま取り上げている1件は流れの上の欄に出し、そこからやめられるようにする（流れに無い発言でもやめられるように。注目コメント専用のページは持たない）。消された発言は取り上げさせない（取り上げたあとで消されたものは、やめられるようにする）。モデレーターの操作（発言の削除・タイムアウト・BAN）は `POST /api/admin/comments/moderation` から自動モデレーションと同じ `worker/bot-moderation.ts` の `punishAsBot` を**botの権限で**呼ぶ（理由は手動のものに変えて記録する）。タイムアウトの長さは Worker の `MANUAL_TIMEOUT_SECONDS` だけが持ち、画面は応答の値を出す。手動のタイムアウト・BANでは発言を先に削除しない（`messageId: null`）。BANだけは確かめてから行う。処分した発言への印は、Twitch から届く削除・消去の通知で付く（画面が自分で付けない）。チャットの送信は `POST /api/admin/comments/messages` から**配信者のトークンで配信者本人として**送る（文言の検証は `worker/bot-routes.ts` の `readMessageToSend` を共有する）。配信者のトークンに `user:write:chat` が無ければ、botで代わりに送らず `missing-scope` で断る。入力欄の Enter は `isComposing` のあいだ送らない。**その配信で初めての発言には挨拶したかを手で付ける。** 初めての発言かは Worker が判定する（`worker/webhook-routes.ts` の `isFirstChatToGreet` が、トリガーと同じ `first_chatters`＝`worker/chat-store.ts` の `claimFirstChatOfStream` で、トリガーの有無にかかわらず判定する）。判定の結果は、流す1件の `firstOfStream` として `toFeedItem` に引数で渡す。配信者自身と bot の発言は、判定も記録もしない。判定に失敗したら `comment-feed-failed` として記録し、印を付けずに流すことはしない。挨拶したかは `POST /api/admin/comments/greetings` で付け外しする。記録は `first_chatters.greeted_at`（`recordGreeting`）に持ち、初めての発言として記録されていなければ404（`unknown-first-chat`）にする。印は付け替えの1件（`kind: 'greeting'`。毎回新しいID）を配送先へ押し出して付ける（画面は先回りして付けず、開き直したときも履歴から戻る。押し出しに失敗したら成功として返さない）。画面は、まだ挨拶していない初めての発言（`needsGreeting`。消された発言は除く）の行を「未挨拶」として目立たせ、流れの上に名前を一覧にする（`pendingGreetings`。押すとその行へ移る）。発話から自動で判定はしない。全発言の既読・未読と、コメントビューアーの設定（`comment-settings`）は持たない。→ `docs/decisions/comments.md`

利用者向けの説明は `docs/guide/comments.md`。
