# コメントビューアー（`/comments/`）

コメントビューアー（`/comments/`）は配信中に配信者が横に開いておく画面で、チャットの発言と出来事（サブスク・ギフト・レイド・ビッツ・チャンネルポイントの引き換え・フォロー）を届いた順に1本の流れとして並べる。Webhook で届いた通知を `worker/comment-feed.ts` の `toFeedItem` が1件に直し（通信を持たない）、配送先の Durable Object（`worker/comment-channel.ts` の `CommentChannel`）へ押し出す。押し出しはほかの処理（自動モデレーション・トリガー・応答）より先に行い、失敗しても2xxを返して `comment-feed-failed` を記録する（コメントビューアーのためにトリガーや応答を止めない）。**サブスク・ギフト・レイドは `channel.chat.notification` から読み**、同じ出来事の `channel.subscribe`・`channel.subscription.message`・`channel.raid` は流さない（二重に並ぶため。逆にお知らせのほうは数えずトリガーにもかけない＝`FEED_ONLY_EVENT_TYPES`）。**Durable Object は中身を読まない配送者で**、直近 `RECENT_LIMIT` 件を保管に覚えてつないだ直後に履歴として渡す。形の確かめと並べ方（同じ通知のメッセージIDは、モデレーターの操作も含めて二度当てはめない・消された発言は並びから消さず印を付ける）は `src/comments/feed.ts` だけが持つ。アイコンは1件に添えず、画面が初めて見た人のIDだけをまとめて `GET /api/admin/comments/icons` に問い合わせる。WebSocketの接続は手書きと同じく `Origin` を自分で確かめる。発言は行のボタンから注目コメントに設定でき、保存は注目コメントのページと同じ `src/focus/api.ts` の `save`（`PUT /api/admin/focus`）を使う（本文はエモートを名前の文字のままつなげる＝`toFocusPick`）。消された発言は取り上げさせない（取り上げたあとで消されたものは、やめられるようにする）。モデレーターの操作（発言の削除・タイムアウト・BAN）は `POST /api/admin/comments/moderation` から自動モデレーションと同じ `worker/bot-moderation.ts` の `punishAsBot` を**botの権限で**呼ぶ（理由は手動のものに変えて記録する）。タイムアウトの長さは Worker の `MANUAL_TIMEOUT_SECONDS` だけが持ち、画面は応答の値を出す。手動のタイムアウト・BANでは発言を先に削除しない（`messageId: null`）。BANだけは確かめてから行う。処分した発言への印は、Twitch から届く削除・消去の通知で付く（画面が自分で付けない）。チャットの送信は `POST /api/admin/comments/messages` から**配信者のトークンで配信者本人として**送る（文言の検証は `worker/bot-routes.ts` の `readMessageToSend` を共有する）。配信者のトークンに `user:write:chat` が無ければ、botで代わりに送らず `missing-scope` で断る。入力欄の Enter は `isComposing` のあいだ送らない。視聴者の発言は `POST /api/admin/comments/reads` で既読にする・未読に戻せ、記録は D1 の `comment_reads`（`worker/comment-read-store.ts`。誰が付けたか＝手か Jev かも持つ）に残し、印は付け替えの1件（`kind: 'read'`。毎回新しいID）を配送先へ押し出して付ける（画面は先回りして付けず、開き直したときも履歴から戻る。押し出しに失敗したら成功として返さない）。反応したかを見るのは配信者自身（broadcaster のバッジ）以外の、消されていない発言だけ（`needsReaction`）。届いてから `UNREAD_HIGHLIGHT_MS`（3分）たっても未読の発言を目立たせ、目立たせるかだけを設定（KV の `comment-settings`。`worker/comment-config.ts`。読むときも検証し、古い形は補わずにエラー）に持つ。設定の `judgeWithJev`（既定はオフ）を入れると、確定した発話を受け取るたびに（`postTranscript` が設定の読み込みごと応答のあとに預ける）`worker/comment-reaction.ts` が、きっかけの発話までの直前の3文（`readTranscriptsUpTo`）で直近の未読の発言を Jev で判定し、`REACTION_THRESHOLD`（0.8）以上の発言を `markReadByJev`（まだ一度も付け替えていない発言だけ）で既読にして `by: 'jev'` の付け替えを押し出す（押し出せなければ `unmarkReadByJev` で取り消し、次の判定の候補に戻す）。未読の発言が無ければ Jev を呼ばない。失敗は `comment-reaction-failed` として記録し、発話の受け取りは止めない。画面は Jev が付けた既読に「発話から既読」と出す。→ `docs/decisions/comments.md`

利用者向けの説明は `docs/guide/comments.md`。
