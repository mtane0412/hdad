# チャットで推理（`/chat-deduction/`）

視聴者がチャンネルポイントの「質問」（はい／いいえで答えられる問い）を繰り返して答え（人物・場所・出来事・もの）を絞り込み、「解答」で当てるゲーム。段階1（issue #375）は問題集の形・ゲームの開始と終了・報酬の作成と切り替え、段階2（#376）は質問の受け口と LLM の回答・上限・返金、段階3（#377）は解答の照合と正解での終了、段階4（#378）は合成ページの素材 `chatDeduction`（カードの一覧）。参考にした既存のゲームの名前はリポジトリに書かない。

- 問題集は `src/chat-deduction/problems.json` だけが持ち、LLM にその場で作らせない。problems.json は問題集（ID・名前・1問以上の問題）の一覧で、1問は ID（英小文字・数字・ハイフン。問題集をまたいでも重ねない）・区分・正解（画面の表記）・別名（解答の照合に使う）・事実メモ（質問に答える LLM の材料）を持つ。形の確かめは `problems.ts` の `readChatDeductionProblemSets`（問題集のテストは `problems.test.ts`）。区分の識別子と画面の言い方は `category.ts` だけが持つ。Worker もページも `problem-set.ts` の `CHAT_DEDUCTION_PROBLEM_SETS`（問題集の一覧）と `CHAT_DEDUCTION_PROBLEMS`（全問題。ゲームの行の問題のIDから引く）を読む（Worker から `src/` を読み込む例外。DOM と `src/core/` に頼らない）
- 配信者は問題集だけを選び（`POST /api/admin/chat-deduction/games` の `{ setId }`）、出す問題は Worker が `worker/chat-deduction-pick.ts` の `pickChatDeductionProblem` で決める（乱数。最後に始めたゲームの問題は除く。1問だけの問題集なら除かない）。1問を直接指定する入口は持たない。ページは開催中に問題集の名前と区分だけを出し、正解は最後のゲームを終えたあとにだけ「前回の正解」として出す（配信者も一緒に推理するため。視聴者の正解で終わったときも出す）
- 視聴者の入口はチャンネルポイントの「質問」「解答」の2つの報酬だけにする。報酬は `/chat-deduction/` から HDAD が作り（`worker/chat-deduction-rewards.ts` の `createChatDeductionRewards`。交換できない・ユーザー入力あり・待ち行列に入れる形）、ID を KV の `chat-deduction-rewards` に控える。既存の報酬は選ばせない（Twitch が交換できるかどうかの切り替えを許すのは同じ Client ID で作った報酬だけのため）。「解答」を作れなければ作った「質問」を消してから投げる。必要ポイントと説明は `/rewards/` で変えられ、チャットで推理の報酬は `/rewards/` から消させない（`reward-in-use`）
- ゲームは D1 の `chat_deduction_games`（`migrations/0039_chat_deduction_games.sql`）に持ち、読み書きは `worker/chat-deduction-store.ts` だけが行う。開催中は1つだけで、開始の確かめは1つの文（`startGame`）で行う。終わり方（`end_reason`）は `stopped`（配信者が打ち切った）と `solved`（正解者が出た。#377）
- 開始（`POST /api/admin/chat-deduction/games`）は行を作ってから2つの報酬を交換できるようにする（`twitch.ts` の `setCustomRewardEnabled`。`is_enabled` だけを送り、配信者が変えたほかの項目を上書きしない）。切り替えに失敗したら行を消し（`cancelGame`）、報酬を交換できない状態へ戻してから502にする。戻せなかったことも黙らずメッセージに添える
- 終了（`POST /api/admin/chat-deduction/games/:id/end`）は先に2つの報酬を交換できないようにし、成功してから行を終える。切り替えに失敗したらゲームを開催中のまま残して502にする（交換できるまま終わったことにしない）
- 質問の受け口は `worker/chat-deduction-question.ts` の `handleChatDeductionRedemption`（`worker/webhook-routes.ts` がアラートのトリガーのあとに呼ぶ）。自分のチャンネルの「質問」の報酬の交換だけを受け、行は D1 の `chat_deduction_questions`（`migrations/0040_chat_deduction_questions.sql`）に持つ。交換のIDを鍵に行を作るのと、受け付けるかどうか（開催中のゲーム `no-game`・1問あたりの上限 `limit`。同じ人の待ち時間は設けない）の判断を1つの文（`reserveQuestion`）で行い、行がもうあれば再送として何もしない。上限は定数 `CHAT_DEDUCTION_QUESTION_LIMITS`（30件）で、数えるのは答え待ちと答えた質問だけ（ポイントを返した質問は数えない）
- LLM（箇所 `chatDeductionAnswer`。`worker/chat-deduction-answer.ts`）と交換の更新は Twitch へ2xxを返したあと（`waitUntil`）に行う。材料は正解・区分・事実メモと質問だけ。**返事は `parseChatDeductionAnswer` だけが照合し**（2行・1行目が はい／いいえ／分からない・1文は `MAX_REPLY_LENGTH`（60文字）まで・1文に正解か別名を含まない）、外れたら切り詰めず補わずに拒む。答えられたら `answerQuestion` で書いて交換を FULFILLED、答えられなければ `failQuestion` で理由を残し `chat-deduction-answer-failed` を記録して CANCELED、受け付けなかった質問は LLM を呼ばずに CANCELED にする（`twitch.ts` の `updateRedemptionStatus`。返金を持たない `/rewards/` の方針の、この報酬に限った例外）。交換を更新するトークン（`getManageToken`）は LLM より先に取り、取れなければ LLM を呼ばずに答え待ちの質問を `failQuestion` で閉じる。交換を更新できなければ `chat-deduction-redemption-failed` を記録し、D1 の答えは書き戻さない
- 解答の受け口は `worker/chat-deduction-guess.ts` の `receiveChatDeductionGuess`（`handleChatDeductionRedemption` が「解答」の報酬の交換を振り分ける）。行は D1 の `chat_deduction_guesses`（`migrations/0041_chat_deduction_guesses.sql`）に持ち、交換のIDを鍵に行を作るのと開催中のゲームの確かめを1つの文（`reserveGuess`）で行う。**正誤は `src/chat-deduction/guess.ts` の `isCorrectChatDeductionGuess` だけが決め**（解答と別名の両方を `normalizeChatDeductionGuess` で揃えて完全一致。LLM は使わない）、正解なら `solveGame` が1つのトランザクションで正解者を1人に決めてゲームを `solved` で終える。照合までにゲームが終わっていた正解は `closed` で受け付けない。ゲームを終えてから2つの報酬を交換できないようにし（打ち切りの経路と逆の順。正解を報酬の切り替えの成否で取り消さない）、切り替えに失敗したら `chat-deduction-rewards-failed` を記録して交換の更新は続ける。正解・不正解は FULFILLED、受け付けなかった解答（`no-game`・`closed`）は CANCELED
- 合成ページの素材（素材の種類 `chatDeduction`）は、最後に始めたゲームの区分と、答えた質問（`answered`）・正誤を決めた解答（`correct`・`wrong`）のカードを、答え・正誤を決めた順に丸ごと受け取る（`worker/chat-deduction-board.ts` の `readChatDeductionBoard`。カードの読み取りは `chat-deduction-store.ts` の `readGameCards`）。**正解の表記はゲームを終えたあとにだけ載せる**（開催中は `answer: null`）。ポイントを返した交換と答え待ち・照合待ちは映さない。開始・終了・質問に答えた・解答の正誤を決めたたびに `AlertChannel` の目印 `chatDeduction`（`pushChatDeduction`・`connectChatDeductionSocket`）で押し出す。開始・終了の経路の押し出しの失敗は、始めた・終えたことを取り消さずに502（`chat-deduction-push-failed`）、質問・解答の押し出しの失敗は `pushBoardAfterRedemption` が `chat-deduction-push-failed` を記録して交換の更新を続ける。合成ページ（`src/overlay/stage.ts` の `mountChatDeduction`）は開いたとき・つながるたび・5分おきに `GET /api/overlay/chat-deduction` で読み直し、読んでいるあいだに押し出しが届いたら読んだ結果は捨てる（意見ボードと同じ）。形の確かめは `src/chat-deduction/board.ts`、表示は `view.ts`（古いものから読む順に、新しいものから `MAX_VISIBLE_CARDS` 枚。質問にはゲームの初めから数えた通し番号を付ける。カードはゲームと種類とIDごとに使い回す。終えたゲームは `endedAt` から `ENDED_GAME_REVEAL_MS`（意見ボードと共有する `src/core/ended-reveal.ts` の `ENDED_REVEAL_MS`）たったら消し、プレビューのサンプルでは消さない。下部バーの「演出を消す」を受けたら終えたゲームだけを待たずに消し、同じゲームは読み直しで届いても映さない（`dismiss`。開催中のゲームは消さない））、見た目は `chat-deduction.css`（板は箱いっぱいで背景を持たず（配信画面を覆わない）、上下左右に配信画面のおよそ5%の余白を取り（大きさはすべて 1920×1080 での画素数に `--u` を掛けて決め、配信画面が小さければ同じ割合で縮む）、見出しの帯とカードだけを白地と影で浮かせ、カードは3列×4行の格子。白地に原色・状態を色面で伝える・下側の厚み・丸みの型に寄せ、色・大きさの値はファイル冒頭のトークンだけを使う。終えたら正解の帯を見出しの位置に重ねる）、プレビューのサンプルは `demo.ts`
- 場面ごとに鳴らす音の枠は `src/chat-deduction/sound.ts` の `CHAT_DEDUCTION_SOUND_SLOTS`（BGM・開始・回答・不正解・正解・打ち切り）で固定し（Worker もここから読む）、配信者は枠ごとにアップロード済みの音声を選ぶか「鳴らさない」にするだけにする。音量は BGM と効果音の2つ。設定は KV の `chat-deduction-sound`（`worker/chat-deduction-sound.ts`。経路は `GET・PUT /api/admin/chat-deduction/sound`）で、画面は `/chat-deduction/` の音のカード（`src/chat-deduction/sound-card.tsx`）。選ばれている素材は削除させない（`worker/admin-routes.ts`）。Worker は合成ページへの一覧（`readChatDeductionBoard`）に音声の URL にした設定（`sound`）を載せ、音を選んでいるのにオーバーレイ用キーが無ければ一覧を返さず投げる。保存は合成ページへ押し出さない
- 合成ページで何を鳴らすかは `src/chat-deduction/sound-cues.ts` の `chatDeductionSoundCuesOf` だけが前の一覧と新しい一覧の差から決める。効果音は押し出しで届いた一覧でだけ鳴らし（読み直しと最初の一覧では鳴らさない）、カードは種類とIDの組で見分ける。正解で終えたときは正解の音だけ、打ち切りの音は配信者が終えたときだけ。BGM は開催中のあいだ流し（`chatDeductionBgmUrlOf`）、読み直しでも合わせる（同じ曲で音量だけ変わったら、流し直さずに音量だけを変える）。流しているあいだ配信の BGM を下げておく長さ（`CHAT_DEDUCTION_BGM_DUCK_HOLD_MS`）を `CHAT_DEDUCTION_BGM_DUCK_RENEW_MS` おきに `POST /api/overlay/bgm/duck` へ送り直す。Audio 要素の操作は `src/core/sound-player.ts`（漢字クイズと共有）。プレビューでは鳴らさない
- 経路は `worker/chat-deduction-routes.ts`。アプリのページは `src/chat-deduction/chat-deduction-page.tsx`（問題集の一覧を引数で受け取る）、Worker の呼び出しは `api.ts`

経緯は `docs/decisions/chat-deduction.md`、使い方は `docs/guide/chat-deduction.md`。
